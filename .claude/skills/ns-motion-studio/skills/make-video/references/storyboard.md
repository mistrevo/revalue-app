# 段階3 絵コンテ

場面（ビート）の並びと秒数、テロップとナレーションの原稿を決め、`storyboard.md` と `timeline.json` に書く。本番は関門2、サンプルは構成の確認（`plan`）で文字を確定させる（お試しは納品で見てもらう）。ここで確定した文字は、以後 `timeline.json` だけを直す（シーンの HTML に文字を書かない）。

## 1. ビートを決める

構成の型（[structures.md](structures.md)）と作例（`references/examples/<作例>.md` の「場面の並びの例」）から始め、ブリーフィングに合わせて足し引きする。型は混ぜてよく、どれにも当たらなければ自由に組む。使うと決めた中身（数値、画面、ロゴなど）は [content-rules.md](content-rules.md) で素材の不足を見直し、足りなければ `briefing.md` の「不足している素材」に足す。ビートごとに次の5つを決める。

| 項目 | 書くこと |
|---|---|
| 秒数 | 開始と終了（動画の先頭からの秒）。ナレーションがあるなら仮の値でよい（段階4で確定する） |
| 入口の状態 | ビートが始まった瞬間に画面にあるもの（前のビートの出口から何が残り、何が入ってくるか） |
| 出口の状態 | ビートが終わる瞬間に画面にあるもの。次のビートの入口とつながるようにする |
| 存在理由 | このビートが、目的か「一番覚えてほしい一文」のどこに効くか。**1行で言えないビートは削る** |
| 文字 | テロップと、ナレーションの原稿 |

- 見せ場は絞る。1つのビートで伝えることは1つ。
- 最後の 1.5〜2.0 秒は止めて読ませる（締めの一文やロゴ）。
- 総尺が 300 秒を超えるなら、ブリーフィングに戻って連作を提案する（[briefing.md](briefing.md)）。

## 2. 文字の書き方

- **テロップ**（`title`、`caption`、`label`）は、ナレーションの要点を短く。全文を出さない。1枚に1メッセージ。
- **表示時間**は、日本語は「文字数 ÷ 5 + 0.5 秒」以上（空白と記号は数えない。15字なら 3.5 秒。文の中の英単語と数字は、1語を 0.3 秒で数える）、英語は「0.3 秒 × 語数 + 0.5 秒」以上。足りなければ、文字を減らすかビートを延ばす。
- **字幕**（`subtitle`）は、ナレーションがあり、音なしで見られる場所（SNS、展示会）で流すときに付ける。ナレーションの区切りごとに1つ。字幕もシーンの中で描く（後から焼き込まない）。ナレーションと同じ文の字幕は、読む速さの式ではなく、声の始まりまでに出し、話し終えて 0.5 秒たつまで出ていればよい（声を聞きながら同じ文を目で追うので、声の速さで読める。声の速さは声と文で変わり、1 秒 5 文字より速く話す行では式より短くなるが、それでも読める。音なしで見る人にも、声の間ずっと字幕が出ている）。自動点検の `hold` も、この時刻で見る（話す長さは、合成の後は実際の長さ、合成の前は 1 秒 5 文字の見積もり。見積もりでは式とほぼ同じ長さになる）。始まりが声より遅い、または終わりが足りない字幕は、読む速さの式で見る。同じ文かどうかは空白だけを除いて比べるので、字幕はナレーションの文をそのまま写す（句読点や全角・半角が 1 文字でも違うと、読む速さの式で見る）。音なしで見られることが多い場所（SNS、展示会）では、字幕をナレーションより短く要約してもよい。要約した字幕は、読む速さの式で見る。
- 製品名・機能名・用語は、渡された資料と画面の表記に一字一句そろえる。数値は渡されたものだけ、出典の時点を `storyboard.md` に書く。
- [banned.md](banned.md) の「言葉の癖」に当たる言い回しを使わない。
- **ナレーション**は、1秒あたり約5文字で長さを見積もる（30字なら約6秒。空白と記号は数えない）。社名・製品名・項目を「、」で並べる行は、区切りごとに間が入るので、1秒あたり約3.5文字で見積もる（試作で合成した声は 1 秒 4.8〜5.6 文字、並べる行は 3.4 文字だった。6 文字で見積もった試作は、45 秒の計画が 53 秒になった）。VOICEVOX を速さ 1.1 で使うなら、1秒あたり約6文字で見積もる（試作では Gemini の声より 14〜21% 短くなった）。合成前の自動点検は並べる行も 1 秒 5 文字で見るので、並べる行は先に合成して実際の長さで確かめる。句読点で息継ぎできるように書く。

## 3. storyboard.md のひな形

```markdown
# 絵コンテ: <題名>

一番覚えてほしい一文: 「<一文>」
総尺: 約 <秒> 秒 / fps: <30> / 比率: <16:9>

## カット1（0:00〜0:04）Hook
- 存在理由: <一文のどこに効くか>
- 入口: <最初に画面にあるもの>
- 出口: <終わりに画面にあるもの>
- 画: <何を、どう見せるか。使う素材 `assets/...`>
- テロップ: 「<文字>」（0:00.4〜0:03.6）
- ナレーション: 「<原稿>」
- 効果音: <どの動きに、どの音か>

## カット2（0:04〜0:12）課題
...
```

## 4. timeline.json を書く

言葉と時間の正本。形は次のとおり。

```json
{
  "version": 1,
  "title": "新製品紹介",
  "fps": 30,
  "ratios": ["16:9"],
  "loop": false,
  "seed": 1,
  "scenes": [
    { "id": "s01", "start": 0, "end": 4, "purpose": "Hook: 課題を一言で", "file": "src/scenes/s01.html" }
  ],
  "texts": [
    { "id": "t01", "scene": "s01", "kind": "title", "text": "現場の待ち時間を、ゼロに。", "start": 0.4, "end": 3.6 }
  ],
  "narration": [
    { "id": "n01", "scene": "s01", "text": "現場の待ち時間を、ゼロに。", "start": 0.3, "audio": null, "duration": null }
  ],
  "sfx": [ { "id": "x01", "t": 0.4, "preset": "pop", "gain": -8 } ],
  "bgm": null,
  "poster": 3.0
}
```

- `title`、`fps`、`ratios`、`loop` は、`project.json` の `settings`（ブリーフィングの記録）から写す。その後は `timeline.json` が正で、`settings` は合わせ直さなくてよい（道具は読まない）。`fps` は 24、25、30、60 のどれか。
- `scenes` は隙間なく並べる（前のシーンの `end` が次の `start`）。カット番号は `scenes` の並び順（1始まり）。`purpose` は「ビート名: 存在理由」。`file` は `src/scenes/<id>.html`。
- `texts` の `kind` は `title`、`caption`、`label`、`subtitle` のどれか。時刻はシーンの中に収める。
- `narration` は `audio` と `duration` を null にしておく（段階4で入る）。`start` はそのシーンの中の時刻（動画の先頭からの秒）。
- `sfx` の `t` は、音を合わせる映像のイベントの時刻（音は自動で1フレーム後に置かれる）。`preset` は `pop`、`click`、`whoosh`、`hit`、`riser`、`chime`、`tick`、`swoosh-out`。`gain` は dB（-6〜-14 が目安。効果音だけの動画では、書き出しの時に全体の頂点がそろうので、音どうしの比べ合いとして書く。audio.md の6章）。効果音を付けないなら空の配列。
- `bgm` は段階4で入る。`poster` はポスター画像にする時刻（決めの画が出そろった瞬間）。
- id は種類ごとに通し番号（`s01`、`t01`、`n01`、`x01`）。重複させない。
- 時刻はすべて動画の先頭からの秒（小数）。

書いたら、形と表示時間を確かめる。問題が出なくなるまで直す。

```
node "<プラグイン>/scripts/timeline.mjs" validate "<制作>"
```

表示時間の不足（「テキスト t03 の表示が 1.2 秒しかありません」）は、文字を減らすか、テキストの `end` を延ばす（シーンも延ばすなら、後ろのシーンをすべてずらす）。

## 5. 下描きのシーンを作り、ラフ画を撮る

**道具なしで進めているとき（`project.json` の `settings.fallback` が `claude-motion`）は、この節を飛ばし、静止画なしで確認ページを作る。** 各カットには「静止画はまだありません」と出る。

関門2の確認ページにはカットごとの静止画が出る。各シーンを、動きのない下描き（`style.md` の色・書体・構図で、文字と素材を最終の位置に置いただけのもの）として作り、撮る。

1. シーンごとに `<プラグイン>/templates/scene.html` を `src/scenes/<id>.html` に写し、配置だけを組む。約束事は [composition.md](composition.md)。
2. `node "<プラグイン>/scripts/frames.mjs" "<制作>" beats` で、各カットの落ち着いた時刻（カットの 70%。最後に出る文字が出て 0.6 秒たつ前なら、その時刻）とポスターの時刻を撮る（`reviews/frames/<比率>/` に入り、確認ページが拾う）。
3. 撮った画を見て、文字のはみ出しや重なりを直す。下描きは段階5でそのまま動きを足して仕上げる。

## 6. 関門2へ（コースで分かれる）

- **お試し:** 確認ページは作らない。上の5節（下描きとラフ画）も省いてよい。下の「次の段階へ」に進む。
- **サンプル:** 構成の確認のページを作る: `node "<プラグイン>/scripts/review-page.mjs" "<制作>" plan`。ブリーフィングの要約、スタイル、既定から外すこと、絵コンテが1枚に出る。下の2と3は同じように行い、承認を得たら `node "<プラグイン>/scripts/project.mjs" approve "<制作>" plan`（ブリーフィング・スタイル・絵コンテをまとめて承認したことになる）。そのあと下の「次の段階へ」に進む。
- **本番:** 次の1〜4のあと、「次の段階へ」に進む。

1. `node "<プラグイン>/scripts/review-page.mjs" "<制作>" storyboard`
2. 利用者には「文字はここで確定します。製品名、数値、言い回しを一字ずつ確かめてください」と伝える。技術解説では用語の正しさ、マニュアルでは手順の番号と画面の対応を、特に見てもらう。
3. 指摘を直したら `timeline.mjs validate` を通し、ページを作り直す。
4. 承認を得たら `node "<プラグイン>/scripts/project.mjs" approve "<制作>" storyboard`

### 次の段階へ（どのコースでも）

ナレーションか BGM を使うなら `project.mjs stage "<制作>" audio`（段階4）、どちらも使わないなら `project.mjs stage "<制作>" build`（段階5）へ。効果音は段階4を通らなくても鳴る（`timeline.json` の `sfx` から書き出しの時に作られる）。
