# 段階2 スタイル決め

見た目の方向を、言葉と静止画で決める。毎回、要件に応じて決める（決まった社のブランドを既定にしない。ブリーフィングで指定されたときだけ使う）。

案の数と確認はコースで変わる（SKILL.md の「コース」）。

| コース | 案 | 静止画 | 確認 |
|---|---|---|---|
| お試し | 1方向に決める | 作らない | 納品のページで見てもらう |
| サンプル | 1方向に決める | 1〜2枚 | 絵コンテの後の構成の確認（`plan`）で見てもらう |
| 本番 | 方向の違う2〜3案 | 案ごとに1〜2枚 | スタイルの確認（`style`）で選んでもらう |

どのコースでも、方向を決めたら「既定から外すこと」（下の6章）を決めて書く。

## 1. 参照を分析する

利用者が渡した参考（動画、サイト、ブランドの資料）を、次の6つの観点で言葉にする。**被写体やコピー（文言）は真似しない。** 真似してよいのは、下の観点の「癖」だけ。

| 観点 | 書き出すこと |
|---|---|
| 色 | 背景・文字・強調の色（16進）、色の数、明るさの傾向、グラデーションの有無 |
| 書体 | ゴシックか明朝か、太さの幅、字間、見出しと本文の大きさの比 |
| 構図 | 余白の量、揃えの基準（左揃え・中央）、格子、画面の何割を何が占めるか |
| ペース | 1カットの長さ、切り替えの頻度、止まって見せる時間 |
| モーション | 入りと出の速さ、イージングの性格（鋭い・柔らかい）、ずらし、跳ねの有無 |
| 質感 | 平面か立体か、影、粒子やノイズ、写真や画面の扱い（角丸、枠、影） |

参考が無ければ、ブリーフィング（見る人、流す場所、方向）からこの6つを決める。決め方の数値の既定は [motion-rules.md](motion-rules.md)、何も言われないときに避ける癖は [banned.md](banned.md)。

## 2. 方向の違う2〜3案を考える（本番）

お試しとサンプルでは、下の例やブリーフィングの方向から1つに決める。本番では、案どうしは、色や書体の小さな違いではなく、**方向**を変える。たとえば:

- 案A: 明るい地、広い余白、細めのゴシック、柔らかく遅い動き（落ち着き、信頼）
- 案B: 暗い地、強い一色の強調、太いゴシック、鋭く速い動き（勢い、新しさ）
- 案C: 製品画面が主役、地は無彩色、文字は最小限、画面への寄りで見せる（具体、実用）
- 案D: 明るい地（白や淡色）、役割を決めた 3〜4 色の多色、図形や色の面が動く、テンポの速いカット、効果音を多めに（楽しさ、親しみ、勢い）

ブランドの指定がある案件では、色と書体は守り、構図・ペース・モーション・質感で方向を変える。

### 案D（明るい多色）で点検を通すには

[banned.md](banned.md) は多色を避ける癖に入れていない。何も言われないときに避けるのは紫のグラデーション、漂う粒、跳ねる UI、同時に複数のヒーローで、案D でも、使う人の意図が無ければそのまま避ける。色は平らな面で使い、グラデーションにしない。

| 役割 | 例 | 使い方 |
|---|---|---|
| 地 | `#FFFFFF` か `#FFF8EC` | 画面の大半 |
| 文字 | `#1F2430` | すべての文字。地の上でも色の面の上でも同じ色 |
| 色1〜4 | `#FF6B4A` `#FFC23D` `#3DA5FF` `#2EC4A6` | 1色に1つの意味（例: 色1 = 課題、色3 = 解決、色2 = 強調の印）。動画を通して入れ替えない |

- **文字は濃い色にする。** 上の4色は、どれも `#1F2430` の文字と 5.5:1 以上になるが、白い文字とは 1.6〜2.8:1 しかない（点検の `contrast` を通らない）。淡い色や彩度の高い色を文字の色にしない。色の面に文字を載せるときは、面を文字の箱（背景色を持つ要素）にして、その上に濃い文字を置く。
- **動く図形は、文字に重ねない。** 図形が文字の手前に 0.2 秒以上重なると、点検の `cover` が指摘する（[composition.md](composition.md) の3章）。文字の後ろを通る図形は `cover` に数えず、`contrast` も文字のまわりの明るさで測るだけなので、その瞬間だけ読みにくくなっても見落とすことがある。文字が出ているあいだ、図形は文字の箱の外（余白の側、画面の端）で動かす。文字を図形の上に置きたいときは、図形を止めて、文字の箱にする。
- **カットの頭の1コマだけを白くしない。** カットの最初のコマだけが何も無く、次のコマで図形や面が一気に出そろうと、前のカットとのつなぎ目で1コマだけ白くなり、点検の `blank` が指摘する。前のカットの図形を引き継ぐか、図形を少し出た状態から始める。フェードや拭き取りでだんだん出す入場は問わない（[composition.md](composition.md) の9章）。
- **図形は少なく大きく、意味を持たせる。** 1カットに 3〜5 個まで。主題を囲む、次のカットへの転換を運ぶ、数や順番を表す、のどれかに使い、飾りの粒にしない（`banned.md` のパーティクル。意図して使うなら6章で外す）。動きは `ms.ease.outExpo` で、跳ねは小さな印にだけ（`ms.ease.outBack` は1本に1〜2回）。ヒーローの動きは同時に1つで、図形はずらして後から追わせる。
- **色の面での転換は、明るさの往復に気をつける。** 白い地と濃い色の面が画面いっぱいに入れ替わると、平均の明るさが2割を超えて動き、点検の `flash`（点滅は毎秒3回まで）に数えられる。テンポの速い区間でも、画面いっぱいの入れ替えは1秒に1回までにし、面は画面の半分以下か、地と明るさの近い色（色2・色3）で覆う。
- **効果音は多めでも、1つの動きに1音。** 図形の着地ごとに鳴らしてよいが、同じ音を3回続けない（`pop`、`tick`、`click` を替える）。音の置き方は [audio.md](audio.md) の5章。

## 3. 書体を取り込む

書体は Google Fonts から選び、制作フォルダに取り込む（描画は常にローカルのファイルを読む）。

```
node "<プラグイン>/scripts/fonts.mjs" "<制作>" "Noto Sans JP" 400,700
```

- `assets/fonts/` にファイルが入り、`assets/fonts/fonts.css` に `@font-face` が足される。シーンのひな形はこの `fonts.css` を読む行を最初から持っている。
- 太さを足すときは、全部の太さを指定して同じ書体を取り込み直す（`fonts.css` のその書体の定義は置き換わる。古い太さのファイルは `assets/fonts/` に残るが害はない）。
- Google Fonts の書体のライセンスは OFL（商用で使える）。権利一覧に書体名と OFL を書く（[export.md](export.md)）。
- ブランドの書体が Google Fonts に無いときは、利用者からファイル（woff2 など）と使ってよい条件を受け取り、`assets/fonts/` に置いて `fonts.css` に `@font-face` を手で書く。
- 書体がまだ無い状態でシーンを撮ると「フォントを読み込めません」で止まる。撮る前に取り込む。
- **取り込めないとき**（「フォント「…」を取得できません」。会社のネットワークで Google Fonts が止められていることが多い）は、次のどちらかにする。
  - 利用者に、ブラウザで https://fonts.google.com/ からその書体を落としてもらう（「Get font」→「Download all」の zip）。zip の中の `.ttf`（可変の太さのファイルなら1つ）を `assets/fonts/` に置き、`fonts.css` に `@font-face`（`font-family`、`src: url("ファイル名")`、`font-weight`）を手で書く。ライセンスは zip の中の `OFL.txt` で確かめ、権利一覧に書く。
  - パソコンに最初から入っている書体を使う（Windows は「Yu Gothic UI」「Meiryo」、Mac は「Hiragino Sans」）。`font-family` にこの名前を並べて書く。書き出した PC と別の PC で描き直すと見た目が変わりうることを、`style.md` に書いておく。

## 4. 案の静止画を作る

案ごとに静止画を1〜2枚作る（見出しが出た画と、中身が並んだ画）。シーンのひな形から作り、時刻を指定して撮る。お試しでは作らない。サンプルでは1方向の分だけ作る。

1. **仮の `timeline.json` を書く。** 案ごと・画ごとに 2 秒のシーンを並べる（id は `style-a1`、`style-a2`、`style-b1`…、`file` は `src/scenes/style-a1.html`…）。文字は、ブリーフィングの「一番覚えてほしい一文」と、構成に合う短いテロップを `texts` に入れる（文字の直書きはしない）。書き方は [storyboard.md](storyboard.md) の `timeline.json` の節と同じ。仮のシーンは 2 秒なので、`timeline.mjs validate` が「表示が 2 秒しかありません」と出すことがある。静止画を撮るだけなので、この表示時間の指摘は直さなくてよい（撮るのは止まらない）。
2. **シーンを作る。** `<プラグイン>/templates/scene.html` を `src/scenes/style-a1.html` などに写し、案の色・書体・構図で組む。入場の動きを入れ、1.5 秒の時点で出そろうようにする。約束事は [composition.md](composition.md)。
3. **撮る。** 各シーンの 1.5 秒の時点（シーンが 0〜2 秒なら 1.5、2〜4 秒なら 3.5…）を撮る。

   ```
   node "<プラグイン>/scripts/frames.mjs" "<制作>" at 1.5 3.5 5.5 7.5 --preset final
   ```

   撮った PNG のパスが、指定した順に1行ずつ出る。
4. **名前を付けて置く。** 撮った PNG を `reviews/style/<案の字>-<番号>.png`（`a-1.png`、`a-2.png`、`b-1.png`…）に写す。確認ページは名前の先頭の字で「案 A」「案 B」にまとめる。この名前でないと、案ごとに分かれない。
5. **自分で見る。** 写した PNG を画像として開いて見る。文字のはみ出し、重なり、読みにくさ、案どうしが似すぎていないかを確かめ、直してから見せる。

## 5. style.md を書き、選んでもらう

選んでもらう間の `style.md` には、案ごとに下のひな形の中身（パレット、書体、動きの性格）を並べて書く。確認ページで静止画の下に表示される（16進の色には色見本が付く）。

お試しとサンプルでは選んでもらわない。決めた1方向で `style.md` を書き、6章の宣言をして、`node "<プラグイン>/scripts/project.mjs" stage "<制作>" storyboard` で段階3へ進む（静止画を作ったサンプルでは、仮のシーンを下の4のとおり片付ける）。本番は次のとおり。

1. `node "<プラグイン>/scripts/review-page.mjs" "<制作>" style`
2. 選ばれたら `node "<プラグイン>/scripts/project.mjs" approve "<制作>" style --note "案B"`。混ぜる希望（「Bの色でAの動き」）があれば、混ぜた案の静止画を作り直して見せてから承認を記録する。
3. `style.md` を、選ばれた案だけの形に書き直す。
4. 仮のシーンを片付ける。選ばれた案の HTML は `reviews/style/` に写して参考に残し、`src/scenes/style-*.html` はすべて消す。仮の `timeline.json` は段階3で書き直す。
5. `node "<プラグイン>/scripts/project.mjs" stage "<制作>" storyboard` で段階3へ。

## 6. 既定から外すことを決め、宣言する

方向を決めたら、その方向のために既定から外すことを決める。一つずつ使う人に聞かず、方向から読み取る（例: 「サイバーで激しく」なら、ネオン、グリッチ、点滅、低いコントラストの背景の文字）。方向から判断がつかないものだけ、まとめて確かめる。

1. **`style.md` の「既定から外すこと」節に書く。** 1行に1つ、何を、どこで、なぜ外すか（例: 「背景に大きな社名を薄く敷く（読ませない飾り。全カット）」）。確認ページの「この動画で既定から外していること」に出る。
2. **自動点検に関わるものは宣言する。** 動画全体かシーンを絞るなら `node "<プラグイン>/scripts/project.mjs" intent "<制作>" --check <点検の名前> --why "理由" [--scenes s01,s02]`。特定の要素だけなら、シーンを描くときに要素へ `data-ms-intent` を付ける（[composition.md](composition.md) の「意図した演出の宣言」）。

   | やりたい演出 | 点検の名前 |
   |---|---|
   | 点滅、激しい明暗の切り替え | `flash` |
   | 背景に薄く敷く文字、地に溶ける文字 | `contrast` |
   | 画面や箱からはみ出して切れる巨大な文字 | `overflow` |
   | 一瞬で流れ去る文字 | `hold` |
   | 文字どうしを重ねる、文字の上を形が通り続ける | `overlap`、`cover` |
   | 字幕の帯にかかる大きな文字 | `safe-area` |
   | 暗転や白みのつなぎ | `blank` |
   | 声を重ねる | `narration` |
   | 静かな環境音だけ、あえて大きな音 | `loudness` |
   | 継ぎ目を見せるループ | `loop` |

   `flash`、`hold`、`narration`、`loudness`、`loop` は要素と結びつかないので、`project.mjs intent` でだけ宣言できる（`data-ms-intent` には書けない）。`style.md` に書くだけでは点検に効かない。

3. **点滅を外すときは、1度だけ伝える。** 次の文を下敷きにする。

   > 点滅を使う演出にします。光に敏感な人が発作を起こすおそれがあります。SNS や展示会など、不特定の人が見る場所で流すなら、冒頭に「点滅する映像が含まれます」といった注意書きを入れることもできます。入れますか。

   入れるかどうかは使う人が決める。決めたら `style.md` の「既定から外すこと」に「点滅の注意書き: 入れる」か「点滅の注意書き: 入れない」と1行書く。入れると決めたら、冒頭のカットとして絵コンテに足す。納品のページには、点滅があることの注意と、注意書きを入れたかどうかが出る（書いていなければ「まだ確かめていません」と出る）。

- **点検を通すためだけに外さない。** 外すのは、演出の意図がブリーフィングかスタイルの方向から言えるときだけ（`--why` に書く）。描いてみて点検に引っかかった崩れは、まず直す。後から宣言を足すと、次の確認ページで「後から足した」と出る。
- 事実に関わる決まり（[content-rules.md](content-rules.md) の「固定」）は外せない。ロゴを途中で変形するのは見せ方なので外せるが、止まって見せる場面では渡されたままの形と色で見せる。

## style.md のひな形

```markdown
# スタイル: <題名>

## パレット
| 役割 | 色 | 使いどころ |
|---|---|---|
| 背景 | `#0F172A` | 全カットの地 |
| 文字 | `#F8FAFC` | 見出し・テロップ（背景とのコントラスト 4.5:1 以上） |
| 強調 | `#38BDF8` | 一番覚えてほしい一文の強調語、矢印 |
| 補助 | `#94A3B8` | ラベル、区切り線（読ませる文字には使わない） |

## 書体
- 見出し: Noto Sans JP 700、96〜120px（16:9）
- テロップ: Noto Sans JP 400、44px
- 字幕: Noto Sans JP 500、48px、字幕の帯（16:9 は下 10%、9:16 は下から 20〜30%。motion-rules.md の「比率ごとの下の安全域」）
- 数字: 等幅の数字（`font-variant-numeric: tabular-nums`）

## 構図
- 左揃え、左右の余白 8%、12 列の格子
- 製品画面は画面幅の 60% まで、角丸 16px、影なし

## 動きの性格
- 入場: `ms.ease.outExpo`、600〜700ms。退場は入場の約 6 割の長さで `ms.ease.inQuart`
- ずらし: 80ms。ヒーローの動きは同時に1つ
- ばね: 使わない（落ち着いた印象のため）
- 切り替え: 押し出し（横 8%）か、カットで切る。クロスフェードは使わない

## 質感
- 平面。影・グロー・粒子なし

## 既定から外すこと
- <方向のために、何も言われないときの既定から外すこと。何を、どこで、なぜ。無ければ「- なし」>

## 禁止
- <この動画で避けること。点検や指摘で見つけた癖もここに足す（banned.md の「新しく見つけた癖を足す手順」）>
```

動きの値は [motion-rules.md](motion-rules.md) の既定から選ぶ。外すときは、その理由を1行添える。
