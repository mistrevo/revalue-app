# モーションの作法

シーンを描くときの数値の既定値。何も言われなければ、この値で描く。使う人の意図でスタイルの方向を決めたら（例: 「ポップに跳ねさせたい」）、その動画の `style.md` が優先する。外すときは、外す理由を `storyboard.md` か `style.md`（「既定から外すこと」）に一行で書く。「なんとなく」で外さない。

数値の出発点は、spec の参考資料 2（@flxrnc の投稿）と 5（whaleyxbt/claude-motion の motion-design）、4（awesome-opus5-5-videos の作例プロンプト）。そこに日本語の文字組みと、このランタイムの書き方を足した。

---

## 1. このランタイムでの書き方

動きはすべて「シーン内の時刻 t（秒）から値を決める関数」で書く。前のフレームの状態を覚えて足し込まない。

- `ms.scene((t) => { ... })` の中で、要素の `style.transform` と `style.opacity` などを t から決める。
- CSS の `@keyframes` も使える。ランタイムが seek のたびに `currentTime` をシーンの時刻にそろえる。開始のずれは `animation-delay` で書く。
- CSS の `transition` は効かない（ランタイムが止める）。
- `setTimeout` と `setInterval` は、描き始めた後に呼ぶと例外になる。待ち時間は t の比較で書く。
- 乱数は `ms.rand()` を使う。seek のたびに seed から始め直すので、呼ぶ順番と回数を毎フレーム同じにする（条件によって呼んだり呼ばなかったりしない）。
- 長さは秒で書く。下の表の「ms」は、コードでは 1000 で割って秒にする（250ms は 0.25）。

区間の進み具合は、次の小さな関数で作る。シーンの先頭にこれを置いてから使う。

```js
const clamp01 = (x) => Math.min(1, Math.max(0, x));
/** t0 秒から dur 秒かけて 0→1。e はイージング */
const prog = (t, t0, dur, e = ms.ease.outExpo) => e(clamp01((t - t0) / dur));
const lerp = (a, b, p) => a + (b - a) * p;

ms.scene((t) => {
  const p = prog(t, 0.2, 0.7);              // ヒーローの入場 700ms
  hero.style.transform = `translateY(${lerp(32, 0, p)}px)`;
  const q = prog(t, 3.0, 0.4, ms.ease.inQuart); // 退場 400ms（入場の約 57%）
  hero.style.opacity = String(1 - q);
});
```

## 2. イージング

ランタイムが持つ曲線は次の5つだけ。新しい曲線を足さない（足したくなったら、まず下の5つで足りないかを考える）。`@keyframes` で書くときは、右の `cubic-bezier` をそのまま `animation-timing-function` に書けば同じ形になる。

| 名前 | cubic-bezier | 使う場所 |
|---|---|---|
| `ms.ease.outExpo` | (0.16, 1, 0.3, 1) | 入場の既定。文字、カード、画面の部品が「着く」動き。最初に速く、最後にすっと止まる |
| `ms.ease.outQuint` | (0.22, 1, 0.36, 1) | outExpo より止まり際が穏やか。大きな面（画面全体、製品の画面）の入場や、カメラの寄り |
| `ms.ease.inOutCubic` | (0.76, 0, 0.24, 1) | 画面の中で A から B へ移る動き（位置の入れ替え、変形、ある要素が次のカットの要素になる動き） |
| `ms.ease.inQuart` | (0.7, 0, 0.84, 0) | 退場。ゆっくり動き出して、速く去る。去るものを見せ続けない |
| `ms.ease.outBack` | (0.34, 1.56, 0.64, 1) | 行き過ぎて戻る（約 10%）。小さな印（バッジ、チェック、点）に、1本の動画で1〜2回まで。文字、カード、画面には使わない |

- **直線（イージングなし）を使ってよいのは、始まりも終わりも画面に映らない連続の動きだけ。** 回転し続けるもの、ゆっくり流れる背景、静止カットの 2% の寄り（9章）。動き出す、止まる動きに直線を使わない。
- 1つのカットで使う曲線は3種類まで（入場用、移動用、退場用）。同じ役割の動きには、動画全体で同じ曲線を使う（入場で使い分けてよいのは、文字と部品の `ms.ease.outExpo` と、大きな面の `ms.ease.outQuint` の2つまで）。曲線の種類が多いと、動きの性格がばらばらに見える。
- 製品の「上質さ」を出したいときの行き過ぎ（オーバーシュート）は 2% 未満に抑える。ばね（6章）なら減衰比 0.78 以上（既定は 0.8）で作る。outBack の 10% は大きすぎる。

## 3. 時間

| 動きの種類 | 長さ | 例 |
|---|---|---|
| UI の小さな変化 | 100〜200ms | ボタンの押下、チェックが付く、数字が1つ変わる、ホバーの色 |
| 移動 | 200〜500ms | カードが位置を変える、一覧に行が入る、矢印が伸びる |
| ヒーロー（見せ場） | 600〜900ms | ロゴが現れる、製品の画面が立ち上がる、主題の一文が出る |
| カメラの動き・寄り（ズーム） | 500〜900ms | 画面の操作箇所へ寄る、全体へ引く、横に流す。`ms.ease.inOutCubic` か `ms.ease.outQuint` |
| カーソルの移動 | 400〜700ms | マニュアルや製品紹介で、マウスの位置が次の操作箇所へ動く。`ms.ease.inOutCubic` |
| 場面転換（マスク） | 400〜600ms | `clip-path` で次のカットへ切り替える（11章） |
| 退場 | 入場の 50〜60% | 入場 700ms なら退場 350〜420ms。`ms.ease.inQuart` |

- 「移動」の帯（200〜500ms）は、画面の中の部品が位置を変える動き。画面全体が動いて見えるカメラの動きと、目で追わせるカーソルの移動は、上の別の帯を使う。

- 動く距離が長いほど長くする。ただし上の帯の上限を超えない。帯に収まらないほど遠いなら、動かす距離を減らすか、カットを分ける。
- 同じ長さの動きを並べない。1つのカットに「短い・中くらい・長い」の3段階が混ざると、自然に見える。全要素が 500ms で動くと機械的に見える。
- 参考: 作例の一つ（参考資料 4）は、カード 280ms、見出し 220ms、付随情報 160ms、ずらし 60ms で組んでいる。UI の部品の入場はこのくらいの短さで足りる。

## 4. ずらしと重なり

ずらしには2種類あり、使い分ける。

**(a) 同じ種類のものが並ぶとき（くり返しのずらし）:** 決まった幅でずらす。

| 何をずらすか | ずらし幅 |
|---|---|
| 単語（日本語なら文節） | 60〜120ms |
| 項目（一覧の行、カード、アイコン） | 40〜80ms |

**(b) 役割の違うものが続くとき（見出し → 本文 → ボタン、製品画面 → ラベル）:** 前の要素の進み具合で決める。

- **次の要素は、前の要素が 30〜50% 進んだところで動き始める。** 前が終わるのを待ってから次を始めると、「読み込み中」のように間が空いて見える。700ms の見出しの入場なら、本文は 210〜350ms 後に始める。
- (a) の幅を役割の違うものに使わない（見出しと本文を 60ms ずらしただけだと、ほぼ同時に見えて階層が出ない）。(b) の考え方をくり返しの項目に使わない（項目ごとに前の 30〜50% を待つと、一覧が出そろうまでが長すぎる）。
- ずらす数が多いときは、総時間で上限を決める。項目が 12 個あっても、最後の項目が動き始めるまでを 600ms 以内にする（1つあたりのずらしを縮める）。
- カットとカットも重ねる。前のカットが去り切る前に、次のカットの最初の要素が入り始める（退場の後半 30〜50% と、次の入場の頭を重ねる）。黒や空の画面が 0.1 秒（30fps で 3 フレーム）を超えて続かないようにする。意図して間を置くとき（章の区切り、締めの前の溜め）は、その理由を絵コンテに書く。

**日本語を語ごとにずらすとき:** `data-ms-text` の要素の中に、`ms.text(id)` を分けた `span` を入れる（つなげた文字列は原稿と同じなので、点検の「原稿との一致」を通る）。分け方は `new Intl.Segmenter('ja', { granularity: 'word' })` で語に分け、助詞は前の語にくっつけて文節にする。

- `span` は HTML に手で書かず、スクリプトで `ms.text(id)` から作る（`ms.scene` を呼ぶ前に1回）。ランタイムは seek のたびに、要素の `textContent` が原稿と違えば `textContent` を原稿で置き換える。手で書いた `span` の間に改行や空白があると、つなげた文字列が原稿と一致せず、`span` ごと消されて1つの文字に戻ってしまう。
- 作るときは、`span` の間に空白の文字ノードを入れない（`el.replaceChildren(...spans)` のように `span` だけを並べる）。

```js
const el = document.querySelector('[data-ms-text="t01"]');
const seg = new Intl.Segmenter('ja', { granularity: 'word' });
const words = [...seg.segment(ms.text('t01'))].map((s) => s.segment); // 必要なら助詞を前の語へまとめる
el.replaceChildren(...words.map((w) => Object.assign(document.createElement('span'), { textContent: w })));
```

- 1文字ずつずらすのは、4〜8文字の短いロゴ文字やキーワードだけにする（長い文で1文字ずつ出すと、読む速さより遅くなる）。

## 5. 階層: ヒーローの動きは同時に1つ

- 1つの時刻に「見てほしい動き」は1つだけ。ヒーローが動いている間、ほかの要素は止まっているか、ヒーローより小さく短い動き（UI の小さな変化の帯）にとどめる。
- 同時に動いてよい要素は、ヒーローを含めて3つまで。4つ目は、ヒーローが 50% 進むまで待たせる。
- 視線の先を1つにする。主役が画面の左にいるのに、右で別の数字が数え上がる、という絵を作らない。
- 1本の動画で最大の見せ場は1つ。それ以外のヒーローは、最大の見せ場より短く、小さくする。最大の見せ場を冒頭で使い切らない。

## 6. ばね

`ms.spring({ damping, stiffness })` は、質量 1 で 0 から 1 へ向かうばね。戻り値は時刻（秒）を受け取る関数。

```js
const s = ms.spring({ damping: 16, stiffness: 100 }); // 減衰比 0.8
const p = s(Math.max(0, t - 0.4));                     // 0.4 秒から動き出す
```

減衰比 ζ は `damping ÷ (2 × √stiffness)`。**使ってよい幅は 0.7〜0.85。** 0.7 未満は跳ね、1.0 以上はもったりする。

**上質に見せる（行き過ぎ 2% 未満）には、減衰比 0.78 以上にする。** 行き過ぎは減衰比だけで決まり（0.78 で約 2.0%、0.8 で約 1.5%、0.85 で約 0.6%）、stiffness では変わらない。0.7〜0.78 は行き過ぎが目に見える「生き生きした」側で、小さな物にだけ使う。

| 性格 | stiffness | damping | 減衰比 | 行き過ぎ | 止まるまで（目安） | 使う場所 |
|---|---|---|---|---|---|---|
| 既定（上質） | 100 | 16 | 0.80 | 約 1.5% | 約 0.5 秒 | 画面の部品、カード |
| 落ち着き（上質） | 100 | 17 | 0.85 | 約 0.6% | 約 0.47 秒 | 大きな面、製品の画面、ロゴ |
| きびきび（上質） | 300 | 28 | 0.81 | 約 1.3% | 約 0.29 秒 | 小さな印、トグル |
| 生き生き（行き過ぎが見える） | 100 | 15 | 0.75 | 約 2.8% | 約 0.53 秒 | 「固い」と言われたときの部品。上質さより軽さを取る場面 |
| 張りあり（行き過ぎが見える） | 170 | 19 | 0.73 | 約 3.5% | 約 0.42 秒 | 「ポップに」と言われたときの小物だけ |

- **引数を省くと damping 10・stiffness 100（減衰比 0.5、行き過ぎ約 16%）になる。これは跳ねすぎるので、必ず値を書く。**
- 「止まるまで」は、行き過ぎが見えなくなるまでのおよその時間（4 ÷ (ζ × √stiffness) 秒）。この時間をホールドの開始と考え、ホールドの長さ（8章）はここから数える。
- ばねは「物」に使う（カード、画面の部品、ロゴの面）。文字の入場とカメラの動きには、イージング（2章）を使う。
- 速さの調整は stiffness で、跳ね具合の調整は damping で行う。stiffness を変えたら、減衰比が 0.7〜0.85 に収まるように damping も直す（stiffness を 4 倍にしたら damping は 2 倍）。

## 7. 視差

奥行きを出すときは、層ごとに動く量を変える。

| 層 | 動く量の倍率 | 例 |
|---|---|---|
| 手前 | 1.0 | 主役の製品画面、主題の文字 |
| 中間 | 0.5 | 補足のカード、ラベル |
| 奥 | 0.2 | 背景の面、模様、色の広がり |

```js
const cam = lerp(0, -120, prog(t, 0.2, 0.8, ms.ease.inOutCubic)); // カメラの横移動（800ms）
fg.style.transform = `translateX(${cam * 1.0}px)`;
mid.style.transform = `translateX(${cam * 0.5}px)`;
bg.style.transform = `translateX(${cam * 0.2}px)`;
```

- 層は3枚まで。4枚以上にすると、奥行きより揺れに見える。
- 視差を付けるのは、カメラが動くカットだけ。カメラが止まっているのに層をばらばらに動かさない。

## 8. ホールド（読ませる時間）

- 文字は、動き終わってから読み終わるまで止める。**読ませている間は文字を動かさない**（2% の寄り以外）。
- 最短の表示時間は、日本語が「文字数 ÷ 5 + 0.5 秒」、英語が「0.3 秒 × 語数 + 0.5 秒」（自動点検の `hold` と同じ式。句読点と空白は数えない）。日本語の中の英単語と数字（Azure、Serverless、2026 など）は、1文字ずつではなく、ひとつながりを1語として 0.3 秒で数える（「PaaS / Serverless のインフラ構築」なら 7 ÷ 5 + 0.3 × 2 + 0.5 = 2.5 秒）。ナレーションと同じ文の字幕（subtitle）だけは例外で、声の始まりまでに出し、話し終えて 0.5 秒たつまで出ていればよい（声と一緒に読むため。storyboard.md の「文字の書き方」）。ここで言う表示時間は、`timeline.json` の `texts` の `start` から `end` まで。入場の動きの時間もこの中に入るので、動きが長いほど止まっている時間が減ることに注意する。
- 締めの一文、ロゴの決めは、最短の表示時間に加えて 1.0 秒以上止める（最後の 1.5〜2.0 秒は動かさない）。
- 表示時間が足りないときは、文字を短くするか、カットを長くする。動きを速くして稼がない。

## 9. 止まっているカットの 2% の寄り

主な動きが終わって止まっている時間が 1.5 秒を超えるカットには、カット全体にゆっくりした寄りを付ける。完全に止まった絵は、動画の中では「固まった」ように見える。

```js
const push = lerp(1.0, 1.02, clamp01(t / ms.duration)); // カットの長さ全体で 2%。直線
stage.style.transform = `scale(${push})`;
```

- 寄せる量は 2%（`scale` 1.00 → 1.02）。3% を超えると「ズームしている」と気づかれる。
- 直線で、カットの長さ全体に伸ばす。途中で止めたり、速さを変えたりしない。
- 寄せるのは、文字とその背景をまとめた外側の箱（ステージ）。文字だけを拡大しない（読ませる文字が動いて見える）。
- 全カットに付けない。カメラや主役が動いているカット、0.8 秒未満の短いカット、ロゴの決め（[examples/logo-reveal.md](examples/logo-reveal.md)）、ループの継ぎ目にかかるカットには付けない（常時ズームは、既定で避ける癖（[banned.md](banned.md)）に入っている）。

## 10. ビートグリッド（音楽に合わせるとき）

BGM の拍に動きを合わせると、映像に芯が通る。

- **1拍のフレーム数 = fps × 60 ÷ BPM。** 30fps・120BPM なら 15 フレーム、60fps・120BPM なら 30 フレーム、30fps・100BPM なら 18 フレーム。
- 割り切れない BPM（例: 30fps・128BPM は 14.0625 フレーム）では、1拍のフレーム数を丸めてから足し込まない。誤差がたまって後半がずれる。**n 拍目の時刻 = n × 60 ÷ BPM 秒を計算し、そのたびにフレームへ丸める**（`Math.round(n * 60 / bpm * fps) / fps`）。
- 大きな動き（ヒーローの着地、カットの切り替え）は、小節の頭（4拍ごと）に置く。小さな動き（項目のずらし）は、拍か半拍に置く。
- 動きの「着地」を拍に合わせる。動き出しではなく、止まる瞬間を拍に置く（`start = 拍の時刻 − 動きの長さ`）。
- 効果音は、映像のイベントの 1 フレーム後に置く（`timeline.json` の `sfx` の `t`）。音が絵より先に鳴ると、ずれて見える。
- BPM の目安: 上質な製品紹介は 100〜120、解説とマニュアルは 80〜100（または BGM なし）、ローンチの盛り上がりは 120〜128。

---

## 11. 場面転換

- 転換は、画面に映っている物で動機づける。前のカットの要素が、次のカットの要素になる（グラフの点が次のカードの角になる、数字が次の画面の金額になる、ボタンが次の画面に広がる）。同じ位置・同じ大きさの形を受け渡すと、「そこから次が出てきた」と見える。
- 次に良いのは、マスクで切り替える（`clip-path: inset(...)` を `ms.ease.inOutCubic` で 400〜600ms）、または意図したカット（拍の頭で切る）。
- クロスフェード（前後の絵が半透明で重なる）は、時間の経過を表すときだけ。1本の動画で2回まで。
- 汎用のワイプ、回転、グリッチ、ズームブラーは、何も言われなければ使わない（既定で避ける癖。[banned.md](banned.md)）。

---

## 12. 動きの量

1920×1080 を基準にした目安。ほかの比率では短い辺の比で換算する。

| 動き | 量 |
|---|---|
| 入場の移動距離（文字、カード） | 16〜48px。100px を超えると「飛んでくる」ように見える |
| 入場の拡大 | 0.96 → 1.00（ヒーローは 0.92 → 1.00 まで） |
| 回転 | 使うなら 2〜4 度まで。意味のない回転はしない |
| 不透明度 | 入場は 0 → 1 を、移動の最初の 40% で終える。半透明のまま止めない |
| ぼかし | 入場の頭に 8px 以下を 200ms で 0 へ。止まった後の文字と製品画面は必ずくっきり |

- 入場の方法を1種類にしない。1つのカットで、主役はマスクの中から出る、補足は少しの拡大、ラベルは不透明度だけ、のように変える（全要素の「フェードと浮き上がり」は、既定で避ける癖に入っている）。

## 13. 日本語の文字組み

文字は `timeline.json` の原稿を `data-ms-text` で流し込む。改行と字間は CSS と原稿で整える。

- **改行:** 見出しとテロップは、文節の途中で折り返さない。CSS で `word-break: auto-phrase;`（文節で折り返す。`<html lang="ja">` が必要）と `text-wrap: balance;`（行の長さをそろえる）を指定する。どうしても位置を決めたい改行は、原稿の文字に改行（`\n`）を入れ、要素に `white-space: pre-line;` を指定する。原稿の改行は関門 2 で利用者に見せる。
- **禁則:** `line-break: strict;` を指定する。句読点、閉じ括弧、小さい「ゃ」「ッ」、長音「ー」が行頭に来ないようにする。
- **1行の長さ:** テロップ（`caption`）は1行 16 文字まで、2行まで。見出し（`title`）は1行 12 文字までを目安に、2行まで。収まらないなら、文を分けてカットを増やす。
- **約物:** 見出しには `font-feature-settings: "palt";`（約物と仮名の詰め）を指定し、字間は `letter-spacing: 0.02em〜0.04em` に戻す。テロップと本文は詰めず、字間 `0.04em〜0.08em`。行頭の括弧が半角分ずれて見えるときは `text-spacing-trim: trim-start;` を使う。見出しの句点「。」は、1本の動画の中で付けるか付けないかをそろえる（混ぜない）。
- **行の高さ:** 見出しは 1.25〜1.4、テロップと本文は 1.5〜1.7。欧文の作例にある `line-height: 1` は、日本語では上下の行がぶつかるので使わない。
- **欧文と数字:** 数字と英字は欧文の書体で組む（和文の書体の英数字は、たいてい見劣りする）。数え上がる数字には `font-variant-numeric: tabular-nums;` を指定し、桁の幅を固定する（幅が変わると数字が左右に揺れる）。
- **書体:** 1本の動画で和文1つ、欧文または等幅1つまで（合わせて3つまで）。動画は圧縮で細い線が潰れるので、太さは 400 以上。テロップは 500 以上、見出しは 700 前後。
- **縁取りと影:** 写真や画面の上に文字を載せるときは、文字の裏に面（不透明度 0.6 以上の帯）を敷くか、背景を暗くする。太い縁取りは安っぽく見えるので、使っても 2px まで。

## 14. 画面の安全域と最小の文字サイズ

| 項目 | 値（1920×1080 のとき） |
|---|---|
| 下の安全域 | 比率ごとに決める（下の「比率ごとの下の安全域」の表）。16:9 は下 10%（108px）が字幕の帯 |
| 端の余白 | 上・左・右の端から 5%（左右 96px、上 54px）の内側に、読ませる物を置く |
| 見出し（title） | 72〜140px |
| テロップ（caption） | 40px 以上（ノート PC の画面や、縮小表示でも読める下限） |
| ラベル（label） | 28px 以上。28px 未満は飾りとして扱い、読ませる情報を置かない |
| 字幕（subtitle） | 44〜52px、500 以上の太さ、字幕の帯の中（比率ごとの位置は下の表） |
| コントラスト | 文字と背景で 4.5:1 以上（自動点検の `contrast`。文字の上に重ねた半透明の面（周りを暗くする面など）は、文字の色にも重ねて比べる） |
| 点滅 | 毎秒3回以下（自動点検の `flash`）。演出として点滅を使うと決めたときの扱いは [style.md](style.md) の点滅の案内 |

### 比率ごとの下の安全域

字幕（`subtitle`）は「字幕の帯」に置き、字幕のほかの文字（`title`、`caption`、`label`）は帯に入れない。「読ませない場所」には、字幕も含めてどの文字も置かない。どちらも自動点検の `safe-area` が文字の箱の下の端で見る。

| 比率 | 読ませない場所 | 字幕の帯 | 理由 |
|---|---|---|---|
| 16:9（1920×1080） | なし | 下 10%（下から 0〜108px） | 動画の再生画面ではボタンが動画の外か、触ったときだけ出る |
| 1:1（1080×1080） | なし | 下 10%（下から 0〜108px） | フィードの投稿として見られ、ボタンは動画の外に出る |
| 4:5（1080×1350） | なし | 下 10%（下から 0〜135px） | フィードの縦長の投稿として見られ、ボタンや説明文は動画の外（下）に出る。縦型の場所（リール、ストーリーズ、ショート）に流すなら、4:5 ではなく 9:16 で作る |
| 9:16（1080×1920） | 下 20%（下から 0〜384px） | 下から 20〜30%（下から 384〜576px） | 縦型の場所（リール、ストーリーズ、ショート、TikTok）では、下 20% に各サービスのボタン、説明文、再生位置の棒が重なる |

- 縦型（9:16、1080×1920）は、スマートフォンで見られる前提で、テロップを 44px 以上、見出しを 80px 以上にする。SNS では右端にもボタン（いいね、共有）が縦に並ぶので、流す場所が決まっているなら、右端の 15% 前後にも読ませる物を置かない（右端は自動点検では見ないので、フレームで確かめる）。
- 比率ごとのレイアウトは、`[data-ratio="9:16"] .title { ... }` のように比率ごとの CSS で組み直す。16:9 を切り抜いて作らない。
- 最初のフレーム（0 秒）を黒や空にしない。自動再生の一覧では、最初のフレームが見本の絵になる。
- 文字は、出ているあいだに一度は全体が見えるようにする。箱（`overflow: hidden`）が小さくて切れたままの文字や、省略記号（`text-overflow: ellipsis`）で切った文字は、自動点検の `overflow` で指摘される。マスクの中から出す入場は、出し終えたときに全体が見えていればよい。出ているあいだずっと不透明な板（背景色が不透明な要素）の下に隠れたままの文字も、一度も表示されていないとして `overflow` で指摘される（一部の時間だけ隠れるのはよい）。
- 文字は、背景の箱（行、札、カード）に収める。文字のいちばん近い、背景（色か画像）・枠線・影のある祖先の箱（画面全体を覆う箱は除く）を、枠線の内側から 1px を超えて越えたまま、表示のあいだ一度も全部見えて収まらなかった文字は、自動点検の `overflow` で指摘される。滑り込みや拭き取りの入場の途中だけ箱の外に出るのはよい。箱の余白に入るだけ（文字が箱の端に近い）は指摘しないので、余白の詰まり具合はフレームを見て確かめる。
- 流れる文字（マーキー、ニュースのティッカー）や流れるクレジットのように、窓より長い文字をわざと窓の中で流すときは、窓の箱に `data-ms-scroll` を付ける（`<div class="ticker" data-ms-scroll>`）。この箱の中の文字は、窓で切れていても指摘しない。省略記号で切ったテロップには付けない（文字の誤りとして直す）。
