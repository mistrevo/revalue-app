# 段階0 準備

環境を確かめ、足りない道具を入れ、制作フォルダを作る。利用者は Node も ffmpeg も知らない前提で話す。

## 1. 環境を確かめる

```
node "<プラグイン>/scripts/doctor.mjs" --json
```

結果（`node`、`tools`、`ffmpeg`、`browser`、`voicevox`、`gemini`、`ok`）を読み、そのまま貼らずに、次のような言葉で伝える。`--json` を付けずに実行すると、やさしい説明の文が出る。それを下敷きにしてよい。

| 結果 | 伝え方の例 |
|---|---|
| すべて揃っている（`ok: true`） | 「動画づくりに必要な道具は揃っています。さっそく内容のお話に入りましょう。」 |
| `tools.ok: false`、`ffmpeg.ok: false`、`browser.ok: false` のどれか | 「動画を書き出すための道具（画面を撮る部品と、動画にまとめる部品）がまだ入っていません。お使いのパソコンの、ご自分用のフォルダ（`<ホーム>/.claude/ns-motion-studio/tools`）に、部品が使うブラウザも含めて入れます。ほかのソフトには影響しません。5〜15分ほどかかり、1 GB ほどの空きが要ります。インターネットから取ってくるので、会社のネットワークによっては止められることがあります。入れてよいですか。」（`tools.outdated` に名前があるときは、試した版と違うので入れ直す、と伝える。`browser.ok` だけが false なら、ブラウザ本体だけを入れる） |
| `node.ok: false` | 「土台のソフト（Node.js）が古いか、入っていないため、新しくする必要があります（22.12 以上）。」と伝え、下の「Node を入れる」で案内する |
| `voicevox.running: false` | 今は伝えない。ナレーションを付けると決まったら、段階4で案内する（[audio.md](audio.md)） |
| `gemini.keySet: false` | 今は伝えない。Gemini を使うと決まったら案内する（[audio.md](audio.md)） |

## 2. 許可を得てから入れる

**許可を得る前に入れない。** 返事が「はい」「お願いします」など、はっきりした了承のときだけ、次を実行する。

```
node "<プラグイン>/scripts/setup-tools.mjs"
```

- **後ろで実行して、終わりの知らせを待つ。** 5〜15分かかることがあり、前面で実行すると途中で時間切れになる（Claude Code なら Bash の `run_in_background`）。待つ間に、ブリーフィングの質問を始めてよい。
- 入れた後は、もう一度 `doctor.mjs` を実行して `ok: true` を確かめる（ブラウザ本体の `browser.ok` も見る）。
- `setup-tools.mjs` が「入れられませんでした」で終わったら、出た案内（取りに行く先と、プロキシ・社内の証明書の設定）を、そのまま利用者に見せる。利用者には「この文を情報システムの担当に見せてください」と伝える。設定してもらえたら、同じコマンドをもう一度実行する（入った分は飛ばして続きから入れる）。待てない、または入れられないなら、下の「3. 入れられないとき」へ。

### Node を入れる

Node.js は 22.12 以上が要る。入れた後は、**Claude Code を開き直してもらう**（開き直さないと、新しい Node が見つからない）。

| 状況 | 案内 |
|---|---|
| Windows で、ソフトを入れる権限がある | `winget install OpenJS.NodeJS.LTS` |
| Mac で Homebrew がある | `brew install node` |
| どちらでもない、または権限が無い | https://nodejs.org/ の LTS 版の入れ方を伝える。会社のパソコンで、入れるときに管理者の許可を求められて止まるなら、「Node.js（22.12 以上）を入れてほしい」と情報システムの担当に頼んでもらう |
| 頼めない、待てない | 下の「3. 入れられないとき」へ |

## 3. 入れられないとき

社内のルールで入れられない、ネットワークが通らない、利用者が入れたくない、のいずれかなら、ここで無理をしない。

- ブリーフィング（段階1）と、絵コンテ（段階3）までは道具なしで進められる（確認ページは Node だけで作れる。Node も無いときは、確認ページの代わりにチャットで要約を見せる）。スタイルの静止画と絵コンテのラフ画は撮れないので、スタイル決めは言葉と色見本だけで行う。確認はコースに合わせる（[claude-motion-fallback.md](claude-motion-fallback.md)）。
- 制作フォルダを作った（下の4.）あとで、逃げ道に切り替えたことを記録する。再開したときに、道具の導入を繰り返さないため。

  ```
  node "<プラグイン>/scripts/project.mjs" fallback "<制作>" on
  ```

- そのうえで [claude-motion-fallback.md](claude-motion-fallback.md) に従い、Claude Motion に貼るプロンプトを作って渡す。

## 4. 制作フォルダを作る

置き場所と題名を聞いてから作る。題名はファイル名にもなる（完成版は `out/<題名>_16x9.mp4`）。

```
node "<プラグイン>/scripts/project.mjs" init "<制作>" --title "新製品紹介"
```

`assets/`、`audio/`、`src/scenes/`、`reviews/`、`out/` と `project.json`、`.gitignore` ができる。既にあれば上書きせず、そのまま使う（`.gitignore` も、既にあれば書き換えない）。

`.gitignore` を置いたときは、コマンドが出す一文のとおり、書き出した動画（`out/*.mp4`）と音声（`audio/` の wav）、作り直せる中間データは git に入らないことを利用者に伝える。動画と音声は git の外で渡す・残してもらう。

利用者に、素材（ロゴ、スクリーンショット、資料、音源）はこの制作フォルダの `assets/` に入れてもらうよう伝える（チャットで渡されたものは、Claude が `assets/` に置く）。

終わったら `project.mjs stage "<制作>" briefing` で段階1へ。
