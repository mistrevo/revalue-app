# 段階5 自己点検のループと関門3

周の上限とラフ版の有無はコースで変わる（SKILL.md の「コース」）。

| コース | 自己点検の批評 | ラフ版と関門3 | 終わったら |
|---|---|---|---|
| お試し | 1周まで | 作らない | 段階6へ進み、全品質で書き出す |
| サンプル | 2周まで | 作らない | 段階6へ進み、全品質で書き出す |
| 本番 | 4周まで | 作って見てもらう | 関門3の承認の後に段階6へ |

自動点検（手順1）は、どのコースでもすべて行う。

シーンを描いたら、人に見せる前に、描いたフレームを画像で見て直すことを繰り返す。「できたはず」で次へ進まない。

## 1周の手順

1. **自動点検を通す。** 周の途中は、主の比率（`timeline.json` の `ratios` の最初）だけを見る（点検の時間は比率の数だけ延びるため）。

   ```
   node "<プラグイン>/scripts/check.mjs" "<制作>" --ratio <主の比率>
   ```

   シーンを開いて 0.2 秒刻みで、文字のはみ出し（画面の外、小さな箱で切れたまま、背景の箱から出たまま）・字幕の帯への侵入・重なり・文字の上に重なり続ける形（`cover`）・正本との食い違い・直書き・コントラスト・表示時間・描画のエラー・決定論と、カットのつなぎ目で最初のコマだけが背景だけになるちらつき（`blank`）を見る。`--ratio` を省くと `timeline.json` のすべての比率を見る（比率が1つなら省いてよい）。ほかの比率は、自己点検を終える前にまとめて見る（下の「終わりの条件」）。結果は `reviews/checks-build-<比率>.json` にも残り、確認ページに出る。見つかったものは、批評より先にすべて直す。`project.mjs intent` か `data-ms-intent` で宣言した演出に当たった指摘は「意図どおり」と出るので、直さない。`style.md` の「既定から外すこと」に書いただけのもの（宣言していないもの）は点検に効かず、不合格のまま出る。演出の意図があるなら宣言し、無ければ直す。終了コード 2（止め時）が出たら、直すのをやめて [SKILL.md の「止め時」](../SKILL.md) に従う。終了コード 4 は点検そのものが動かなかった（時刻表の誤り、ほかの実行中など）ので、出た文を読んで直してからやり直す。
2. **フレームを撮る。**

   ```
   node "<プラグイン>/scripts/frames.mjs" "<制作>" all
   ```

   `all` は `beats`・`contact`・`strips` をまとめて撮る（1つずつ撮るときは `all` の代わりにその名前を書く）。前の周に撮った静止画は、シーンの中身と時刻と画質が同じなら撮り直さないので、直したシーンの分だけ時間がかかる。`beats` は各カットの落ち着いた時刻（カットの 70%。最後に出る文字が出て 0.6 秒たつ前なら、その時刻）とポスターの時刻、`contact` は1秒ごとの一覧（`reviews/contact-<比率>-01.png`。1枚 32 コマで、長い動画は `-02.png`、`-03.png` … に分かれる）、`strips` はシーンの境目の前後 ±0.25 秒の帯（`reviews/strip-<比率>-cut<前>-<後>.png`）。速い動きの途中を見たいときは `frames.mjs at <秒>…` で足す。
3. **画像を見る。** 撮った PNG を画像として開き、次と見比べる。ブリーフィングの「一番覚えてほしい一文」が伝わるか、`storyboard.md` の入口と出口、その動画の `style.md`（「既定から外すこと」と「禁止」を含む）、[motion-rules.md](motion-rules.md) の既定値、[banned.md](banned.md) の、何も言われないときに避ける癖（`style.md` で使うと決めたものは除く）。
4. **批評を絞る。** 描いたフレームに見えたことだけに基づける（コードを読んだ印象で書かない）。影響の大きい順に、上限（[SKILL.md の「止め時」](../SKILL.md)）までを、次の3点の形で書く。
   - **時刻**: カット番号と時刻（「カット3 0:12.4」）
   - **証拠**: どの画像の、何がどう見えたか（「`strip-16x9-cut3-4.png` の3コマ目で、見出しと製品画面が同時に動いている」）
   - **局所的な直し方**: どの要素の、どの値を、何から何へ（「s04 の製品画面の入場を 0.15 秒遅らせ、見出しの着地の後にする」）
5. **その区間だけ直す。** 批評に挙げていない場所は触らない。直したら、その時刻を撮り直して、直ったことを画像で確かめる。自動点検は毎回、手順1のコマンドで通す（前回から変わっていないシーンは開き直さないので、直したシーンの分しか時間がかからない）。
6. **記録する。** `reviews/self-review.md` に、周の番号、批評、直したことを書き足す。

## 終わりの条件

- 終える前に、`--ratio` を付けずに（すべての比率で）自動点検を通し、ほかの比率だけで出た指摘を直す（直したら、その比率で通し直す）。ラフ版を書き出す前と、段階6へ進む前に、すべての比率で通っていること。
- 批評に挙げる問題が無くなったら終わる。
- 周の上限（[SKILL.md の「止め時」](../SKILL.md)）まで回しても残った問題は、それ以上いじらずに `reviews/compromises.md` に書く（納品のページに「残った妥協点」として出る）。

```markdown
# 残った妥協点

- カット5（0:41〜0:47）: 製品画面の文字が小さく、縦型（9:16）では読みにくい。渡されたスクリーンショットの解像度が足りないため。高い解像度の画面があれば差し替えられます。
```

- 点検で、banned.md にない新しい癖を見つけたら、banned.md の「新しく見つけた癖を足す手順」で、その動画の `style.md` の禁止の節に足してから直す。

## 気をつけること

- 静止画（`frames.mjs`）は、時刻を飛ばして撮るため、動画のコマと縁の数画素が違うことがある。縁の1〜2画素の差は問題にしない。
- 自動点検の点滅・尺・音量の点検は、完成版の MP4 でしか見られない（段階6の全品質の書き出しで通る）。ループの継ぎ目は、シーンの点検でも最初と最後のコマを比べ、完成版では圧縮した後の画で見直す。

## 関門3（代表スチルとラフ版。本番だけ）

お試しとサンプルでは、この節を飛ばし、自己点検が終わったら `project.mjs stage "<制作>" export` で段階6へ進む。

1. ラフ版を書き出す（960×540 相当、30fps、音付き）。時間がかかりそうなら、先に見込みを伝える（`node "<プラグイン>/scripts/render.mjs" "<制作>" --preset draft --estimate`）。

   ```
   node "<プラグイン>/scripts/assemble.mjs" "<制作>" --preset draft
   ```

   `out/<題名>_<比率>_draft.mp4` ができる（比率は `16:9` なら `16x9`）。比率が複数なら全部の比率で作られる。
2. 代表スチル（`frames.mjs beats`）とコンタクトシート（`frames.mjs contact`）が最新であることを確かめる（どちらも、すべての比率で撮る）。
3. 関門の手順は [SKILL.md の「関門での振る舞い」](../SKILL.md)（関門は `rough`）。利用者には「画質を落とした試作版です。動きの流れ、文字、音を見てください。音を出して見てください」と伝える。指摘で直したら、ラフ版も作り直す。
4. 承認の後、`project.mjs stage "<制作>" export` で段階6へ（[export.md](export.md)）。**全品質の書き出しは、この承認の後だけ。**
