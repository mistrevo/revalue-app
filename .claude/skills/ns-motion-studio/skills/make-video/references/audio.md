# 段階4 音の土台

ナレーションを先に作り、その長さで `timeline.json` の秒数を確定させる。BGM を作るか受け取る。効果音は `timeline.json` の `sfx` から書き出しの時に作られるので、ここでは置き場所を見直すだけ。

## 1. 読み上げの方法を選ぶ

| 方法 | 向いているとき | 注意 |
|---|---|---|
| VOICEVOX（基本） | 多くの場合。無料で、パソコンの中だけで動き、原稿を外へ送らない | 導入と起動が要る。使えるキャラクターは、規約が明確なものに絞ってある。クレジット表記が要る |
| Gemini の読み上げ | 自然な声の種類を広く選びたいとき | API キーと費用が要る。原稿を Google へ送る。下の注意事項への了承が必要 |

未公開の製品情報、顧客名、個人情報を含む原稿なら、VOICEVOX を勧める。決めたら `project.json` の `settings.audio.narration` を `voicevox` か `gemini` にする。

## 2. VOICEVOX で作る

1. **導入を案内する。** 「無料の読み上げソフト VOICEVOX を使います。公式サイト（https://voicevox.hiroshiba.jp/ ）からお使いのパソコン用を入れて、起動してください。起動している間だけ使えます。」
2. **起動を確かめ、声の一覧を出す。** 声を利用者が指定しなければ、既定の四国めたん（ノーマル）を使う。一覧を出すのは、別の声を選びたいときだけ。

   ```
   node "<プラグイン>/scripts/voicevox.mjs" speakers
   ```

   使ってよいキャラクターだけが「ずんだもん: ノーマル=3、あまあま=1…」の形で出る（既定の四国めたんには「（既定）」が付く）。数字が声の番号。`--speaker` には番号のほか、「名前/スタイル」（例: `四国めたん/ノーマル`）も渡せる（一覧から番号を引く。名前やスタイルが無ければ、あるスタイルを添えて止まる）。動かなければ「VOICEVOX が起動しているか確かめてください」と伝える。
3. **声を決める。** 既定は四国めたん（ノーマル）。別の声にするなら、見る人と調子に合う声を一覧から2〜3提案する。使えるのは、利用規約が「企業の動画（商用）でも申請・連絡なしに、クレジットだけで使える」とはっきり書いているキャラクターに限る（`voicevox.mjs` の `VOICEVOX_CHARACTERS`。四国めたん、ずんだもん、九州そら、中国うさぎ、中部つるぎ、冥鳴ひまり、雨晴はう、満別花丸）。規約の URL、確かめた日、要点はこの一覧に入っていて、合成のときに `project.json` の `models` に残り、権利の一覧に出る。**制作のたびに規約を読み直さなくてよい。** 一覧に無いキャラクター（企業の利用に問い合わせが要るもの、条件がはっきりしないもの）は `narration.mjs` が止めるので、利用者が望んでも使わず、一覧の中から選び直してもらう。規約の禁止事項（政治・宗教、特定の個人・団体の批判や支持など）に当たる内容の動画なら、声を付ける前に利用者に伝える。
4. **読みを確かめ、読みの辞書を作る。** 英字の語（`ffmpeg`、`ns`）、略語、数字と単位、珍しい漢字（「章ごと」が「アキラゴト」になった）は読み違えやすい。合成の前に、VOICEVOX が各行をどう読むか（`/audio_query` の `accent_phrases` の `moras` をつないだカタカナ）を出して全行を見る（合成はしない）。

   ```
   node "<プラグイン>/scripts/voicevox.mjs" kana "<制作>" [--speaker "ずんだもん/ノーマル"]
   ```

   `--speaker` を省くと既定の四国めたん（ノーマル）で読む。

   `n01: その PNG を…` の下に `→ ソノ/ピイエヌジイオ/ファンペグエ/…` の形で出る（「/」は句切れ、「、」は息継ぎ）。読み違いがあれば、`audio/readings.json` に足して、もう一度出して確かめる。

   ```json
   [
     { "surface": "ffmpeg", "reading": "エフエフエムペグ" },
     { "surface": "ns", "reading": "エヌエス" },
     { "surface": "章ごと", "reading": "ショウゴト" }
   ]
   ```

   - 読み上げに渡す文だけを置き換える。字幕・テロップ・`timeline.json` の原稿は元の文のまま。読みはカタカナで書く。
   - 長い語から先に当てる。英字・数字と、それらをつなぐ記号（`- . _ + # / @ & : '`）の一続きは1語とみなし、見出しがその1語とちょうど同じときだけ当てる（`ns` は `dns` にも `ns-skills` にも当たらない。`ns-skills` を直すなら `ns-skills` で足す。`v2` は `v2.1` に、`.NET` は `ASP.NET` に当たらない）。語の後ろの文末の「.」「,」は語に含めない。大文字と小文字は区別する。同じ見出しを2回書くと、その語を挙げて止まる。
   - VOICEVOX のユーザー辞書には書かない（利用者のエンジンに何も残らない）。辞書は制作フォルダにあるので、作り直しても同じ読みになる。Gemini の読み上げにも同じ辞書が当たる。
   - 日本語と英字・数字の間の半角空白（「その PNG を」）は、VOICEVOX へ渡す文でだけ自動で詰める（空白は 0.3〜0.9 秒の間になるため）。原稿は表記の決まりどおり空白を入れたままでよい。英字どうしの空白（`Claude Code`）は残る。
5. **作る。**

   ```
   node "<プラグイン>/scripts/narration.mjs" "<制作>" --engine voicevox [--speaker "ずんだもん/ノーマル"] [--speed 1.0] [--intonation 1.0]
   ```

   - 省くと、声は四国めたん（ノーマル）、話す速さ 1.1、抑揚 1.2 で作る。`--speed` は話す速さ（0.5〜2.0。エンジンの標準は 1）、`--intonation` は抑揚（0〜2.0。エンジンの標準は 1、0 で平板）。落ち着いた説明にしたいときは 1.0 前後に下げる。1行聞いてから決める。範囲の外や数でない値は、何も作らずに止まる。Gemini には使えない。
   - 声（名前/スタイル）と番号、速さ、抑揚、日付、そのキャラクターの規約の URL と確かめた日（`terms`、`termsChecked`）が `project.json` の `models` に残る（作り直すときに同じ読み方を選べる）。読みの辞書を使ったときは、その語数（`readings`）も残る。
   - 各行が `audio/narration/<id>.wav` になり、`timeline.json` の `audio` と `duration` が埋まる。
   - 合成の後、時刻表を新しい声の長さに自動で合わせ直す（伸ばしも縮めもする。下の「声の長さが変わったとき」）。シーンごとの長さの表（`s01: 10.467 → 10.492 秒（+0.025）`）が出るので、総尺が変わったら利用者に伝える。
   - クレジット「VOICEVOX:<キャラクター名>」が `project.json` の `credits` に入る。納品の確認ページの権利の一覧に、この表記とスタイル・速さ・抑揚、規約の URL と要点が載るほか、多くのキャラクターは動画の説明欄などへの表記が条件なので、そのことを利用者に伝える。
6. **残った「注意」を直す。** 合わせ直しで直せなかったこと（読み切れない文字、BGM の確かめ直し）は「注意: …」と出る。出た所だけ直して `node "<プラグイン>/scripts/timeline.mjs" validate "<制作>"` を通す。

原稿や声、速さを変えたら、`narration.mjs` をもう一度実行する。声・速さ・抑揚・読み上げる文（読みの辞書を当てた後）が前と同じ行は、前の声を使い回し、変わった行だけを作る（Gemini は同じ文でも毎回読み方が変わるので、直していない行の声は変えない。了承に見せる回数も作る行の数になる）。声や速さを変えると全行が変わるので全行を作る。そのときの時刻表から合わせ直す（前に伸ばしたシーンも、声が短くなれば縮む）。直していない行も別の読み方で作り直したいときは `--force` を付ける（Gemini なら全行ぶん有料）。

### 声の長さが変わったとき（時刻の自動の合わせ直し）

`narration.mjs` は、合成の前の時刻表（初めての合成では、1 秒 5 文字の見積もりの長さ）と新しい声の長さから、シーンごとに前から順に組み直す。時刻を手で直す必要は無い。

| もの | 動き方 |
|---|---|
| ナレーションの行 | シーンの頭から最初の行までの間と、行と行の間は元のまま。ただし行の間は 0.5 秒以上あける（声は重ならない） |
| シーンの終わり | 最後の声の終わり + 元の余白（最後の声の終わりからシーンの終わりまで。0.5 秒より短ければ 0.5 秒）。シーンの終わりまで出る文字が、元は読み切れていたのに読み切れなくなるなら、その分延ばす。合成済みの声が元から次のカットへはみ出していた（J カット）シーンは延ばさず、カットを声の中の同じ所に置く。そのとき次のシーンの最初の行は、はみ出した声の終わり + 0.5 秒より前には始めない（後ろはその分ずれる） |
| 後ろのシーン | 前のシーンの変化の分だけずれる。声の無いシーンは長さを変えない |
| テロップ・ラベル | 声の中にある時刻は声に比例して動く（話している語に合わせた文字は語に付いて動く）。声の外の時刻は、直前の基準（シーンの頭、行の終わり）からの秒を保つ。シーンの終わりまで出るものは新しい終わりまで。シーンの絵は `ms.time` でテキストの時刻から動くので、絵も付いて動く |
| ナレーションと同じ文の字幕 | その声の始まりまでに出て、声の終わり + 0.5 秒まで出る。同じシーンの字幕どうしは重ねない（前の字幕は次の字幕の始まりで切る。行が隙間なく続いていた所も、行の間を 0.5 秒あけるので両方が守れる） |
| 効果音・ポスター | テロップと同じ写し方（声の中は比例、声の外は直前の基準からの秒を保つ） |
| BGM | `offset` と `repeat` は変えない |

合わせ直しの後、次のことを確かめる。

- **読み切れない文字。** 声が縮むと、声の中だけに出る文字も縮む。「注意: テキスト t22 の表示が 2.8 秒しかありません（読み切るには 2.9 秒以上）」と出たら、その文字の終わりを延ばすか、次の文字への切り替えを遅らせる。
- **BGM。** 総尺やカットの境目が変わると「注意: 声に合わせてカットの長さが変わりました … BGM の offset と repeat はそのままです」と出る。拍とカットの境目（下の「テンポに場面の切り替えを揃える」）、締めの和音とロゴの時刻（`bgm.offset` と `bgm.repeat`）を確かめ直す。カットの境目が元は拍に乗っていたなら「拍に乗っていましたが … 外れました」とも出る。拍へは自動で丸めないので、拍に乗せ直すなら、シーンの終わりを次の拍の頭まで延ばす（縮めると声や文字が切れることがある）。動画が短くなって締めの和音がロゴより後ろへずれたら、`repeat` を縮めるか外し、`offset` を拍の単位で動かして合わせる。

## 3. Gemini を使うとき（読み上げ・BGM 共通）

### 注意事項を示して、了承を記録する

Gemini を選んだ時点で、次の手順を飛ばさない。

1. 注意事項の正確な文面を出す。次を `--yes` なしで実行すると、文面が表示されて止まる（何も記録しない）。

   ```
   node "<プラグイン>/scripts/gemini.mjs" consent "<制作>"
   ```

2. 表示された箇条書きを、**言い換えずにそのまま**利用者に示し、「この内容を了承のうえで Gemini を使いますか」と聞く。外部 API に原稿や曲の指示を送るかどうかは、利用者の責任で決めるものだと伝える。
3. 利用者本人がはっきり了承したときだけ、その言葉をそのまま `--quote` に入れて記録する。

   ```
   node "<プラグイン>/scripts/gemini.mjs" consent "<制作>" --yes --quote "<利用者の言葉>"
   ```

   `project.json` の `externalApiConsent` に日時と利用者の言葉と文面が残る。記録が無いと、読み上げも BGM も動かない。記録があっても、有料の実行のたびに了承を取る（[SKILL.md の「止め時」](../SKILL.md) の「有料の API」）。

### API キー

- キーは Google AI Studio（https://aistudio.google.com/apikey ）で作る。**課金設定済みのプロジェクト**のキーを使う（無料枠では、送った内容が製品改善に使われ、人が読むこともある）。
- キーは環境変数 `GEMINI_API_KEY` に、利用者自身に設定してもらう（Windows は `setx GEMINI_API_KEY "<キー>"` のあと Claude Code を開き直す。Mac は `~/.zshrc` に `export GEMINI_API_KEY=<キー>`）。**キーをチャットに貼ってもらわない。制作フォルダに書かない。**
- 設定できたかは `doctor.mjs` の `gemini.keySet` で確かめる。
- モデル名と料金は変わることがある。使う前に公式の情報（https://ai.google.dev/gemini-api/docs/speech-generation 、https://ai.google.dev/gemini-api/docs/music-generation ）で確かめる。

### 読み上げ

```
node "<プラグイン>/scripts/narration.mjs" "<制作>" --engine gemini --voice Kore
```

声は定義済みの名前（`Kore` など30種）から選ぶ。`audio/readings.json` の読みの辞書（VOICEVOX の手順4）も当たる（Gemini には読みを確かめる道具が無いので、作った声を聞いて読み違いを探す）。合成の後の時刻の合わせ直しと「注意」も VOICEVOX と同じ（上の手順5・6）。使ったモデル（`gemini-3.8-flash-tts`）と声の名前と日付が `project.json` の `models` に残る。実行のたびに全行を作り、文字量に応じて費用がかかる。`--approved` は、出た回数と目的に利用者が了承した後にだけ付ける（[SKILL.md の「止め時」](../SKILL.md) の「有料の API」）。

## 4. BGM

### Gemini（Lyria）で作る

```
node "<プラグイン>/scripts/gemini.mjs" bgm "<制作>" --prompt "<プロンプト>" --seconds <総尺+2>
```

プロンプトは英語で、次の型で書く（歌なしの指示は自動で足される）。テンポは「数字 bpm」で書く（`timeline.json` の `bgm.bpm` に読み取られる）。

```
Genre: <minimal electronic / warm acoustic / corporate ambient など>
Mood: <confident, calm, forward-looking など。ブリーフィングの調子から>
Tempo: <100> bpm
Instruments: <soft synth pads, plucked piano, light percussion など>
Structure: <quiet intro for 4 s, gradual build until 40 s, clear peak at 45 s, gentle ending>
Avoid: <heavy drums, vocals>
```

- 特定のアーティスト名、既存の曲名、歌詞を書かない。
- 1曲 $0.08 かかる。作るたびに利用者の了承を得てから `--approved` を付ける（[SKILL.md の「止め時」](../SKILL.md) の「有料の API」）。
- `audio/bgm.wav` に入り、`timeline.json` の `bgm` が `{file, bpm, gain: -18, source: "lyria-3.5", license}` になる。使ったプロンプトは `project.json` の `models` に残る。
- **できた曲の長さとテンポを確かめる。** 曲は頼んだ秒数より長く（2分前後）できることがあり、プロンプトの構成（「14 秒で山」など）も守られるとは限らない。テンポも指定と少しずれることがある。`timeline.json` の `bpm` はプロンプトから読んだ値なので、実際の拍とは限らない。曲を聞いて（音の大きさの変わり目、拍の頭）、使いたい区間を決める。
- **曲の途中から使うときは、`bgm.offset` に秒を書く**（例: `"offset": 2.07`）。書き出しの時に、曲のその位置から動画の長さだけ使い、終わりの 1.5 秒で絞る。区間の頭は拍の頭（できれば小節の頭）にそろえる。offset は 0 以上の数（文字の "2.07" は不可）で、曲の長さより短くする（外れると書き出しが理由を添えて止まる）。
- **曲が動画より短いときは、`bgm.repeat` で曲の途中の区間をくり返して伸ばす**（例: `"repeat": {"from": 42.692, "to": 117.358, "times": 2}`）。曲は頼んだ秒数に関係なく 2〜3 分でできることが多く、それより長い動画では曲が途中で終わる（書き出しの時に「注意: BGM は動画の … 秒で終わり」と出て、くり返しがあれば足りる `times` の値も出る）。書き出しの時に、曲を `to` まで鳴らしてから `from` へ戻って続けることを `times` 回（省くと 1 回）くり返し、終わりの部分（締めの和音）はそのまま残る（伸びる秒数は `(to - from) × times`）。つなぎ目は `to` の手前 0.08 秒と `from` の手前 0.08 秒を重ね、重ね終えた所がちょうど `from` になる（`to` の頭の音は鳴らさず、拍の頭の音を2つ重ねない）。そのため `from` は 0.08 秒以上、`to` は曲の長さより前にする。`from` と `to` は、同じ拍の位置（小節の頭、できれば 4 小節や 8 小節の区切り）にそろえ、`to - from` は小節の長さのちょうど整数倍にする（点検はしない。`bpm` は当てにならないので、拍は音を聞くか波形で確かめる）。つなぎ目の前後で鳴っている楽器がそろう区間を選ぶ。締めの和音を動画の決めの時刻（ロゴなど）に置きたいときは、`(to - from) × times` と `offset` で合わせる。`offset` は、くり返した後の曲に対して効く。
- **テンポがずれていたら、曲を伸び縮みさせずに、映像の時刻を実際の拍に合わせる**（`bgm.bpm` も実際の値に直す）。曲を伸び縮みさせると波形の位相が崩れ、AAC にしたときに頂点が 2〜3 dB 上がって、音量の点検（-1 dBTP）を通らなくなる。
- 映像の時刻を拍に合わせるときは、`timeline.json` のシーンとテキストと効果音の時刻を直す。シーンの入場を `ms.time(id)` から決めておけば（[composition.md](composition.md)）、HTML は直さなくてよい。

### 持ち込みの音源

1. 音源の出どころと、動画で使ってよい条件（商用、クレジット、改変）を利用者が確かめたことを確認する。確かめていなければ、使わない。
2. ファイルを `audio/` に置き、`timeline.json` の `bgm` を手で書く: `{"file": "audio/<名前>.wav", "bpm": <分かれば数>, "gain": -18, "source": "持ち込み", "license": "<利用者が確かめた条件。クレジット表記も>"}`。
3. `project.json` の `settings.audio.bgm` を `file` にする。

### テンポに場面の切り替えを揃える

BGM の `bpm` があれば、シーンの境目と大きな動きを拍に乗せる（1拍 = 60 ÷ bpm 秒）。数値の決め方は [motion-rules.md](motion-rules.md) の「ビートグリッド」。境目を動かしたら `timeline.mjs validate` を通す。

## 5. 効果音

- 合わせる映像のイベント（見出しが着地する、カードが置かれる、画面が切り替わる）の時刻を `sfx[].t` に書く。1フレーム後への移動は自動。
- 鳴らしすぎない。目安は大きな動き1つに1音。同じ音を続けて3回以上鳴らさない。style.md の案D（効果音を多めに）を選んだときだけは、図形の着地ごとに1音鳴らしてよい（1つの動きに1音は変わらない）。
- 鳴らす位置は、段階5で動きが固まってから見直す。

## 6. 音量と記録

- 音量は書き出しの時（`assemble.mjs`）に自動でそろう（-14 LUFS、ピーク -1 dBTP 以下）。ただし効果音だけ（ナレーションも BGM も無い）の動画は、-14 LUFS にはそろえない（効果音を -14 LUFS まで持ち上げると耳に刺さる）。代わりに、効果音どうしの釣り合いは `gain` のまま、全体を同じだけ上げ下げして、いちばん大きい音の頂点を -3 dBFS にそろえる。ただし統合の音量は -16 LUFS を超えない（効果音を詰めて鳴らすと、頂点をそろえただけで大きくなりすぎるため。そのときは -16 LUFS まで下げる）。そのため効果音だけの動画では、`gain` は音どうしの大きさの比べ合いとして書けばよく、目安の -6〜-14 のままで小さく聞こえることはない。自動点検もこの場合は、-14 LUFS 以下とピーク -1 dBTP 以下だけを見る。途中で音だけ聞きたいときは `node "<プラグイン>/scripts/mix.mjs" "<制作>"` で `audio/master.wav` を作れる。
- 権利一覧（`reviews/rights.md`）は納品の前に、`project.json` の `credits` と `models`、`timeline.json` の `bgm.license` から作る（[export.md](export.md)）。

終わったら `node "<プラグイン>/scripts/project.mjs" stage "<制作>" build` で段階5へ。
