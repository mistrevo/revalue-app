# 作例: 製品マニュアル

こういう依頼なら、こう組むとよい一例。決まりではないので、使う人の意図に合わせて変えてよい。

## どんな依頼の例か

製品の操作を、見た人がそのとおりに手を動かせるように見せたい。社内ツールの使い方、お客様向けの操作説明、ヘルプページの添え物に使う。わくわくより「迷わない」が目的。

## 組み合わせた構成の型

- [手順](../structures.md) だけで組む。
- 1本1テーマにする。「ログインして、設定を変えて、書き出す」なら3本に分け、連作にする。

## 尺と fps の目安

- 尺: 1本 30〜180 秒。90 秒くらいが多い。1本で扱う手順は 3〜7 つまで。長いものは章ごとの連作にし、1本は 5 分以内（目安は 3 分以内）。
- fps: 30。

## 場面の並びの例

手順5つ、90 秒の場合:

| 秒 | 段 | 中身 |
|---|---|---|
| 0〜6 | ゴール | この動画でできるようになることと、完成後の画面 |
| 6〜14 | 準備 | 前提（必要な権限、開く画面、版）。無ければ省く |
| 14〜80 | 手順 1〜5 | 1手順 10〜15 秒。「番号と一文 → 操作する場所に寄る → 操作 → 結果の画面」の順 |
| 80〜90 | 確認と次 | 結果の確かめ方。連作なら次の章の名前。最後の 1.5 秒は止める |

- 1手順の中の目安: 番号と一文の入場 0〜1.5 秒、寄り 1.5〜2.3 秒（`ms.ease.inOutCubic` で 800ms）、操作 2.3〜6 秒、結果 6〜10 秒以上。

## 見せ場の作り方

- 手順の番号と、そのとき見えている画面を必ず対応させる。番号とテロップは毎回同じ場所（画面の左上か右上）に出す。
- 操作箇所の示し方を動画全体で1つにそろえる（例: アクセント色の 4px の角丸の枠と、周りを 25〜30% 暗く）。暗くした場所にある文字のコントラストは自動点検の `contrast` で見られるので、暗くする量を周りの文字が読める所にする。
- マウスの動きは `ms.ease.inOutCubic` で 400〜700ms。クリックは 100〜150ms の小さな縮み（0.92 倍）と `click` の効果音（1 フレーム後）。
- 画面とボタンの表記は [content-rules.md](../content-rules.md) の「製品画面」に従う。マニュアルは音なしで見られることが多いので、字幕を勧める。
- 同じ製品の連作は、色、番号の位置、操作箇所の示し方、締めの形を全章でそろえる（`style.md` を共有する）。

## よくある失敗

- 1本に複数のテーマを詰め、5 分を超える。
- 画面録画を等倍のまま流し、ボタンが小さくて読めない。
- 古い版の画面で作り、今の画面と食い違う。
- 結果の画面をすぐに切り替え、成功したかが分からない。
