# 段階5 シーンを描く（約束事）

シーンは1つにつき1枚の HTML（`src/scenes/<id>.html`）。書き出し・静止画・点検の道具が、そのページを開いて時刻を指定し、撮る。ここに書く約束を守れば、同じ時刻からは必ず同じ画が出る。動きの数値は [motion-rules.md](motion-rules.md)、避ける癖は [banned.md](banned.md)、見た目はその動画の `style.md` に従う。

## 1. 作り始め

- `<プラグイン>/templates/scene.html` を `src/scenes/<id>.html` に写して始める（段階3の下描きがあれば、それに動きを足す）。
- ランタイム（`<プラグイン>/scripts/runtime/ms-runtime.js`）は、道具がページの読み込み前に注入する。**`<script src>` でランタイムを読まない。** シーンにプラグインの場所を書かない。
- 書体は `../../assets/fonts/fonts.css` を読む（ひな形に最初からある）。外部（http/https）のものは何も読まない。

## 2. ランタイムの API

| 名前 | 中身 |
|---|---|
| `ms.scene((t) => { ... })` | 描画の関数を登録する。`t` はシーン内の時刻（秒、シーンの先頭が 0） |
| `ms.text(id)` | `timeline.json` の文字（その id のテキスト）。無い id は例外 |
| `ms.time(id)` | そのテキストの `{start, end}`（シーン内の秒）。文字の入場をここから始めると、`timeline.json` の時刻を直したとき（拍に合わせ直す、部分修正）に動きも一緒に動く。無い id は例外 |
| `ms.ease.outExpo`、`ms.ease.outQuint`、`ms.ease.inOutCubic`、`ms.ease.inQuart`、`ms.ease.outBack` | イージング（0〜1 を受けて 0〜1 を返す）。使い分けは motion-rules.md |
| `ms.spring({damping, stiffness})(t)` | 0 から 1 へ向かうばね。値は motion-rules.md の「ばね」 |
| `ms.rand()` | 0 以上 1 未満の乱数。描くたびに seed から始め直す |
| `ms.ratio`、`ms.width`、`ms.height` | いまの比率（`"16:9"` など）と、CSS 上の幅と高さ（px） |
| `ms.duration` | シーンの長さ（秒） |

`<html>` には `data-ratio="16:9"` などが自動で付く。

## 3. 文字は data-ms-text だけで出す

- 画面に出る文字は、すべて `<div data-ms-text="t01"></div>` のように、`timeline.json` の `texts` の id で置く。ランタイムが正本の文字を流し込む。
- **HTML や JS に文字を直書きしない。** 字幕（`subtitle`）、数字、ラベル、ボタンの文字も同じ。直書きは自動点検の `hardcoded-text`、正本との食い違いは `text-mismatch` で止まる。
- 一語だけ色を変えたいなど、1つのテキストの一部を飾りたいときは、その部分を別のテキスト（別の id）にして `timeline.json` に足し、並べて置く。
- テロップの背景の箱（行、札、カード）は、文字の要素を箱の中に入れて組む（`<div class="row"><div data-ms-text="t05"></div></div>`）。自動点検の `overflow` は、文字のいちばん近い、背景（色か画像）・枠線・影のある祖先の箱から、表示のあいだずっとはみ出したままの文字を指摘する。箱と文字を別々に置いて重ねただけだと、点検には箱が見えない。文字より小さい飾りの形を後ろに置くときは、逆に文字の祖先にしない（祖先でない形は問わない）。
- 語や文節ごとの span に分けて順に出す見出しでも、切れたまま・はみ出したままは span ごとに見る。先に出た語が収まっていても、あとから出る行が札で切れたままなら `overflow` になる。マスクの中で語を入れ替える枠（回る単語）や、流れる端末の画面のように、一部の文字を最後まで出さない箱は `data-ms-scroll` にする（付けないと、一度も全部見えなかった文字が `overflow` になる）。
- **図形・色の面・画像を、文字の上（重なり順で手前）に重ねたままにしない。** 自動点検の `cover` は、文字が見えている（不透明度 0.5 以上の）あいだに、文字でない塗りのある要素（不透明度 0.5 以上の背景の色か画像がある要素、SVG の形、`img`）が字の帯（行の箱の上下の中央 7 割）の 10% を超えて手前に重なり、それが 0.2 秒以上続くと指摘する。文字の後ろ（重なり順で下）を通る形、0.2 秒より短く横切る形、行の上下の余白だけにかかる下線、`mix-blend-mode` が `normal` でない形（乗算の蛍光ペンなど、字が透ける形）は問わない（後ろの形は `contrast` が見る）。`data-ms-scroll` の箱の中の文字は見ない。
- **限界: 9 割以上を覆う形は問わない。** 文字の 9 割以上を覆う板は、文字を隠しておいて出す演出とみなして `cover` に数えない。表示のあいだずっと覆っていれば「一度も表示されていない」と出るが、一度見せた後で形が文字をほとんど覆い隠しても、点検では見つからない（段階5の批評でフレームを見る）。
- 転換の拭き取りのように、わざと 0.2 秒以上かけて文字の上を通す形には `data-ms-wipe` を付ける。付けた要素とその中は、**そのシーンのあいだずっと** `cover` に数えない（転換の時間だけではない）。文字の読める時間が減るので、転換の形にだけ付け、ほかの時間に文字の上に止まる形には付けない。
- 画面の操作を見せるカーソルや指の絵も、文字の手前に 0.2 秒以上止まると `cover` に数える。小さなボタンの文字の上で止めず、文字の横や端に止める。
- 字幕はシーンの中で描く（後から動画に焼き込まない）。字幕の帯（16:9 なら画面の下 10%、9:16 なら下から 20〜30%。比率ごとの値は motion-rules.md の「比率ごとの下の安全域」）に置き、ほかの文字はこの帯に入れない（`safe-area`）。9:16 の下 20% には、字幕も含めてどの文字も置かない。
- 文字の形の決まり（大きさの下限、端の余白）は motion-rules.md の「画面の安全域と最小の文字サイズ」。

### 意図した演出の宣言（data-ms-intent）

`style.md` の「既定から外すこと」で決めた演出のうち、特定の要素だけで外すものは、その要素に `data-ms-intent` を付ける。値は点検の名前を空白で区切って並べる。

```html
<!-- 背景に薄く大きく敷く社名（読ませない飾り）。コントラストとはみ出しを外す -->
<div class="bg-word" data-ms-intent="contrast overflow"><span data-ms-text="t09"></span></div>
```

- 付けた要素と、その中の要素に効く。`<body>` に付けると、そのシーンのすべての指摘に効く（つなぎ目の `blank` もこれで外す）。
- 書ける名前は `overflow`、`safe-area`、`overlap`、`cover`、`contrast`、`blank`（`blank` は `<body>` に書く）。`cover` は、文字の側にも、覆う形の側にも付けられる。
- `flash`、`hold`、`narration`、`loudness`、`loop` は、完成版の動画や台本の時刻表から見る点検で、要素とは結びつかない。要素には書かず、`project.mjs intent` で宣言する（シーンを絞るなら `--scenes`）。
- 知らない名前、上の5つ、正しく作るための点検（`text-mismatch`、`hardcoded-text`、`determinism`、`media`、描画のエラー）の名前を書くと、点検が描画のエラーとして知らせる。
- 当たった指摘は「意図どおり」と出て、合否と止め時に数えない。動画全体やシーン単位で外すなら、要素に付けずに `project.mjs intent` で宣言する（SKILL.md の「既定から外すこと」）。
- 意図していない崩れを隠すために付けない。付けるのは `style.md` に書いた演出の要素だけ。

## 4. 決定論

- 文字の入場の時刻は、なるべく `ms.time(id).start` から決める（`const a = ms.time('t03').start; prog(t, a, 0.5)`）。HTML に秒を直書きすると、`timeline.json` の時刻だけを直したときに、文字の時刻と動きがずれる。
- 動きは `ms.scene` の関数の中で `t` から決めるか、CSS の `@keyframes` で書く（シーンの先頭で始まったものとして時刻がそろう。開始のずれは `animation-delay`）。前のフレームの値を覚えて足し込まない。
- `setTimeout` と `setInterval` は読み込みの間だけ使える。描き始めた後に呼ぶと例外になる。待ちは `t` の比較で書く。
- CSS の `transition` は効かない（ランタイムが止める）。
- `Date`、`performance.now` はシーンの時刻を返す固定の時計になる。頼らず `t` を使う。`requestAnimationFrame` で回し続けない。
- `ms.rand()`（と `Math.random`）は描くたびに seed から始め直す。呼ぶ回数と順番を毎フレーム同じにする（条件によって呼んだり呼ばなかったりしない）。
- GSAP を使うときは、`paused: true` のタイムラインを作り、描画の関数の中で `tl.seek(t)` を呼ぶ。
- 同じ時刻を2回描いて違えば、自動点検の `determinism` で見つかる。

## 5. 比率ごとに組み直す

- 既定のレイアウトを 16:9 で書き、ほかの比率は `[data-ratio="9:16"] .title { ... }` のように比率ごとの CSS で組み直す。切り抜きで作らない。
- 位置や大きさを JS で決めるなら `ms.width`、`ms.height`、`ms.ratio` を使う。
- 縦型の注意（下 20% と右端に SNS のボタンが重なる）は motion-rules.md の「比率ごとの下の安全域」。

## 6. 素材の参照

- 素材は制作フォルダの `assets/` に置き、シーンからは相対パスで読む（`<img src="../../assets/logo.svg">`）。読み込めない画像があると、書き出しはその名前を出して止まる。
- **ロゴは渡されたファイルをそのまま置く。** 描き直さない、色を変えない、変形しない、効果をかけない。動かすのはロゴの外側（マスク、位置、不透明度、拡大率）だけ。
- 製品画面は、渡されたスクリーンショットを `<img>` で置く。もっともらしい画面を描かない。
- 動画の素材（画面録画）は `<video>` で置かない（時刻をそろえられない）。必要な場面の静止画を取り出して `<img>` で並べ、`t` で切り替える。取り出しは ffmpeg で行う（場所は `doctor.mjs --json` の `ffmpeg.path`）: `"<ffmpeg>" -ss 12.0 -to 18.5 -i "<制作>/assets/rec.mp4" -vf fps=10 "<制作>/assets/rec/%04d.png"`（`-ss` と `-to` で、使う区間の始まりと終わりの秒を指定し、その区間だけを取り出す。書き出し先のフォルダは先に作っておく）。枚数は少なく（数十枚まで）し、全部を最初から読み込んでおき、表示だけを切り替える。

## 7. 1つのシーンの確かめ方

```
node "<プラグイン>/scripts/frames.mjs" "<制作>" at <秒> <秒>
node "<プラグイン>/scripts/render.mjs" "<制作>" --scene s03
```

`frames.mjs at` は動画の先頭からの秒で撮る（ラフの画質）。`render.mjs --scene` はそのシーンだけを MP4 にする（入力が前回と同じなら描き直さない）。撮った画は必ず画像として開いて見る。

## 8. シーンをサブエージェントに分けて描くとき

シーンの数が多いときは、シーンごとにサブエージェントへ任せてよい。渡すものは次の形にそろえる。

1. 書くファイル: `<制作>/src/scenes/<id>.html` の絶対パス（このファイルだけを書く）
2. シーンの文字と時刻: `node "<プラグイン>/scripts/timeline.mjs" slice "<制作>" <id>` の出力（シーン内の時刻にした texts、narration、sfx）
3. `storyboard.md` のそのカットの節（存在理由、入口と出口、画）と、前後のカットの出口・入口
4. 読ませる文書の絶対パス: この composition.md、`style.md`（禁止の節と、既定から外すことの節も含む）、motion-rules.md、banned.md、content-rules.md、`<プラグイン>/templates/scene.html`
5. 使ってよい素材: `assets/` のファイル名と、それぞれの使いどころ
6. 終わりの条件: 「`frames.mjs at` でシーンの入場直後・中央・退場直前を撮り、画像を見て直してから返す。書き出し（render、assemble、check）は走らせない」

**同じ制作フォルダで書き出し・点検を並列に走らせない。** `render.mjs`、`assemble.mjs`、`check.mjs` は、全員の HTML がそろった後に、メインの会話が1つずつ実行する。

## 9. カットのつなぎ目

- **カットの最初のコマだけを空にして、次のコマで一気に出さない。** 前のカットの最後のコマに絵があり、次のカットの最初のコマだけが空で、2コマ目で絵がぱっと出そろうと、つなぎ目の1コマだけ画面が空になり、ちらついて見える（60fps の1コマでも気づく人がいる）。入場の始まりが 0 秒より少し後ろにずれている、0 秒の値だけ別の扱いになっている、などで起きる。自動点検の `blank` は、カットの最初のコマで背景でない画素が 0.2% 以下、前のカットの最後のコマに 1% 以上の絵があり、空のコマのすぐ後のコマ（完成版の fps で見る。60fps では 2コマの穴も数える）に 1% 以上の絵があって、その濃さと広さ（最初のコマからの色の差の増え）が 0.1 秒のコマの 8 割以上にもう達しているときに指摘する。
- 何も無い地から、フェードや拭き取り、線を描くようにだんだん出る入場（0.4 秒の outExpo のフェードのような速い入場でも、すぐ後のコマではまだ出そろっていない）は、ふつうのカットの切り替えなので問わない。
- 指摘されたときの直し方は、最初のコマから何かを置くこと。前のカットの形を引き継いで始める、入場を少し進んだところから始める（`prog(t, -0.05, d)` のように 0 秒より前に始める）、地の上に図形や色の面を先に置く、のどれか。
- わざと空の間を置くときは 0.1 秒より長くする（点検では問わない。段階5の批評で、間が意図どおりかを見る）。
