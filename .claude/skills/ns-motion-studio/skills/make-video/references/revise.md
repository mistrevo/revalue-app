# 指摘の受け取り方と、段階8 部分修正

どの関門でも、指摘はこの手順で受け、記録し、直し、直したことを次の確認ページで見せる。納品の後の直し（段階8）も同じ手順で、直したシーンだけを書き出し直す。

## 1. 指摘を記録する

指摘は2つの形で来る。

- **確認ページのコピー文**: 1行目が `[ns-motion-studio 指摘] <題名> / <関門>`、続く行が `カット3（0:05〜0:08）：テロップの『製品』を『サービス』に` や `全体：BGM をもう少し静かに`。
- **チャットの自由な文**: 「カット3のテロップを〜」「0:12 あたりの文字が〜」など。

どちらも、受け取った文を**そのまま** `<制作>/reviews/feedback-in.txt` に書き（毎回上書きでよい）、読んで記録する。

```
node "<プラグイン>/scripts/feedback.mjs" log "<制作>" "<制作>/reviews/feedback-in.txt" --gate rough
```

`--gate` は、いま確認してもらっている関門（`briefing`、`style`、`storyboard`、`plan`、`rough`、`deliver`）。出力は JSON。

```json
{
  "logged": [ { "index": 4, "cut": 3, "text": "テロップの『製品』を『サービス』に" } ],
  "unresolved": [ "なんとなく暗い" ],
  "duplicates": []
}
```

- `logged` は記録した指摘。`index` は後で「直した」と書くときの番号。`cut` が null なら全体への指摘。
- `duplicates` は、記録済みでまだ直していない指摘と同じ文（貼り直したもの）。記録しない。二度直さない。
- 読み取れる行: 「カット3」「cut 3」、行頭の「#3」（行の途中の `#3` や `#333333` のような色は読まない）、「0:12」のような時刻（そのカットに割り当てる）、「全体：」で始まる行。
- `reviews/feedback-log.json` に残り、次の確認ページの冒頭に「前回の指摘と対応」として出る。

## 2. 読めなかった行は聞き返す

`unresolved` の行は記録されていない。**推測で直さない。** 行をそのまま引用して聞き返す。

> 「なんとなく暗い」は、どのカットのことでしょうか。全体のことでしたら「全体」とお知らせください。

返事が来たら、カットを補った形（`カット2：なんとなく暗い`）で `feedback-in.txt` に書き、もう一度 `feedback.mjs log` で記録する。

## 3. 直す前に決めること

- **どのシーンか。** カット番号は `timeline.json` の `scenes` の並び順（カット3 は3番目のシーン）。
- **感覚の言葉は数値に訳す。** 「もたつく」「ポップに」「AIっぽい」は [sense-to-number.md](sense-to-number.md) で、何をどれだけ変えるかに訳す。1回の直しで変える軸は2つまで。
- **事実に関わる指摘は出どころを確かめる。** 「ここに導入社数を入れて」のように新しい数値や社名が要るときは、実際の数値と出典を渡してもらう。作らない。
- **関門を戻る必要があるか。** 文字の直しは関門2（サンプルは構成の確認）で確定した内容を変えるので、直した文字を確認ページで見せて確かめてもらう（お試しとサンプルで、納品の後なら納品のページ。サンプルで書き出しの前なら構成の確認のページ）。構成（ビートの増減、順番）が変わるなら、段階3に戻る（`project.mjs stage "<制作>" storyboard`）。

## 4. 直す

指摘されたところだけを直す。ほかのシーンを「ついでに」直さない。

| 指摘の中身 | 直す場所 |
|---|---|
| テロップ・字幕・ナレーションの文字 | `timeline.json` の `texts` か `narration` の `text` だけ（シーンの HTML に文字を書かない） |
| 見た目・動き | そのシーンの `src/scenes/<id>.html` だけ |
| 時間（長さ、出るタイミング） | `timeline.json` の時刻。シーンの長さを変えると、後ろのシーンがすべてずれる。ずれた幅がコマの長さの倍数なら（30fps・60fps なら 0.1 秒刻みの長さの変更なら）、後ろのシーンは描き直さない。そうでなければ後ろのシーンも描き直しになる（書き出しの時間が延びることを伝える） |
| ナレーションの原稿・声・速さ | `timeline.json` を直した後、`narration.mjs` を実行し直す（直した行だけを作り、ほかの行は前の声を使い回す。声や速さを変えたときは全行を作る。Gemini なら作る行の数だけ有料。回数と目的を伝えて了承を得てから `--approved` を付ける。[SKILL.md の「止め時」](../SKILL.md) の「有料の API」）。テロップ・字幕・効果音・後ろのシーンの時刻は、新しい声の長さに自動で合わせ直される（短くなれば縮む。[audio.md](audio.md) の「声の長さが変わったとき」）。出た長さの表で総尺の変化を伝え、「注意」が出た所（読み切れない文字、BGM の拍と締め）だけを直す。読み違いは `audio/readings.json` に足して作り直す（辞書が当たる行だけが作り直しになる）。直していない行も読み直したいときは `--force` |
| 音量・BGM | `timeline.json` の `bgm.gain` や `sfx[].gain`、または BGM の作り直し（[audio.md](audio.md)） |

直したら、確かめてから見せる。

1. 文字や時刻を直したら `node "<プラグイン>/scripts/timeline.mjs" validate "<制作>"`
2. 自動点検を通す: `node "<プラグイン>/scripts/check.mjs" "<制作>"`（前回から変わっていないシーンは開き直さないので、直したシーンの分しか時間がかからない）。
3. 直した時刻を `node "<プラグイン>/scripts/frames.mjs" "<制作>" at <秒>…` で撮り（すべての比率で撮れる）、画像を見て、直ったことと、周りが崩れていないことを確かめる。比率が複数あるときは、どれも見る（文字を長くすると、狭い比率だけ箱の端に詰まることがある。自動点検は箱の外へのはみ出しは拾うが、余白の詰まりは拾わない）。

## 5. 書き出し直す

前回と入力が同じシーンは描き直さないので、直したシーン（と、コマの長さの倍数でない幅で時刻がずれたシーン）だけが書き出される。ただし `assets/` の素材を差し替えたり足したりすると、どのシーンが読むかを道具が見分けないので、全シーンを描き直す（時間を伝える）。

- 本番の関門3まで（ラフ版を見てもらっている間）: `node "<プラグイン>/scripts/assemble.mjs" "<制作>" --preset draft`
- 本番の関門3の後、お試しとサンプル、段階8: [export.md](export.md) の手順3（見込みを伝えてから全品質で書き出す。完成版の点検とコンタクトシートまで通る）。

## 6. 直したことを記録して見せる

指摘ごとに、何をどう直したかを、利用者が読んで分かる言葉で記録する。

```
node "<プラグイン>/scripts/feedback.mjs" resolve "<制作>" 4 --how "カット3 のテロップを『製品』から『サービス』に直しました"
```

その後、同じ関門の確認ページを作り直す（[SKILL.md の「関門での振る舞い」](../SKILL.md)）。冒頭の「前回の指摘と対応」に、対応済みと未対応が並ぶ。直せなかった指摘は、理由を添えてチャットで伝え、未対応のまま残す。

## 段階8（納品の後の部分修正）

1. `node "<プラグイン>/scripts/project.mjs" stage "<制作>" revise`
2. 上の1〜6の手順で直す。`--gate` は `deliver`。
3. 全品質で書き出し直し（[export.md](export.md) の手順3）、権利一覧と妥協点を更新する（素材や音を変えたとき）。
4. 納品のページを作り直して見てもらい（修正確認）、承認を得たら `node "<プラグイン>/scripts/project.mjs" approve "<制作>" deliver` で記録し直す。
