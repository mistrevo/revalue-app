# 段階6 仕上げと書き出し、段階7 納品

本番は関門3（ラフ版）の承認の後にだけ進む。お試しとサンプルは、自己点検が終わったら進む（ラフ版は作らない）。全品質の書き出しは時間がかかるので、始める前に必ず見込みを伝える。

## 段階6 仕上げと書き出し

### 1. 比率ごとの組み直しを確かめる

- `timeline.json` の `ratios` にある比率すべてで、各シーンが比率ごとの CSS で組み直されていること（切り抜きではないこと）を確かめる。
- 関門3の後で比率を足すことになったら、`timeline.json` の `ratios` に足し、段階5に戻ってその比率の自己点検と関門3を通す（お試しとサンプルは関門3が無いので、自己点検の後に全品質で書き出し、納品のページで見てもらう）。

### 2. 展示会向けの確かめ

ブリーフィングで展示会向けとしたときだけ行う。

- **音なしでも伝わるか。** コンタクトシートを、音が無いつもりで最初から見る。各ビートの言いたいことが画面の文字で読めるか。ナレーションだけが伝えている内容があれば、字幕（`subtitle`）を足すか、テロップに要点を出す（`timeline.json` を直し、文字の確認（本番は関門2、サンプルは構成の確認）を取り直す）。
- **ループ。** `timeline.json` の `loop` を true にする。最後のフレームが最初のフレームと同じ画になるよう、最後のシーンの出口を最初のシーンの入口にそろえる。継ぎ目は自動点検の `loop` が見る（シーンの段階では、最初と最後のコマで色が少しでも違う画素が全体の 0.01% を超えると指摘する。完成版の動画は圧縮で画素が揺らぐので、全体の PSNR が 45 dB 未満、または 8×8 の区画のどれかで色の差の平均が 6 を超えたときに指摘する。ロゴの細い線が1本残っていても引っかかる）。最初と最後のシーンは、継ぎ目の2つのコマが同じ質で圧縮されるように、書き出しが自動で圧縮の設定を変える（`loop` を true にすると、この2つのシーンは描き直しになる。ほかのシーンは描き直さない）。ループ版と本編は同じシーンの MP4 をつなぐので、この設定は本編の最初と最後のシーンにも効く。この設定は暗い無地や平らな地（紺の地など）に割く情報が減るので、全品質のコンタクトシートで、最初と最後のシーンの地に縞（色の段）が出ていないかを見る（ファイルの大きさと縞の出方は測っていない）。ループ版は音なしで書き出される。ループ版は本編の動画から音を除いた複製なので、ループが必要なときは本編も最後が最初の絵に戻って終わるように作る（締めのビートをそのように設計する）。

### 3. 見込みを伝えてから、全品質で書き出す

```
node "<プラグイン>/scripts/render.mjs" "<制作>" --preset final --estimate
```

「見込み: 5400 フレーム（全部を書き出す）、約 351 秒。assemble.mjs で音をまとめてつなぐなら、さらに約 41 秒（合わせて約 392 秒）」のように出る（前回のまま使えるシーンは数えない）。伝えるのは「合わせて」の秒数。「全品質の書き出しに、約7分かかります。その間パソコンは重くなります。始めてよいですか」と伝えて、了承を得てから書き出す。見込みは前回の計測から出すので、初めての全品質の書き出しでは外れやすい（目安として伝える）。

```
node "<プラグイン>/scripts/assemble.mjs" "<制作>" --preset final
```

- シーンを全品質で書き出し（前回と入力が同じシーンは描き直さない）、音をまとめて音量をそろえ（音の入力が前回と同じなら混ぜ直さない）、比率ごとに1本へつなぎ、続けて全品質のコンタクトシートを撮って完成版の自動点検を通す。
- できるもの（比率ごと）: 完成版 `out/<題名>_<比率>.mp4`、ポスター画像 `out/<題名>_<比率>_poster.png`、ループ版 `out/<題名>_<比率>_loop.mp4`（`loop` が true のとき）。比率は `16:9` なら `16x9`。
- 1つの比率だけ書き出すときは `--ratio 16:9` を付ける。
- 同じ制作フォルダで、書き出しを2つ同時に走らせない。
- 終了コード: 0 は書き出しも点検も問題なし、1 は書き出しの失敗か点検の指摘（出力の文で見分ける）、2 は点検の止め時、3 は書き出しが見込みを大きく超えて止まった（どちらも [SKILL.md の「止め時」](../SKILL.md)）。

### 4. 出力を読む

完成版の点検は、シーンの点検に加え、MP4 の尺・解像度・fps、点滅（毎秒3回以下）、音量（-14 LUFS ±1、ピーク -1 dBTP 以下。効果音だけの動画は -14 LUFS にそろえないので、-14 LUFS 以下とピーク -1 dBTP 以下だけ）、ループの継ぎ目を測る。`loop` が true なら、ループ版 `_loop.mp4` があること、本編より新しいこと（本編だけ書き出し直した残りでないこと）、尺・解像度・fps が本編と同じ規則に合うこと、音が入っていないこと、継ぎ目が合っていることも確かめる（どれも `media` か `loop`）。結果は `reviews/checks-final-<比率>.json`。問題があれば直して、手順3からやり直す（直したシーンだけが描き直される）。終了コード 2 は止め時（[SKILL.md の「止め時」](../SKILL.md)）。点検だけをやり直すときは `node "<プラグイン>/scripts/check.mjs" "<制作>" --stage final`（これも止め時の回数に数える）。

全品質のコンタクトシート `reviews/contact-<比率>-01.png`（長い動画は 32 コマごとに `-02.png`、`-03.png` … と分かれる）を、最後に一度、画像として開いて全体を見る。

### reviews/rights.md（使った素材と権利の一覧）

納品の確認ページに、そのまま表として出る。記録（`project.json` の `credits` と `models`、`timeline.json` の `bgm`、`assets/` と `assets/fonts/` の中身）から作り、記録に無いことは書き足さない。

```markdown
# 使った素材と権利

| 種類 | 素材 | 出どころ | 条件・クレジット |
|---|---|---|---|
| ロゴ | `assets/logo.svg` | ご提供 | 社のロゴの使い方の決まりに従う |
| 製品画面 | `assets/screen-01.png` ほか3点 | ご提供 | 社内で公開の確認済み（ブリーフィングより） |
| 書体 | Noto Sans JP（400、700） | Google Fonts | OFL（商用可） |
| ナレーションの声 | VOICEVOX:四国めたん（ノーマル、話す速さ 1.1、抑揚 1.2） | VOICEVOX | 動画の説明欄などに「VOICEVOX:四国めたん」と表記する。キャラクターの利用規約（https://zunko.jp/con_ongen_kiyaku.html、2026-10-23 に確認）: 商用・非商用とも可、申請不要。クレジット必須。政治・宗教、特定の個人・団体の批判や支持などに使わない |
| BGM | `audio/bgm.wav` | Gemini API（lyria-3.5、2026-10-21 生成） | Gemini API 生成物（SynthID 透かし入り）。AI 生成である表示は社内のルールに従う。補償は確認できていない |
| 効果音 | 8種 | このスキルがコードで合成 | 権利の確認は不要 |
```

- VOICEVOX の声は、`project.json` の `models` に残った規約の URL と確かめた日（`terms`、`termsChecked`）と、`voicevox.mjs` の `VOICEVOX_CHARACTERS` の要点（`note`）を書く。規約を読み直す必要はない（[audio.md](audio.md)）。
- Gemini を使ったときは、モデル名と生成日、透かしが入っていること、AI 生成の表示は社内ルールに従うことを書く。
- 持ち込みの音源は、利用者が確かめた条件（`bgm.license`）をそのまま書く。

### out/再現手順.md

後で作り直すときのための記録。

```markdown
# 再現手順: <題名>

- 制作フォルダ: <絶対パス>
- 作り方: ns-motion-studio の make-video スキル
- 正本: `timeline.json`（言葉と時間）、`src/scenes/`（描画）、`style.md`（見た目）
- 書き出し: `node "<プラグイン>/scripts/assemble.mjs" "<制作フォルダ>" --preset final`
- 音: <ナレーションの方法と声、BGM の出どころ>（`project.json` の `models` と `credits` も参照）
- 読みの辞書: `audio/readings.json`（<語数> 語。例: ffmpeg=エフエフエムペグ）。`narration.mjs` が読み上げの文にだけ当てる（無ければ「なし」と書く）
- 同じ入力からは同じ動画が出る（シーンは時刻だけから描く。乱数の seed は timeline.json の `seed`）
```

### 納品確認

1. `node "<プラグイン>/scripts/project.mjs" stage "<制作>" deliver` で段階7に入り、`node "<プラグイン>/scripts/review-page.mjs" "<制作>" deliver`
2. 利用者に、納品物の場所（絶対パス）と、残った妥協点があればその要点を伝える。お試しとサンプルでは、納品のページに要件のまとめ、仮に決めたこと、スタイル、既定から外したこと（お試しは絵コンテも）が出るので、そこも見てもらうよう伝え、本番用に仕上げたいときは言ってもらえば続きから作れることを添える。点滅を使ったときは、ページの注意を念のため伝える。VOICEVOX のクレジットなど、公開の時に利用者がすることがあれば、ここで念を押す。制作フォルダを git で管理しているなら、完成版の動画と音声（wav）は `.gitignore` で外してあり git に入らないので、別の場所に残すよう伝える。
3. 承認を得たら `node "<プラグイン>/scripts/project.mjs" approve "<制作>" deliver`。
4. 後から直したいところが出たら、段階8（[revise.md](revise.md)）へ。
