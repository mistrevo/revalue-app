# 何も言われないときに避ける癖

生成した動画が「AIが作った感じ」に見える原因は、だいたい決まっている。ここにある癖は、**何も言われないときには使わない**。使う人の意図があれば使ってよい（例: 「サイバーに」でネオンとグリッチ、「ポップに」で跳ねる動き）。使うと決めたら、その動画の `style.md` の「既定から外すこと」に書く（[style.md](style.md)）。

自己点検（描いたフレームを見る段階）では、この表を上から当てはめる。当たったら、その動画の `style.md` で使うと決めたものでなければ、その場で直す。

事実に関わる決まり（渡されていない画面、数値、社名を作らない、ロゴの扱い）は、表現の癖ではないので、ここではなく [content-rules.md](content-rules.md) にある。そちらは外せない。

---

## 1. 色と質感

| 癖 | 何も言われないときに避ける理由 | 代わりの既定 | 意図して使うときのこつ |
|---|---|---|---|
| 紫のグラデーション（青紫〜ピンク、紫〜水色の帯や背景） | 生成された画面の典型。ブランドと無関係に「それっぽさ」だけが出る | `style.md` のパレットだけを使う。グラデーションが要るなら、同じ色相の明度差（例: 紺から黒）で作る | ブランド色に紫があるときや、夜・未来の雰囲気を出したいときに。文字の裏は平らな面にして、コントラストを保つ |
| 意味のないグロー（文字や枠が光る） | 光が何も説明していない。圧縮で輪郭がにじむ | 光は状態の変化に結びつける（選ばれた、完了した、の瞬間だけ） | ネオン調なら、光は細く短く。読ませる文字は光らせず、飾りの線に光を持たせる |
| パーティクル（漂う光の粒、弾ける粒） | 画面を埋めるための飾りに見える。点滅の点検にも引っかかりやすい | 何も足さない。空いた面は余白として残す | 祝い・華やかさを出したいときに。粒は大きさと数を絞り、seed 付きの `ms.rand()` で決定論を守る |
| ガラス風（すりガラスの板、`backdrop-filter: blur`） | 背景の模様が透けて、文字の読みやすさとコントラストが不安定になる | 不透明な面にする。重なりは影の濃さで表す | 板の不透明度を上げ、文字の後ろの地をほぼ一色にする |
| レンズフレア、光の筋、意味のない画面揺れ | 映画の予告の真似。製品と関係がない | 使わない | 予告編風の演出を頼まれたときに。揺れは 1 回 0.3 秒以内、読ませる文字の出ている間は揺らさない |
| ネオン、サイバー風の線、ホログラム | 「未来っぽさ」の記号で、内容を語らない | 実際の画面や図で表す | 方向として選んだときは、1つの色相に絞ると安っぽくならない |

## 2. 動き

| 癖 | 何も言われないときに避ける理由 | 代わりの既定 | 意図して使うときのこつ |
|---|---|---|---|
| 全要素のフェードと浮き上がり（全部が同じ長さで、下から同じ距離だけ上がりながら現れる） | いちばん多い「テンプレートの動き」。階層がなく、全部が同じ重さに見える | 要素ごとに入り方を変える（主役はマスクの中から、補足は 0.96 → 1.00 の拡大、ラベルは不透明度だけ）。長さを3段階に散らす（`motion-rules.md` 3章・12章） | 静かで均一な印象をあえて出すなら、長さだけは散らす |
| 多用されるクロスフェード（毎回半透明の重なり） | 転換に意味がなく、2つの絵が濁って見える | 画面の物で転換を動機づける。クロスフェードは時間の経過を表すときだけ、1本に2回まで | 回想や夢のような柔らかさを出すときに |
| 常時ズーム（全カットがゆっくり寄り続ける、引き続ける） | 動きの意味が消え、見る人が酔う | 2% の寄りは、主な動きが止まって 1.5 秒を超えるカットだけ（`motion-rules.md` 9章） | ドキュメンタリー風の落ち着きを出すときに。寄りの速さは全カットでそろえる |
| 跳ねる UI（パネル、カード、ボタン、文字が弾んで止まる） | 子ども向けか、安いアプリの広告に見える | `ms.ease.outExpo` か、減衰比 0.78〜0.85 のばね（行き過ぎ 2% 未満。既定は stiffness 100・damping 16）。`ms.ease.outBack` は小さな印に1本で1〜2回まで | 「ポップに」と言われたら使う。跳ねるのは主役だけにし、読ませる文字は止まってから読ませる |
| 直線での動き出し・止まり | 機械的で、重さがない | 入場は `ms.ease.outExpo`、退場は `ms.ease.inQuart`。直線は始まりも終わりも映らない連続の動きだけ | 機械らしさ・デジタルらしさを出すときに |
| 読ませている文字を動かす（漂う、揺れる、回る） | 読めない | 文字は止めて読ませる。動かすのは入場と退場のときだけ | 読ませない飾りの文字（背景の大きな文字など）なら動かしてよい |
| 意味のない 3D 回転 | 「動かすために動かしている」 | 回転は 2〜4 度まで、奥行きを見せる理由があるときだけ | 立体の演出を選んだときは、回転の軸と向きを1本でそろえる |
| グリッチ、色ずれ、ノイズの走査線 | 定番の「デジタルっぽさ」。点滅の点検に引っかかる | 使わない | サイバー調で選んだときに。強い点滅になるなら、点滅を外す扱い（[style.md](style.md) の点滅の案内）に従う |
| 汎用のワイプ、スライドで次へ（毎回横から押し出す） | プレゼンソフトのアニメーションに見える | 画面の物で転換する | 紙芝居やスライドらしさをあえて出すときに |
| タイプライターで長文を1文字ずつ出す | 読む速さより遅く、待たされる | 1文字ずつは 4〜8 文字の短い語だけ。長い文は文節ごとのずらし（60〜120ms） | コードやチャットの入力を見せるときに。読む時間は別に取る |
| 同時に複数のヒーロー | 視線が割れる | ヒーローの動きは同時に1つ（`motion-rules.md` 5章） | にぎやかさを出すときも、見てほしい1つは決めておく |

## 3. 構図と文字

| 癖 | 何も言われないときに避ける理由 | 代わりの既定 | 意図して使うときのこつ |
|---|---|---|---|
| すべてのカットが中央揃え・同じ大きさの見出し | 単調。テンプレートに見える | 左揃えの格子を基本にし、中央揃えはロゴと締めの一文など、決めの場面だけ | 対称の構図で格式を出すなら、大きさで強弱を付ける |
| 汎用アイコンや絵文字の羅列（ロケット、電球、歯車、きらきら） | 内容のない記号。どの会社の動画にも見える | 実際の画面、実際の図、渡された素材で見せる | 親しみやすさを出すときに。アイコンの線の太さと色をそろえる |
| 説明の長文を画面に貼る | 動画では読まれない | 1画面1文。言い切れないことはナレーションへ回す | 規約や注意書きなど、読ませる必要があるときは読める時間を取る |
| 最初のフレームが黒・空 | 自動再生の一覧で見本の絵が真っ黒になる | 0 秒から絵がある状態で始める | 暗転から始める演出なら、`poster` を別の時刻にする |
| 縁取りの太い文字、強いドロップシャドウ | 安っぽく見える | 縁取りは 2px まで。文字の裏に面を敷く | 漫画風・バラエティ風を選んだときに |

## 4. 言葉の癖（原稿を書くとき）

次の言い回しは、何も言われなければ使わない。渡された資料にその言葉があるとき、または使う人が望んだときは使ってよい。原稿を変えるときは、原稿の確認（絵コンテの関門か、構成の確認）で使う人に確かめる。

- 「革新的な」「次世代の」「シームレスな」「圧倒的な」「新たな価値を」「〜の未来へ」「〜を、もっと。」
- 「あなたのビジネスを加速」「すべてを、ひとつに」のような、どの製品にも当てはまる一文。
- 代わりの既定: 具体の名詞と動詞で書く（その製品が何を、誰の、何から解放するのか）。

## 新しく見つけた癖を足す手順

点検で、この表にない癖が見つかることがある（例: 「全カットで見出しが左上から斜めに入る」「数字がいつも 0 から数え上がる」）。見つけたら、**その動画の `style.md` の「禁止」節**（その動画で避けると決めた癖）に足してから描き直す。こうすると、後で描くシーンや部分修正で同じ癖が戻らない。

1. **癖を具体的に書き出す。** どのカットの何秒で、何がどう動いているかを書く。「AIっぽい」ではなく「カット2・3・5 で、見出し・本文・ボタンが同じ 500ms で同時に下から 40px 浮き上がる」。
2. **`style.md` の「禁止」節に1行足す。** 形は「〜しない。代わりに〜する（見つけた点検: 自己点検の何周目、または利用者の指摘）」。節が無ければ、`## 禁止` の見出しを作って足す。

   ```markdown
   ## 禁止

   - 見出し・本文・ボタンを同じ長さで同時に浮き上がらせない。代わりに見出しをマスクで 700ms、本文を 120ms 遅れて 400ms、ボタンを不透明度だけで 180ms にする（自己点検 2 周目、カット2・3・5）
   ```

3. **ほかのシーンを探す。** 同じ癖が、まだ指摘されていないシーンにもないかを、コード（`src/scenes/*.html`）とコンタクトシートで探す。見つけたものはまとめて直す。
4. **直したシーンだけを書き出し直して、フレームで確かめる。** 遷移の前後と、該当の時刻のフレームを見る。「直したはず」で終えない。
5. **シーンを他の作業者（サブエージェント）に任せるときは、`style.md` を必ず一緒に渡す。** 「禁止」節と「既定から外すこと」節を読まずに描くと、同じ癖が戻るか、決めた演出が消える。
