# まとまりを作る（Spec → 計画 → 実装・評価 → main へ）

引数は、まとまりの名前（例: `discover`）、`next`（未着手の最初の 1 つ）、`all`（残りを順にすべて）のどれか。省略したら `all`。開発者の返事は待たない。まとまりの境目でも止まらない。

## 始める前に

1. `docs/prd.md`（まとまりの一覧、順番、受け入れ基準）、`docs/specs/00-common.md`、`docs/specs/00-tech-stack.md`、`docs/superpowers/progress.md` を読む
2. progress.md がなければ、下の形で作る。`00-common.md` がなければ、PRD のまとまりをまたぐ決まり（製品の芯、4 観点の物差し、AI の言い方、データの扱い、合格基準）から作り、doc-reviewer に点検させてコミットする
3. 対象のまとまりを決める。状態が「進行中」のものがあれば、それの続きから始める

## まとまりごとの手順

各手順の成果はファイルとコミットに残す。途中で止まっても、次のセッションでは、できているところを飛ばして続ける。

1. **ブランチ**: `unit/<番号>-<名前>` を main から切る（あれば切り替える）。progress.md の状態を「進行中」にする
2. **Spec**: `docs/specs/<番号>-<名前>.md` を書く
   - 見出しは「目的」「振る舞い」「受け入れ基準」「やらないこと」「評価との対応」
   - 受け入れ基準は 1、2、3 と番号を振り、呼び名を `<名前>-<番号>（タイトル）` にする
   - まとまりをまたぐ決まりは 00-common.md に書き、ここからは参照する
   - 書いたら doc-reviewer エージェントに読みやすさを点検させ、コミットする
3. **計画**: superpowers:writing-plans で `docs/superpowers/plans/` に書く。実行方法は尋ねず、承認も待たない。確認コマンド（ビルド、テスト、評価）を計画の最後に書く。コミットする
4. **実装・評価**: run-plan スキルの手順で回す
5. **次へ**: 引数が `all` なら、次の未着手のまとまりへ進む。保留にしたまとまりがあっても止めない

すべて終わるか、残りがすべて保留になったら、開発者に知らせて、まとめを報告する（呼び名はタイトルとセットで）。

## progress.md の形

```markdown
# 自走の進み具合

| まとまり | 状態 | ブランチ | 更新 | メモ |
|---|---|---|---|---|
| 01 DISCOVER（対話とエピソードの保存） | 未着手 / 進行中 / 完了 / 保留 | unit/01-discover | 2026-11-03 14:20 | 評価 18/20 |

## 開発者に確認してほしいこと

- [ ] discover-2（足りない観点だけ聞き返す）の言い方:「…」（evals/results/2026-11-03-discover.md）

## 保留

- 02 VALIDATE: 2 回直しても評価が通らない。理由と、試したこと
```

状態と確認事項だけを書く短い文書にする。経緯の詳細はコミットと `docs/superpowers/` に残す。
