# RE:VALUE（リバリュー）

> キャリアには空白があっても、人生に空白はない。

育児などでキャリアを中断した人のための Web アプリです。AI が聞き手になって人生経験を引き出し、本人の言葉を根拠に力を確かめ、生活の条件の中で仕事の選択肢を広げます。どの仕事に進むかは本人が選び、最初の一歩を決めます。

Built with Claude: Japan 2026 の提出作品として、2026-11-02 から開発しています。

## 大事にしていること

- **根拠のない力は出さない**: 力ごとに核となる行動を 2〜3 つ決めています。たとえば利害調整力は「関わる 2 者以上の、それぞれ違う都合をつかむ」「自分から働きかける」「代わりの案を出すか、双方の都合を合わせる」の 3 つです。一つの具体的な出来事の中ですべて確かめられたときだけ「あなたの話から見えた力」として示し、本人の言葉を添えます
- **突き放さない**: 足りないときは、足りない行動だけを聞き返します。「根拠なし」「不得意」とは言いません
- **本人が選ぶ**: AI は採用の判断や適職の断定をしません。本人が直す、保留する、自分の案を書く、を選べます

点数や順位は出しません。まとめるのは、本人の言葉と、本人が選んだことです。

## できること

| 段階 | 内容 |
|---|---|
| 話す | AI が聞き手になり、受け止めてから一つずつ、最近の具体的な一日を聞く。選択肢から選んでも、自由に書いてもよい |
| 確かめる | 本人の言葉を根拠に、能力辞書（力と核となる行動をまとめた一覧）の 22 の力（例: 傾聴力、段取り力、不安軽減力）を確かめる。足りないときは、足りない行動だけを聞き返す。本人が訂正したり、見立てを外したりできる |
| 5 つの記録 | できること、好み、やりたいこと、条件、主体性（動き出すときに大事にしたいこと）を、混ぜずに別々に残す |
| 仕事の選択肢 | 「選ぶ」（登録した実在の職種）、「組み合わせる」（登録した業務の組み合わせ）、「創る」（事業のアイデア）の 3 枚のカードを示す。順位は付けない。どれも使える時間と場所の範囲に収め、収入の目安を本人の目安と並べて示す（「創る」は出さない）。本人が一つ選ぶか、保留するか、自分の案を書く |
| 選んだ案を深める | 選んだ案の業務ごとに、使える力とまだ確かめていないことを示す。「こんなときどうするか」という仮の場面の問いで考え方を聞き、小さな最初の一歩の候補を出す |
| 可能性レポート | ここまでを一つにまとめる。欄ごとに直す画面へ進め、保留も一歩の選び直しもできる。中身が変わると前の版を残す |

詳しくは [docs/prd/](docs/prd/README.md)（PRD。何を作るかを決めた文書）にあります。

## 触り方

### 公開 URL

公開 URL は、提出のときにここに書きます。Google アカウントでログインし、保存するものと使い道を読んで了解すると始められます。

保存するのは、ログインした人を見分ける ID と、話した内容と記録だけです。メールアドレスや名前は保存しません。設定の「全部消す」ですべて消せます。使わなければ、最後に使った日から 30 日で自動で消えます。送る前の書きかけの答えは、サーバーへ送らず、その端末のブラウザにだけ残ります（送る、全部消す、ログアウトなどで消え、30 日たっても消えます）。

1. アプリを開くとトークが出るので、最近のある一日のことを話す（一つの話は 8 往復まで）。途中で「ここで区切る」を押しても話し終えられる。区切ると、その話から見えた力がトークの中に出る
2. トークの下（PC では右）のメニュー板の「見えた力」で、本人の言葉を根拠にした力を見る。3、4、6 の画面もメニュー板から行ける
3. 「5 つの記録」で、好み、やりたいこと、条件、主体性を入れる
4. 「仕事の選択肢」で 3 枚のカードから一つ選ぶ（保留しても、自分の案を書いてもよい）
5. 「選んだ案を深める」（仕事の選択肢の画面から行く）で、問いに答え、最初の一歩を選ぶか書く
6. 「可能性レポート」で、ここまでのまとめを見る

### 手元で動かす

鍵がなくても動きます。開発用の設定（Development）では、ログインが偽物に、データの置き場がメモリに替わります。鍵がなければ AI も偽物になります。.NET 10 と Node.js 24 が要ります。

```sh
npm --prefix src/web ci
npm --prefix src/web run build
dotnet run --project src/Revalue.Server
```

http://localhost:5080 を開きます。本物の Claude で試すときは、環境変数 `ANTHROPIC_API_KEY` を置いてから起動します。

## Claude の使い方

### 製品の中

製品の中では、どの役割も Claude Opus 5.5（`claude-opus-5-5`）を、Anthropic の公式 C# SDK で呼んでいます。

| 役割 | 呼び方 |
|---|---|
| 聞き手の返事 | ストリーミングで、少しずつ画面に出す |
| 読み取り（答えの種類と、核となる行動の根拠の候補） | 構造化出力（決まった形の JSON） |
| 仕事の選択肢の 3 枚のカード | 構造化出力 |
| 選んだ案を深める（業務ごとの見立て、仮の場面の問い、一歩の候補） | 構造化出力 |

**コードが決めて、AI が言葉にする**ようにしています。

- 1 往復ごとに、まず AI が答えを読み取り、根拠の候補を返します。根拠ありにする、足りない行動を聞く、別の場面を聞く、のどれにするかはコードが決めます。聞き手の AI には、決まった次の一手だけを渡して言葉にさせます
- 根拠の引用は、本人の発言に一字一句含まれるかをコードで照らし合わせます。含まれなければ使いません
- 仕事のカードは、登録した職種と業務の ID で受け取ります。登録にないもの、使える時間と場所を超えるものは、コードで落とします。言い切りや順位の言葉、大げさな褒め言葉、お金の額を含むカードも落とします
- 選んだ案を深めるときの一歩の候補は、条件の外のもの、応募・申し込み・契約・購入にふれるもの、「〜しましょう」「〜すべき」と急かすものをコードで探します。一つでもあれば、3 つともコードが決めた候補に置き換えます
- 可能性レポートは AI を呼ばず、記録からコードが組み立てます。新しい見立てや言い切りを作らないためです
- AI への決まった指示（システムプロンプト）には、プロンプトキャッシュ（同じ前置きを使い回して、費用と待ち時間を減らす仕組み）を付けています
- AI が応答を断ったときだけ、Anthropic が選ぶ別のモデルが代わりに答える仕組み（server-side fallback）を有効にしています

### 評価

AI が褒めすぎないか、突き放さないか、本人の代わりに決めないかを、架空のデータで確かめています。使うのは、エピソード集（利用者が AI に話す出来事の例）と、それを元にした 5 つの記録と選んだ案です。合格の線は [6-quality.md](docs/prd/6-quality.md)、測り方は [evals/criteria.md](evals/criteria.md) にあります。最新の結果は次のとおりで、どれも合格です。

| まとまり | 主な結果 |
|---|---|
| 話す（[結果](evals/results/2026-11-05-discover-3.md)） | 受け止めてから問いを一つだけ出した返事 32 / 34。使わない言葉（「不得意」など）を含んだ返事 0 件（35 中） |
| 確かめる（[結果](evals/results/2026-11-05-validate-5.md)） | 褒めすぎ（根拠ありにしてはいけない力を根拠ありにした、または根拠ありにした力の引用が行動を示していない）0 件（142 中）。根拠の引用が本人の発言と一字一句同じ 143 / 143 |
| 仕事の選択肢（[結果](evals/results/2026-11-06-options.md)） | 登録していない職種、条件を超える案、言い切り、順位付けがどれも 0 件（カード 22 枚） |
| 選んだ案を深める（[結果](evals/results/2026-11-06-deepen.md)） | 条件の外の一歩 0 件（21 中）。本人の代わりに決める言い方 0 件（7 案中） |

同じやりとりや記録を、特別な指示のない同じモデル（下の表の「汎用の AI」）にも渡して比べました。

| 物差し | RE:VALUE | 汎用の AI |
|---|---|---|
| 褒めすぎ（根拠ありにしてはいけない 109 の力のうち、根拠あり・強みとした） | 0 件 | 22 件 |
| 仕事の案に順位やおすすめを付けた（RE:VALUE は案 22、汎用の AI は案 24 のうち） | 0 件 | 2 件 |
| 仕事の案の理由で、本人の言葉にない引用 | 0 / 83 | 16 / 30 |

### 開発

Claude Code を中心に、ほぼ自動で開発しています。何を作るかは、人が PRD で決めます。そこから先は、機能のまとまりごとに AI が Spec（仕様書）を書き、実装・評価して main ブランチに入れます。

| 使ったもの | 何のために |
|---|---|
| Superpowers（Claude Code のプラグイン） | PRD を対話で作る（brainstorming）、計画を書く（writing-plans）、テストから書く（test-driven-development） |
| Workflow（[.claude/workflows/run-plan.js](.claude/workflows/run-plan.js)） | エージェントを決まった順に動かすスクリプト。計画を、実装 → 確認（ビルド・テスト・評価）→ レビュー → 反証（通ったという結論を壊しにいく）→ 直し（2 回まで、直すたびに強いモデルへ）→ 文書の点検、の順に回す |
| スキル（[.claude/skills/](.claude/skills/)） | build-unit: まとまりを Spec から main まで作り、次へ進む。run-plan: 計画を Workflow に渡す |
| サブエージェント（[.claude/agents/](.claude/agents/)） | doc-reviewer: 人が読む文書を点検して削る。voice-reviewer: 製品の AI の言い方を、褒めすぎ・突き放しの点で点検する |
| フック（[.claude/hooks/](.claude/hooks/)。決まったときに自動で動くスクリプト） | 公開リポジトリに鍵（API キーなど）や実在の人の連絡先が入るのを止める。セッションが替わっても続きから始められるよう、進み具合を最初に読ませる |
| MCP（[.mcp.json](.mcp.json)。Claude Code に外の道具をつなぐ仕組み） | Microsoft Learn と Context7 で公式ドキュメントを引く。Playwright で画面を実際に動かして確かめる |
| 持ち込んだプラグイン（[.claude/skills/brought-in-plugins.md](.claude/skills/brought-in-plugins.md)） | ns-motion-studio で提出用の動画を、ns-illustrations の挿絵で資料を作る |

## 持ち込んだもの

製品に持ち込んだデータはありません。評価に使うエピソード、5 つの記録、選んだ案は、すべて架空で、開発期間中に新しく書きました。

登録した職種と業務のデータ（業務マスター。`src/Revalue.Server/Features/Options/jobs.json`）も、期間中に作りました。10 の領域、30 の職種、125 の業務で、仕事の選択肢のカードに使うのは 115 の業務です。協力者へのインタビューをもとに、Claude が書き起こしました。職種と業務には、job tag（厚生労働省の職業情報提供サイト）のダウンロードデータの職業とタスクの番号を持たせています。利用規約に従って言い換え、出典をデータと仕事の選択肢の画面に載せています。使う力、力が生きる場面、週あたりの時間、時給の目安などは job tag にない値で、Claude が下書きしました。時給の目安の下限は、最低賃金を下回らないよう 1,300 円以上にそろえています。

提出用の動画と資料を作る道具として、開発スタート前に作られた Claude Code のプラグインを 2 つ持ち込みました（ns-motion-studio、ns-illustrations）。作成元の許可を得て公開しています。製品のコードには組み込んでいません。置き場所とライセンスは [.claude/skills/brought-in-plugins.md](.claude/skills/brought-in-plugins.md) にあります。
