# 力を能力辞書に置き換え、業務を業務マスターにする

2026-11-05。PRD の [4-rules.md](../prd/4-rules.md) の「力を確かめる物差し」と、芯 1（根拠のない力は出さない）の文言を変えた。その理由を残す。進め方は [設計](../superpowers/specs/2026-11-05-ability-dictionary-design.md)。

能力辞書は、力の名前とその力を感じる行動をまとめた一覧。業務マスターは、職種と業務の一覧。

## なぜ変えるか

- 当事者の協力者から、ゴールの姿と聞き出し方のイメージを受け取った（11/5）。次の流れ
  - 話から能力の候補を見つける
  - 能力ごとに「その能力を感じる行動」を根拠に示す
  - 能力に合う業務を、業務マスターから推薦する
  - 本人の希望と条件で絞る
- 協力者の考える量は、能力 126、業務 120。いまの 3 つの力（見立てる、調整する、優先順位をつける）と 3 職種 12 業務の作りでは、この量が入らない。力はデータではなく、コードに直接書いてある
- 架空の 6 人で試した評価（11/4）でも、力の名前と本人の言葉の引用が並ぶだけで、なぜその力なのかが伝わらなかった

## 決めたこと

| 決めたこと | 決めた人 | 外した案 | 理由 |
|---|---|---|---|
| 力の名前と理由は、協力者のインタビューで得たものを基準にする。中身は Claude が書き起こす | 開発者 | 協力者の表をそのまま取り込む | 協力者はハッカソンの選考を通っていないので、プロジェクトに貢献できない（当事者へのインタビューは制限されない）。資料は git が無視する置き場所に置き、協力者はリポジトリにコミットしない（協力者も了解） |
| いまの 3 つの力は残さず、辞書の力に置き換える | 開発者 | いまの 3 つを残して、辞書の力を足す | 物差しを協力者の見方にそろえる |
| 核となる行動は、理由を分けた 2〜3 つ。芯 1 の文言を「3 つ」から「2〜3 つ」に変える | 開発者 | 3 つにそろえる | 3 つにそろえると、理由が 2 つにしか分かれない力に、理由にない行動を足すことになる。一つの出来事の中ですべてそろったときだけ根拠ありにする決まりは変えない |
| 辞書は 126 項目をすべてデータに入れ、話から確かめるのは 24 から始める。残りは準備中 | 開発者（数）、Claude（24 の選び方） | 126 項目すべてを話から確かめる | 力ごとに評価の台本で確かめないと、根拠のない力を出すおそれがある。24 は、業務マスターの業務につながる力から選んだ |
| 一つの出来事から見せる力は、分類ごとに 1 つまで。「まだ聞けていない力」の一覧は出さない | Claude | すべて見せる | 似た名前の力が並ぶと褒めすぎに見え、24 の一覧は採点表に見える |
| MBTI（性格のタイプ分け）は使わない | Claude（開発者に示した） | 自己理解の参考として使う | 運営が避けるべき例に挙げた「性格診断」にあたる |
| 08 revisit（別の日に話す）は、能力辞書と業務マスターのあとに作る | 開発者 | 同じ期間に両方作る | 提出（11/8）までに両方は作れない。08 revisit で示す「話の数」は力ごとに数えるので、力が決まってから作るほうが二度手間にならない |
| 最初の問いの選択肢を、協力者の入口の言葉に寄せ、「うれしかった日」「困ったことがあった日」「思いどおりにいかなかった日」にする | Claude | いまの 3 つ（「うまくいったと感じた日」「大変だったけど、乗り切った日」「思うようにいかなかった日」） | 協力者の深掘りの入口が気持ちの言葉で始まるため。最初の問いの文は変えない。言葉は協力者に確かめる |
| 原因分析力と仮説思考力は、聞き方が決まるまで準備中にする。話から確かめる力は 22 から始める | Claude | 行動の文と続きの問いを、本人がしたことを聞く形に書き直して残す | 2 つの力は、うまくいかなかったわけを考えることそのものが核となる行動で、続きの問いと手がかりがわけを問う形になる。うまくいかなかったわけは聞かない決まり（6-quality.md）とぶつかり、最初の問いに「困ったことがあった日」を入れたので、聞き返される見込みも高い。書き直すと理由（協力者の見方）から離れるので、聞き方を協力者に確かめてから戻す |
| 一つの出来事から見せる根拠ありの力は、場面全体でも 3 つまでにする | Claude | 分類ごとの上限（1 つまで）だけにする | 話から確かめる力のある分類が 8 つあり、分類ごとの上限だけでは、一つの話に力が並びすぎて褒めすぎに見える |
| そろっても見えた力に出せない力（同じ分類で行動の多い力がそろっている、全体の上限からこぼれる）は、聞き返さず、「もう少し聞かせてほしいこと」にも出さない | Claude | 聞き返し、そろったら見せずにおく | 答えても本人には何も見えず、往復の上限も減る。聞き返しの振る舞い（芯 3（AI が聞き手になる）、validate-2（足りない行動だけ聞き返す））を変えるので、評価で確かめる |
| 本人の行動ではない状況（用事が重なる、予定が変わる、困りごとが続く、思うようにいかない）の行動に印（`situation`）を付け、見えた力ではその行動の文を出さず、本人の言葉だけにする | Claude | すべての行動の文を、本人の言葉と組にして出す | うまくいかなかった状況を、本人の力の見出しとして本人の言葉に付けないため。印を付けたのは、優先順位設定力 1、予定変更への対応力 1、走破力 1、回復力 1 |

## まだ分かっていないこと

- 24 の力の中に、日々の話から確かめにくい力がないか
- 分類ごとに 1 つまで見せる決まりで、本人にとって大事な力が隠れないか。協力者の「能力候補をたくさん見つける」考えとのつり合いを、協力者に確かめる
- Claude が理由に 2 つ目の行動を書き足した力と、使う力を付け替えた業務が、協力者の考えに合っているか
