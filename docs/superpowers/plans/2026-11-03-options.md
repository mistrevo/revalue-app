# 05 options（仕事の選択肢） 実装計画

> **For agentic workers:** この計画は run-plan スキル（Workflow）で回す。手順はチェックボックス（`- [ ]`）で進み具合を記録する。

**Goal:** 確かめた力と 5 つの記録から、条件の範囲で「選ぶ」「組み合わせる」「創る」の 3 枚のカードを出し、本人が選ぶ・保留する・自分の仕事を書けるようにする。評価で、登録にない職種、条件を超える案、根拠を引けない「創る」、言い切りを数える。

**Architecture:** 登録した職種と業務は `Features/Options/jobs.json`（埋め込みリソース）を起動時に読み、`JobCatalog` に持つ。コードが条件に合う業務だけを候補にして AI に渡し、AI（構造化出力、effort high）が ID を選んで理由を書く。AI の答えはコード（`OptionsValidator`）が登録、条件、力、引用、使わない言葉、長さで照らし合わせ、合わないカードは出さない。利用者ごとに 1 件の `OptionsItem`（id `options`）に、カード、本人が書いた仕事、選んだ案を持つ。カードを作ったときの元の記録の指紋（`Basis`）を持ち、変わったら作り直せると伝える。

**Tech Stack:** ASP.NET Core（.NET 10）Minimal API、Anthropic 公式 C# SDK（`client.Beta.Messages.Create`、構造化出力）、System.Text.Json、xUnit v3。React 19 + TypeScript + Vite + Tailwind 4 + shadcn/ui、Vitest + Testing Library。Playwright MCP。評価は `evals/Revalue.Evals`。

**Spec:** `docs/specs/05-options.md`（あわせて `docs/specs/00-common.md`、`docs/specs/00-tech-stack.md`、`docs/specs/03-validate.md`、`docs/specs/04-profile.md`）

## Global Constraints

- 回答・文書・コミットメッセージは日本語。呼び名はタイトルとセット（例: options-5（条件の範囲だけ））
- テストの名前（DisplayName / `it` の文）は `options-N（タイトル）: …` の形にする。受け入れ基準は options-1（3 枚を同じ重さで示す）、options-2（選ぶは登録した職種から）、options-3（組み合わせるは登録した業務から）、options-4（創るは根拠を引けるときだけ）、options-5（条件の範囲だけ）、options-6（本人が選ぶ、保留する、自分で書く）、options-7（1 場面で進める）、options-8（理由は本人の言葉とつなぐ）
- テストでは Claude を呼ばない。`IOptionsAi` の偽物（`ScriptedOptionsAi`、テストではさらに差し替え）を使う
- 使わない言葉（`src/shared/forbidden-words.json`）を、画面の文言、データ、AI が書いた文に入れない。照らし合わせるときは、力の名前「優先順位をつける力」の中の「順位」を除く（00-common.md の「言葉」）
- カードを作り直すのは、元の記録が変わったときだけ（画面を開いたときに自動で）。同じ記録のまま作り直す道は作らない
- 状態の呼び名（根拠あり、要確認、未確認）、点数、順位を画面に出さない。「要確認」の力は「確かめ中」と示す
- 根拠の本人の言葉は「」で囲み、一字一句そのまま出す。選んだ答えの根拠は「（選んだ答え）」と結びついた言葉を添える（03 の `QuoteList` を使う）
- 画面の文言は `src/web/src/copy.ts`、AI への指示は `src/Revalue.Server/Ai/Prompts/options.md` に置く
- 仕事の選択肢の AI: モデルは設定 `Claude__Model`（既定 `claude-opus-5-5`）、構造化出力（`BetaJsonOutputFormat`）、`Effort.High`、`Fallbacks = new Default()` と beta `server-side-fallback-2026-07-01`、システムプロンプトに `CacheControl`。thinking の無効化、`budget_tokens`、`temperature` は送らない
- `POST /api/options` は `RequireDailyLimit()`（1 日の送信回数に 1 回）。ほかの API は AI を呼ばず、上限も数えない。どれも `RequireConsent()`
- ログに書いてよいのは、利用者キー、件数、かかった時間、トークン数、止まった理由、照らし合わせで落とした数（規則ごと）、エラーの種類だけ。カードの中身、理由、本人が書いた仕事、根拠の言葉は書かない
- 文字数は `StringInfo.LengthInTextElements`（見た目の 1 文字）で数え、中身の長さ（UTF-16）にも見た目の上限の 4 倍の上限を置く。前後の空白は落としてから数える。見える文字のない言葉は断る（04 profile（5 つの記録）の照らし合わせを使い回す）
- 収入の目安は、業務の時給の目安 × 週あたりの時間 × 4（月 4 週）。下は 1,000 円単位で切り下げ、上は 1,000 円単位で切り上げる。画面では万円で小数 1 けたまで（`4.8`、`7` のように末尾の `.0` は書かない）
- 職種と業務のデータ（`jobs.json`）の値は Claude の下書き。実装でデータを変えない（変えるなら報告に書く）
- progress.md は書き換えない

## Review Focus

1. カードを作ったあとに、本人がカードの理由に使った力を外す → その力を使ったカードは、作り直すまで出さず、`missing` に `excluded` として出す。作り直せることも伝える（`stale` が true）。Task 4 の `ExcludedAbilityHidesCardUntilRegenerated`
2. カードを作ったあとに、条件を狭める（週 10 時間 → 3 時間、外出できる → 家だけ）→ 新しい条件に収まらないカードは出さず、`missing` に `noFit` として出す。Task 4 の `NarrowedConditionsHideCardsOutOfRange`
3. AI が、登録にはあるが条件に合わない業務の ID を返す（外に出る業務を「家だけ」の人に）→ カードを出さない。Task 2 の `RegisteredButOutOfConditionsTaskIsRejected`
4. 古い画面でカードを選ぶ（別の画面で作り直したあと）→ 409 で、選んだ案は変わらない。Task 4 の `ChoosingStaleCardIs409`
5. AI の理由の文に、本人の根拠にない「」の言葉がある → そのカードを出さない。Task 2 の `BracketQuoteNotInEvidenceIsRejected`

決まり:
- `Load` / `Parse` は、データが壊れていたら `InvalidOperationException` を投げる（起動を止める）。確かめること: 職種と業務の id が重ならない、`Min ≤ Max`（時間と時給）、`HoursPerWeek.Min ≥ 1`、時間帯が 1 つ以上、使う力が 3 つの力のどれか、`JobTagTasks` が 1 つ以上
- `Fits`: `task.HoursPerWeek.Min ≤ c.HoursPerWeek`、`task.TimeSlots` と `c.TimeSlots` が 1 つ以上重なる、`PlaceFits(task.Place, c.Place)`（`Out` は `CanGoOut` の人だけ）
- `ChooseRange`（業務はどれか一つから受けられる、と読む）: 時間の下 = 業務の `Min` のいちばん小さい値、上 = `min(c.HoursPerWeek, 業務の Max のいちばん大きい値)`。収入の下 = 時間の下 × 時給の `Min` のいちばん小さい値 × 4、上 = 時間の上 × 時給の `Max` のいちばん大きい値 × 4
- `CombineFits`: どの業務も `Fits` で、`Min` の合計 ≤ `c.HoursPerWeek`
- `CombineRange`（業務を一緒に受ける、と読む）: 時間の下 = `Min` の合計、上 = `min(c.HoursPerWeek, Max の合計)`。収入の下 = 業務ごとの `Min × 時給の Min` の合計 × 4、上 = 時間の上 × 時給の `Max` のいちばん大きい値 × 4
- 収入は、下を 1,000 円単位で切り下げ、上を 1,000 円単位で切り上げる

照らし合わせの規則（どれかに当たればそのカードを出さず、`MissingReason.Rejected` と `CardRejection` を足す。`Rule` の名前をそのまま使う）:
- `notMade`: `Made` が false（このときは `Rejected` ではなく、選ぶ・組み合わせるなら `NoFit`、創るなら `NoEvidence` にする）
- 候補で作れない（`CanChoose` / `CanCombine` が false）カードは、AI の答えを見ずに `NoFit`（`CardRejection` は足さない）
- `unknownId`: 渡していない職種や業務の ID（登録にあっても候補にないものを含む）
- `wrongOccupation`: 選ぶの業務が、選んだ職種の業務でない
- `taskCount`: 選ぶの業務が 1〜3 でない、組み合わせるの業務が 2〜3 でない、同じ業務が重なる
- `singleOccupation`: 組み合わせるの業務が 1 つの職種だけ
- `overHours`: 組み合わせるの `CombineFits` が false、創るの `HoursPerWeek` が 1 未満か本人の時間を超える
- `outsideConditions`: 創るの場所が本人の条件に合わない（`homeOnly` の人に `out`）、時間帯が空か本人の時間帯の外を含む、知らない場所や時間帯の名前
- `abilityNotUsable`: 力の名前が知らないもの、使える力でない（外した力を含む）
- `abilityNotInTasks`: 選ぶ・組み合わせるで、使った力がカードの業務のどの使う力とも違う
- `quoteNotVerbatim`: 創るの `Quotes` が 1〜3 でない、またはその力の根拠の言葉（`Evidence.Quote`）と前後の空白を落として一字一句同じでないものがある
- `bracketNotVerbatim`: 理由、役割の名前、創るの文のどれかにある「」の中の言葉が、使える力の根拠の言葉（`Quote` か `LinkedQuote`）のどれにも含まれない（Ordinal の `Contains`）
- `forbiddenWord`: AI が書いた文のどれかで `ForbiddenWordList.FirstIn` が null でない
- `tooLong` / `empty`: 見た目の文字数の上限を超える、または空。上限: 理由 300、役割の名前 30、題 40、誰の 60、困りごと 120、創るの中身 300（Claude の判断）

カードにする中身:
- `CardAbility.Quotes`: 選ぶ・組み合わせるでは、その力の `UsableAbility.Quotes` をそのまま。創るでは、AI の `Quotes` に一致した `Evidence`（`UsableAbility.Quotes` から取る）
- `Range`: 選ぶは `ConditionFit.ChooseRange`、組み合わせるは `ConditionFit.CombineRange`
- 文は前後の空白を落として入れる

`ForDisplay`（保存したカードを見せるとき）:
- カードの力がいまは外した力 → そのカードを出さず `Excluded`
- カードの力がいまは使える力でない（状態が未確認に下がった） → 出さず `Rejected`
