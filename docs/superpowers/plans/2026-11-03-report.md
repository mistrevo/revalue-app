# 07 report（可能性レポート） 実装計画

> **For agentic workers:** この計画は run-plan スキル（Workflow）で回す。手順はチェックボックス（`- [ ]`）で進み具合を記録する。

**Goal:** 確かめた力と根拠、まだ確かめていないこと、5 つの記録、選んだ案、仕事の場面での考え方、最初の一歩を、いまの記録からコードが組み立てて一つの画面に示す。中身が変わったら版を増やし、前の版（根拠の言葉は写さない）と変わった欄を残す。レポートから、直す画面へ進む、保留する、一歩を選ぶ・書くができる。

**Architecture:** `ReportBuilder` が、03 の力の状態（`AbilityBook.View`）、04 の `ProfileItem`、05 の `OptionsItem`（選んだ案）、06 の `DeepenItem`（`DeepenTargetReader`、`DeepenLighting` を含む）から `ReportContent` を組み立てる。AI は呼ばない。欄ごとの指紋（`SectionHashes`）と全体の指紋を作り、`GET /api/report` で、いちばん新しい版と違えば `ReportItem`（id `report`）に版を足す（新しいものから 10 まで）。版には根拠の言葉を除いた写し（`ReportSnapshot`）を持つ。開けたら「可能性レポートまで進んだ人」を数える。画面は `/report`。保留は 05 の API、一歩は 06 の API と部品を使い回す。

**Tech Stack:** ASP.NET Core（.NET 10）Minimal API、System.Text.Json、xUnit v3。React 19 + TypeScript + Vite + Tailwind 4 + shadcn/ui、Vitest + Testing Library。Playwright MCP。

**Spec:** `docs/specs/07-report.md`（あわせて `docs/specs/00-common.md`、`docs/specs/00-tech-stack.md`、`docs/specs/05-options.md`、`docs/specs/06-deepen.md`）

## Global Constraints

- 回答・文書・コミットメッセージは日本語。呼び名はタイトルとセット（例: report-3（版を残す））
- テストの名前（DisplayName / `it` の文）は `report-N（タイトル）: …` の形にする。受け入れ基準は report-1（一つにまとめて示す）、report-2（直す、保留する、次の一歩を選ぶ）、report-3（版を残す）、report-4（決めつけない）、report-5（保留しても開ける）、report-6（話を足したら作り直す）
- AI は呼ばない。`GET /api/report` は `RequireConsent()` だけで、1 日の送信回数（`RequireDailyLimit`）は使わない
- 状態の呼び名（根拠あり、要確認、未確認）、点数、順位を画面に出さない。根拠ありは「あなたの話から見えた力」、要確認は「確かめ中」、未確認は「まだ聞けていない力」。根拠の本人の言葉は 03 の `QuoteList`（「」と（選んだ答え））で出す
- 本人が外した力（`AbilityView.Excluded`）は、どの欄にも使わない
- 使わない言葉（`src/shared/forbidden-words.json`）と、言い切りと順位の言葉（`OptionsValidator.AssertiveWords`）を、画面の文言とコードが組み立てる文に入れない。選んだ案は「あなたが選んだ案」と書く
- 版（`ReportItem.Versions`）には根拠の本人の言葉（`Evidence.Quote`、`LinkedQuote`）を写さない。指紋の計算には使ってよい（元に戻せない値なので）
- 画面の文言は `src/web/src/copy.ts` の `report` に置く
- ログに書いてよいのは、利用者キー、件数、かかった時間、エラーの種類だけ。レポートの中身は書かない
- 書き換えは、読んだときから変わっていないときだけ書く（ETag。`OptionsStore.UpdateAsync` と同じ形の `ReportStore.UpdateAsync`）
- progress.md は書き換えない

## Review Focus

1. 場面を飛ばした（またはその言葉を根拠にしていた力を外した）あとで、前の版を見る → 前の版に、その言葉が残っていない（版には根拠の言葉を写さない）。Task 2 の `VersionsDoNotKeepQuotes`
2. 2 つの画面でほぼ同時にレポートを開く → 同じ中身なら版は 1 つだけ増える。Task 2 の `ConcurrentOpenAddsOneVersion`
3. 案を選んだあとに保留へ切り替えて開く → 版が増え、「選んだ案」の欄が保留になり、変わった欄に「選んだ案」が入る。Task 2 の `HoldingAddsVersion`
4. 選び直して 06 の深めた中身が古いまま開く → 考え方と一歩の欄は、前の案のものを出さずに、深めると出せると示す。Task 1 の `StaleDeepenIsNotShown`
5. 11 回中身を変えて開く → 版は新しいものから 10 まで残り、版の番号は通し番号のまま（第 11 版がいちばん新しい）。Task 2 の `KeepsTenVersions`

| API | 振る舞い |
|---|---|
| `GET /api/report` | `ReportBuilder.BuildAsync` で組み立てる。`Ready` が false なら `ReportDto(false, null, null, [])`（版も数も触らない）。前の版を返すときは、いま本人が外している力を `Snapshot.Abilities` から除く。`Ready` なら、欄の指紋と全体の指紋を作り、`ReportStore.UpdateAsync` の中で、いちばん新しい版の `Hash` と違えば版を先頭に足す（番号は前の番号 + 1、`Changed` は欄の指紋が違う欄、11 個目以降は捨てる）。同じなら書き換えない（`apply` がそのまま返したら書かない形にする）。そのあと、`Choice.Kind` が `Card`、`Own`、`Hold` のどれかなら `CountOnceAsync(ReachedReport)`（まだ選んでいなければ数えない）。`Current` はいちばん新しい版、`Previous` はそれより前の版 |
