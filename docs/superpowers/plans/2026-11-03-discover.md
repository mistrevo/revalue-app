# 02 discover（話す） Implementation Plan

> **For agentic workers:** このリポジトリでは、計画は run-plan スキル（`.claude/workflows/run-plan.js`）で回す（CLAUDE.md）。Superpowers の subagent-driven-development / executing-plans は使わない。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI が聞き手になって最近の一日を一つの場面として聞き出す会話（読み取り → 次の一手 → 返事を少しずつ流す）と、エピソードの保存・一覧・続きから話す・飛ばす・区切る、最小の評価の仕組みを作る。

**Architecture:** 1 往復ごとに、`IConversationAi.ReadAsync`（構造化出力）で答えの種類を読み取り、`NextMovePolicy`（コードだけ）が次の一手を決め、`IConversationAi.StreamReplyAsync`（ストリーミング）が一手を言葉にする。返事は `ReplyStreamSplitter` で本文と選択肢に分け、本文を SSE で流す。つらい状態のサインには AI の返事を使わず、`DiscoverText` の決まった言葉で応える。会話はエピソード 1 件（`EpisodeItem`）にまとめて保存し、返事を最後まで受け取れたときだけ書く。

**Tech Stack:** .NET 10 Minimal API（`TypedResults.ServerSentEvents`）、Anthropic 公式 C# SDK（NuGet `Anthropic`、13 系）、xUnit v3、React 19 + TypeScript + Vitest、GitHub Actions（`evals.yml`）、Bicep。

**Spec:** `docs/specs/02-discover.md`（あわせて `docs/specs/00-common.md`、`docs/specs/00-tech-stack.md`、`docs/specs/01-foundation.md`）

## Global Constraints

- 版・置き場所・コマンドは `docs/specs/00-tech-stack.md` に従う。機能のコードは `src/Revalue.Server/Features/Discover/`、AI の呼び出しは `src/Revalue.Server/Ai/`、プロンプトは `src/Revalue.Server/Ai/Prompts/*.md`
- Claude の C# SDK の書き方は推測しない。`claude-api` スキル（C#）を読んでから書き、名前が分からなければコンパイラのエラーで直す。モデルは設定 `Claude:Model`（既定 `claude-opus-5-5`）。日付つきの ID は使わない
- Opus 5.5 で 400 になるもの（thinking の無効化、`budget_tokens`、`temperature` などのサンプリング、assistant の先読み入力、`tool_choice` の `any`/`tool`）を送らない。返事は `OutputConfig.Effort = Effort.Low`、読み取りは `Effort.Medium` を明示する
- 拒否への備え: server-side fallback を有効にする（`fallbacks: "default"`、beta `server-side-fallback-2026-07-01`）。C# SDK に `"default"` の形がなければ、配列の形（`Fallbacks = [new(Model.ClaudeOpus4_8)]` と beta `server-side-fallback-2026-06-01`）にし、そのことを報告に書く。`StopReason == "refusal"` のままなら、拒否として扱う
- システムプロンプトは固定し、`CacheControl = new CacheControlEphemeral()` を付ける。次の一手のような毎回変わる指示はシステムプロンプトに入れず、会話の最後に足す（Opus 5.5 の会話の途中の system メッセージが SDK で使えればそれを、使えなければ最後の利用者の発言に `<next_move>…</next_move>` を足す）
- テストでは Claude を呼ばない。`IConversationAi` を偽物に差し替える。本物を呼ぶのは評価だけ
- `ANTHROPIC_API_KEY` があれば本物の AI。なければ、Development と Testing では決まった返事を返す偽物（`ScriptedConversationAi`）、Production では起動を止める（Claude の判断）
- テスト名に受け入れ基準の呼び名とタイトルを入れる。C# は `[Fact(DisplayName = "discover-1（具体的な一日を一つ聞く）: …")]`、画面は `it('discover-1（具体的な一日を一つ聞く）: …')`
- 利用者に見せる言葉のうち、画面のものは `src/web/src/copy.ts`、裏側が決めるもの（最初の問い、飛ばしたあとの問い、つらい状態のサインへの言葉、汎用の選択肢）は `Features/Discover/DiscoverText.cs` の 1 か所。どちらも `src/shared/forbidden-words.json` の言葉を含まないことをテストする
- 相談窓口のページ: 厚生労働省「まもろうよ こころ」`https://www.mhlw.go.jp/mamorouyokokoro/`。電話番号は書かない（フックにも止められる）
- 1 場面は 8 往復まで。8 往復目の返事は問いと選択肢を付けない締めの返事
- ログに話した内容、AI の返答を書かない（00-common.md の「データ」）。AI の呼び出しで書いてよいのは、利用者キー、かかった時間、トークン数、エラーの種類
- 公開リポジトリ。架空エピソードはすべて架空にし、このハッカソンの期間中に新しく書く
- コミットメッセージは日本語。呼び名はタイトルとセットで書く

## Review Focus

1. 区切りの行（`---選択肢---`）が AI の流れの途中で 2 つのかけらに分かれて届く → 区切りの一部も、選択肢も、本文として画面に漏れない。Task 2 のテストで押さえる
2. 返事の途中で AI が失敗・拒否する → 利用者の答えも返事も保存せず、二重にならない。同じ答えで送り直すと、1 往復だけ増える。Task 4 のテストで押さえる
3. 8 往復目の答えがつらい状態のサインだった → 締めより、相談窓口が先。Task 2 のテストで押さえる
4. ほかの人のエピソードの id で読む・送る・区切る・飛ばす → すべて 404。Task 1 と Task 4 のテストで押さえる
5. 画面で、話し終えた場面を開く → 読み返せるが、答えを送る欄は出ない。途中の場面は続きから話せる。Task 6 のテストで押さえる

### Task 4: 答えを受け取り、返事を SSE で流す

**Files:**
- Create: `Features/Discover/TalkStream.cs`
- Modify: `DiscoverEndpoints.cs`、`Program.cs`
- Test: `TalkStreamTests.cs`

**Interfaces:**
- Consumes: Task 1〜3 の型、`RequireConsent()`、`RequireDailyLimit()`
- Produces: `POST /api/episodes/{id}/messages`（本文 `{ text: string, kind: "free" | "choice" }`、`RequireConsent().RequireDailyLimit()`）→ `text/event-stream`。イベント（`TypedResults.ServerSentEvents` と `SseItem<T>` の `eventType`）:
  - `delta` `{ text }` — 本文のかけら
  - `choices` `{ choices: string[] }` — 本文のあとに 1 回（`Close` と `Distress` では送らない）
  - `notice` `{ kind: "distress" | "support", text, linkUrl, linkLabel, actions?: string[] }` — つらい状態のサインのとき（`actions` は `DiscoverText.DistressActions`）、読み取りに失敗したとき（`kind: "support"`）
  - `done` `{ userTurnCount, status, move }`
  - `error` `{ kind: "refusal" | "failure" }`
- 本文が空、2,000 文字を超える、`kind` が不正 → 400（SSE を始める前に）。話し終えた場面 → 409。ほかの人の id → 404
- 保存: 返事を最後まで受け取れたときだけ、利用者の答え（`AnswerKind`）と返事（`Move`、`Choices`）の 2 ターンを足して `UpsertAsync`。`Close` なら `Status = "finished"`、`FinishedAt`。`Distress` なら返事の代わりに `DistressText` のターンを足し、`ExcludedFromValidation = true`。読み取りか返事で失敗したら何も保存しない
