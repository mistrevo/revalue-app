# 06 deepen（選んだ案を深める） 実装計画

> **For agentic workers:** この計画は run-plan スキル（Workflow）で回す。手順はチェックボックス（`- [ ]`）で進み具合を記録する。

**Goal:** 選んだ 1 案の業務ごとに、使える力と根拠、まだ確かめていないことをコードが並べ、AI が書いた仮の場面の問い（1〜2 問）と最初の一歩の候補（3 つ）を、コードが照らし合わせて示す。本人は問いに答え、一歩を選ぶか書き、「創る」と自分の仕事では業務の見立てを直せる。評価で、条件の外の一歩、需要の確かめのない「創る」、言い切りと突き放しを数える。

**Architecture:** 深める対象は 05 の `OptionsItem.Choice`（カードか本人が書いた仕事）。対象の指紋（`DeepenTarget.Basis`）が変わったら作り直す。業務ごとの照らし合わせ（deepen-2）は、開いたときにいまの記録（`OptionsInputsReader`）からコードで計算し、保存しない。AI（構造化出力、effort high）は 1 回の呼び出しで、業務の見立て（「創る」と自分の仕事だけ）、問い、一歩の候補を書く。AI の答えはコード（`DeepenValidator`）が部分ごとに照らし合わせ、一歩の候補が通らなければ、コードが決めた候補に置き換える。利用者ごとに 1 件の `DeepenItem`（id `deepen`）に、深めた中身、問いの答え、選んだ一歩、書いた一歩を持つ。

**Tech Stack:** ASP.NET Core（.NET 10）Minimal API、Anthropic 公式 C# SDK（`client.Beta.Messages.Create`、構造化出力）、System.Text.Json、xUnit v3。React 19 + TypeScript + Vite + Tailwind 4 + shadcn/ui、Vitest + Testing Library。Playwright MCP。評価は `evals/Revalue.Evals`。

**Spec:** `docs/specs/06-deepen.md`（あわせて `docs/specs/00-common.md`、`docs/specs/00-tech-stack.md`、`docs/specs/05-options.md`）

## Global Constraints

- 回答・文書・コミットメッセージは日本語。呼び名はタイトルとセット（例: deepen-3（最初の一歩は小さく））
- テストの名前（DisplayName / `it` の文）は `deepen-N（タイトル）: …` の形にする。受け入れ基準は deepen-1（選んだ 1 案だけ深める）、deepen-2（業務ごとに照らす）、deepen-3（最初の一歩は小さく）、deepen-4（創るの一歩には需要の確かめを入れる）、deepen-5（うまくいかなくても次へ）、deepen-6（仮の場面での考え方を聞く）
- テストでは Claude を呼ばない。`IDeepenAi` の偽物（`ScriptedDeepenAi`、テストではさらに差し替え）を使う
- 深める AI には、根拠の本人の言葉を渡さない。選んだ案の中身、条件、好み、やりたいこと、主体性だけを渡す
- 問いの答えは `DeepenItem` にだけ保存し、力の状態（`AbilityBookItem`、エピソード）には書かない。答えから人柄や傾向を名づける文を作らない
- 状態の呼び名（根拠あり、要確認、未確認）、点数、順位を画面に出さない。根拠ありは「あなたの話から見えた力」、要確認は「確かめ中」。根拠の本人の言葉は 03 の `QuoteList`（「」と（選んだ答え））で出す
- 使える力でない力は「この業務で使う○○は、まだ確かめていません」と書く。「ない」「不得意」とは書かない
- 使わない言葉（`src/shared/forbidden-words.json`、照らし合わせは `ForbiddenWordList.FirstIn`）、言い切りと順位の言葉（`OptionsValidator.AssertiveIn`）、褒め言葉（`OptionsValidator.PraiseIn`）、お金の額（`OptionsValidator.HasMoneyAmount`）を、AI が書いた深める文に入れない。05 の照らし合わせを使い回し、言葉の一覧を写さない
- 画面の文言は `src/web/src/copy.ts` の `deepen`、AI への指示は `src/Revalue.Server/Ai/Prompts/deepen.md`、コードが決めた一歩の候補は `src/Revalue.Server/Features/Deepen/DeepenText.cs` に置く
- 深める AI: モデルは設定 `Claude__Model`（既定 `claude-opus-5-5`）、構造化出力（`BetaJsonOutputFormat`）、`Effort.High`、`MaxTokens` 16000、`Fallbacks = new Default()` と beta `server-side-fallback-2026-07-01`、システムプロンプトに `CacheControl`。thinking の無効化、`budget_tokens`、`temperature` は送らない（`ClaudeOptionsAi` と同じ形）
- `POST /api/deepen` は `RequireDailyLimit()`（1 日の送信回数に 1 回）。その前に、深めた中身があり対象の指紋が同じなら AI を呼ばずに返すフィルターを置く（`OptionsEndpoints` の POST と同じ形）。ほかの API は AI を呼ばない。どれも `RequireConsent()`
- ログに書いてよいのは、利用者キー、件数、かかった時間、トークン数、止まった理由、照らし合わせで落とした数（部分と規則ごと）、エラーの種類だけ。業務、問い、答え、一歩の中身は書かない
- 文字数は `ProfileEndpoints.FitsIn(text, max, max * 4)`（見た目の文字と、中身の長さ）と `ProfileEndpoints.HasVisibleText` で確かめる。前後の空白は落としてから数える
- 書き換えは、読んだときから変わっていないときだけ書く（ETag。`OptionsStore.UpdateAsync` と同じ形の `DeepenStore.UpdateAsync`）
- progress.md は書き換えない

## Review Focus

1. 深めたあとに、仕事の選択肢の画面で選び直す → 開くと `stale` が true で、画面が 1 回だけ作り直す。前の案の答え、選んだ一歩、書いた一歩は残らない。古い中身への書き換え（答え、一歩、業務）は 409。Task 4 の `RechoosingMakesDeepenStale`
2. 深めたあとに条件を狭める（週 10 時間 → 1 時間、外出できる → 家だけ）→ 収まらない一歩の候補は `fits` が false で、新しく選べない（409）。前に選んでいた候補は選んだまま残る。Task 4 の `NarrowedConditionsHideStepCandidates`
3. AI が、家だけの人に外に出る一歩、週の時間を超える一歩、需要の確かめのない「創る」の一歩を返す → 3 つともコードの候補に置き換わる。Task 2 の `StepsOutsideConditionsFallBack`
4. 問いに答えても、力の状態（見えた力の画面と 5 つの記録のできること）は変わらない。Task 4 の `AnswersDoNotChangeAbilities`
5. 仕事の選択肢で選んだカードの力を外したあとに深める → 業務の照らし合わせは、いまの記録でその力を「まだ確かめていません」と書き、外した力の根拠の言葉を出さない。Task 1 の `ExcludedAbilityIsNotYet`

決まり（Spec の「AI が書いた中身をコードで確かめる」）:
- 業務の見立て（`target.Drafts` のときだけ見る。ほかは AI の業務を捨てて `Tasks = []`）: 2〜4 つ。名前 1〜30、中身 0〜80、知識や道具 0〜60、力が 3 つのどれか、どの文も `TextProblem` に当たらない。一つでも当たれば `Tasks = []`、`TasksRejected = true`、規則を 1 つ返す。id は `t1`、`t2`…
- 問い: 問いごとに、場面 1〜200、選択肢がちょうど 3 つで、どれも 1〜40 で重ならない、力が 3 つのどれかで、対象の業務の「使う力」（`Registered` か、通った見立ての業務の力。見立てが通らなかったら 3 つの力のどれでも）のどれか、どの文も `TextProblem` に当たらない。当たった問いだけを捨てる。通った問いの先頭から 2 つまでを残す。id は `q1`、`q2`
- 一歩の候補: ちょうど 3 つ。することは 1〜100、`Hours` と `Place` が `StepFit.Fits`、`Place` が `home` か `out`、どの文も `TextProblem` に当たらない。`target.Kind == Create` なら `DemandCheck` が 1 つ以上。一つでも当たれば、3 つとも `DeepenText.FallbackSteps(target.Kind)` に置き換え、`StepsFallback = true`、規則を 1 つ返す。id は `s1`〜`s3`（コードの候補は `f1`〜`f3`）
- `DeepenText.FallbackSteps`（文は Claude の判断。どれも 1 時間、家でできる）:
  - 共通: 「この仕事について、知りたいことや気になることを 3 つ書き出してみる」「この仕事をしている人の体験談を、本やウェブの記事で 1 つ読んでみる」
  - 選ぶ、組み合わせる、自分の仕事の 3 つ目: 「この仕事の募集を 2〜3 件読んで、業務の中身と時間の条件を書き出してみる」
  - 創るは、1 つ目を需要の確かめ（`DemandCheck` true）にする: 「身近な知り合い 2〜3 人に、この困りごとがあるか、どんなときに困るかを聞いてみる」。あとの 2 つは共通の 2 つ
- コードの候補は、どの条件でも `StepFit.Fits` を満たす（1 時間、家）。満たすことをテストで確かめる
- `Visible`（Spec の「最初の一歩」。条件を変えたあと）: 中身の候補を順に見て、いまの条件に収まるもの（`Fits` true）と、収まらないが選んでいたもの（`Fits` false、`Chosen` true）を残す。収まらず選んでいない候補は出さない。出した候補のうち `Fits` true が 3 つに満たなければ、`FallbackSteps(kind)` を順に、同じ id がまだないものだけ足して 3 つにする。「創る」で `Fits` の需要の確かめが 1 つもなければ、需要の確かめのコードの候補（`f1`）を最初に足す。`Chosen` は `chosenIds` に id があるか
