# 画面の作り直し（設計）

2026-11-06。開発者との相談で決めたことを、変更の経緯として残す。正しい姿は PRD と Spec に書く。モックは [2026-11-06-screen-redesign-mocks/](2026-11-06-screen-redesign-mocks/) にある（Design キャンバスの書式で、`support.js` がないと開いても崩れる。中の大きさと色を読む参考にする）。

## なぜ

- 使うのは、IT にあまり慣れていない主婦。主にスマホで使い、PC でも使う
- 使う場面は、家事が一通り終わってソファで休んでいるとき（朝、子どもを学校に送り出したあと）と、夜、子どもを寝かしつけたあとの布団の中
- 途中で呼ばれて手が止まる。長い文を書いている途中で画面を閉じる、寝てしまう。どちらも「あるある」（開発者）
- 慣れているアプリは LINE、Instagram、楽天、メルカリ、Amazon。嫌われるのは、業務システムのようにごちゃっとした画面、文字を読むだけの画面、Discord のような専門的な画面（開発者）
- いまの画面は、細い文字、黒と灰色だけの色、縦に並んだボタンと長い説明文で、まさに「文字を読む画面」になっている
- 締め切りの 11/8 20:00 に見せる場では、基本的にすべての画面を見せる。いちばん見せたいのは話す画面（開発者）

## ゴール

1. 話す画面を、LINE のトークのように使える形にする。アプリを開くと、そのままトークが出る
2. 書きかけの文を失わない。閉じても、寝てしまっても、開き直すと残っている
3. 文字は太めの丸ゴシックで読みやすくし、色は 6 色から選べる。夜は暗い画面になる
4. ほかの画面も同じ見た目にそろえ、トークの下のメニュー板から行ける

## やらないこと

- AI の聞き方を変えること（プロンプト、評価）。08 revisit（別の日に話す）も含めない
- ほかの画面（話したこと、見えた力、5 つの記録、仕事の選択肢、選んだ案を深める、可能性レポート、設定）の中身の並びを変えること。見た目をそろえるだけにする
- 声で入力するボタン。スマホのキーボードにあるマイクで足りる（Claude の判断）
- メニュー板の「新着」の印。見たかどうかを覚える仕組みが要るので入れない（Claude の判断）
- 暗い画面を手で切り替えるスイッチ。スマホの設定に合わせるだけにする
- 裏側（API）の変更。いまの API だけで作る（作ってみて足りなければ、作る人が最小の変更で足してよい）

## 失敗とみなすこと

- 診断や採点に見える。点数、割合、チェックの印、「済」の数を出す（ハッカソンのルールと、03-validate の「状態の呼び名やチェック表、点数は出さない」）
- 書いた文が消える。送れなかったとき、閉じたとき、寝てしまったとき
- 新しい話を始める道、ほかの画面へ行く道が見つからない
- 見えた力のカードで、核となる行動と本人の言葉の組が崩れる（芯 1）。読み取りを直す道が見えにくくなる（芯 5）
- つらい状態のサインに応えたあとに、先へ進むことを勧める（芯 2）
- 幅 320px〜1280px のどこかで横にはみ出す。入力欄がキーボードやボタンに隠れて押せない

## 開発者が決めたこと（11/6）

- 案 A の別案（A-4）にする。トークの下にメニュー板を置く。お店の LINE 公式アカウントでよく見る形
- 色は設定で選ばせる。6 色。暗い画面はスマホの設定に合わせる
- 文字は太めの丸ゴシック
- 話す画面は、モックの 3 場面（最初の問い、話している途中、区切ったとき）の形にする
- アプリを開いたら、ホームを通らずにトークがそのまま出る。ホームの画面はなくす
- 入口の 2 画面（案内、はじめる前に）は、モックの短さにする
- ほかの画面は、文字、色、カードの見た目をそろえる程度にとどめる
- PC は、トークを中央、メニュー板を右に置く
- 作る順は、見た目の土台 → 話す画面（ホームをなくすことも含む）→ 入口の 2 画面 → ほかの画面。1 と 2 を先に main に入れ、3 と 4 はそのあとに入れる

## 1. 見た目の土台

### 文字

- M PLUS Rounded 1c。太さは本文 500、見出しとボタン 700、大見出し 800
- npm の `@fontsource/m-plus-rounded-1c` で、アプリの中から配る（Claude の判断）。外のサーバーに読みに行かないため。いまの `@fontsource-variable/geist` は外す
- 本文は 16px、行の高さ 1.7。補足の文字も 12px より小さくしない
- 押すものは、高さ 44px 以上にする

### 色

6 色を、同じ名前の役割（トークン）で持つ。明るい画面の値はモックのとおり。

| 役割 | 使う所 |
|---|---|
| ground | 画面の地 |
| surface | 聞き手の吹き出し、カード、入力のまわり、メニュー板 |
| text / muted | 本文 / 補足の文字 |
| border | 区切りの線 |
| accent / onAccent | 送るボタン、選択肢の枠と文字、アイコン / その上の文字 |
| tint / onTint | 本人の吹き出し、アイコンの丸 / その上の文字 |
| tile | メニュー板のタイル |
| chip | 日付やお知らせの小さな札 |
| field / fieldBorder | 入力欄 |

| 色（設定に出す名前） | 中の名前 | accent | tint | tile |
|---|---|---|---|---|
| あおみどり（いつもの色） | teal | #1F7A6E | #DCEFEA | #EEF5F2 |
| さくら | rose | #B4475A | #FBE4E8 | #FBEEF0 |
| わかば | green | #3A7D2C | #E3F1DC | #EDF4E8 |
| そら | blue | #2F5D9E | #E1EAF7 | #EAF0F9 |
| みかん | orange | #B05A00 | #FCEBD5 | #FBF0E2 |
| ふじ | purple | #6A4FA3 | #ECE6F6 | #F0ECF7 |

- 残りの役割の値は、モック `menutalk.html` の色の表にある
- 暗い画面の値は、作る人が 6 色それぞれに作る。あおみどりの暗い画面は、モック `a-night.html` を参考にする（地 #121517、吹き出し #22272A、本人の吹き出し #1D3B36、accent #6CCBBB）
- どの色でも、明るい画面と暗い画面の両方で、テストでコントラスト比を計算して確かめる（WCAG の AA。Claude の判断）。確かめる組は次のとおり
  - 4.5 以上: text と ground・surface・field、muted と ground・surface、onTint と tint、onAccent と accent、accent と surface（選択肢の文字）
  - 3 以上: 入力欄の枠（fieldBorder と field・surface）、アイコンの accent と tint・tile
  - 対象にしない: 文字のあるボタンの枠（文字でボタンと分かるため）、区切りの線（border）、点線の「それ以外（自分で書く）」の枠
- モックの fieldBorder（白い地に対して約 1.5）は 3 に届かないので、濃くしてよい。モックから外れるのは、この値だけにする（Claude の判断）。「ここで区切る」の枠は、fieldBorder でなく border か muted を使ってよい
- shadcn/ui の変数（`--primary` など）は、この役割から引く。部品ごとに色を書き込まない
- 設定の名前は、「あおみどり」だけ Claude が付けた（Claude の判断）

### 暗い画面

- スマホや PC の設定（`prefers-color-scheme`）に合わせて自動で切り替える。いまの `.dark` の書き方は、この設定で切り替わるように直す

### 色を選ぶ

- 設定の画面に「色」の欄を足す。6 色の丸を並べ、押すとすぐに変わる。名前も添える
- 選んだ色は、その端末のブラウザ（`localStorage`）に残す。サーバーには送らない。アプリが残すのは、見分ける ID と話した内容だけ、という決まりを守るため（Claude の判断）
- 読めないとき（ブラウザが保存を止めているときなど）は、いつもの色で出す。読み書きは失敗しても画面を止めない

## 2. 話す画面

### 開いたときの行き先

- 新しく `/talk`（場面の ID なし）を置く。開くと、次の順で行き先を決める（Claude の判断）
  1. 話している途中の場面があれば、その場面（`/talk/:id`）
  2. 話し終えた場面があれば、いちばん新しく話し終えた場面。区切ったときの形（下の「区切ったとき」）で出す。いちばん新しい場面は、話し終えた時刻で決める。一覧の API に話し終えた時刻がなければ、足してよい（最小の変更）
  3. ただし、2 の場面がつらい状態のサインに応えたところで終わっていたら、その会話を出さない。開くたびに打ち明けた内容を見せないため（revisit-7（つらい話を持ち出さない）と、いまのホームがこのとき会話を見せていないことに合わせる）。代わりに、場面のないトークに、聞き手の側から「また話したくなったときに、いつでも始められます。」を出し、目立たせない「別の日のことを話す」だけを置く。押したときに始まる場面の入口は、いまの決まり（つらい状態のサインのあとの入口）のまま。前の場面は「話したこと」から開ける（Claude の判断）
  4. どれもなければ、新しい場面を始めて、最初の問いを出す
- ログインして了解した人が案内（`/`）を開いたら、`/talk` へ送る。開いたらトークが出る、という決定を、ブックマークやホーム画面のアイコンから開いたときにも守るため。了解していなければ、はじめる前にへ送る。案内は、ログインしていない人に見せる（Claude の判断。見せる場で、ログインしたまま案内を見せたいときは、ログアウトするか別のブラウザで開く）
- `/home` は `/talk` へ送る（古いリンクを生かすため）。了解したあと、ほかの画面の「トークに戻る」の行き先も `/talk` にする。設定の「全部消す」のあとは、了解も消えるので、いまのまま、はじめる前にへ進む
- トークに出すのは、いま開いている 1 つの場面だけにする。前の場面は「話したこと」で見る（Claude の判断）
- 「話したこと」から開いた前の場面（`/talk/:id`）も、同じトークの形で出す。区切ったときのカードと「次は、どれにしますか？」のボタンも、いまの話す画面と同じく、どの話し終えた場面にも出す。つらい状態のサインに応えたところで終わった場面かどうかは、その場面で見る（いまの話す画面と同じ。Claude の判断）

### いつも出すもの

- 上の帯: 聞き手のアイコン、「聞き手」、その下に「最近の一日の話」。話す画面の上の帯は、左上の「RE:VALUE」の代わりになる（Claude の判断）
- 場面の始まりに、日付の札（例: 11月6日（木））
- 吹き出し: 聞き手は左に surface、本人は右に tint。訂正の言葉は、いまの CorrectionBox の役目のまま、トークの中に出す
- 返事を書いているあいだは、聞き手の側に「返事を書いています…」の吹き出しを出す
- 画面の下に、入力の帯とメニュー板を重ねて置く（下の「入力の帯」「メニュー板」）。トークだけが上下に動き、入力の帯はいつも見える

### 最初の問い（モック `talkopen.html`）

- 最初の問いの選択肢 9 つは、2 列の格子に並べる。最後のマスに「それ以外（自分で書く）」を点線の枠で置き、押すと入力欄へ移る
- 飛ばしたあとや、つらい状態のサインのあとの入口の選択肢、AI が出す答えの例（3 つ）も、同じ見た目のボタンにする。4 つ以下なら、折り返して横に並べる（Claude の判断）
- 選んだ言葉は、そのまま本人の吹き出しになる（いまと同じ）

### 話している途中（モック `talkmid.html`）

- 入力欄のすぐ上に「ここで区切る」と「この話は飛ばす」を置く。最初の問いのところでも出す（discover-5（つらい話は飛ばせる）の「いつでも押せる」を守る。モック `talkopen.html` にはないが、足す。Claude の判断）。「この話は飛ばす」を押したときの確かめ（「このやりとりは残さずに、別の話にしますか？」）は、いまと同じく画面の中で聞く。どちらの答えも目立たせない
- つらい状態のサインに応えたときの案内と選択肢、使いすぎのお知らせ、うまく返事を作れなかったときの言葉は、トークの中にカードで出す。言葉はいまのまま

### 書きかけを残す

- 入力欄に書いた文は、書くそばからその端末のブラウザに残す。場面ごとに分けて持つ（Claude の判断）
- 開き直すと、入力欄に戻す。書きかけがあるあいだは、入力欄の下に「書きかけは残っています。閉じても、続きから書けます」と小さく出す
- 送れたとき、場面を区切ったとき、飛ばしたときに消す。ログアウトと「全部消す」のときは、その端末の書きかけをすべて消す（Claude の判断）
- 送れなかったときは消さない（いまの「書いた答えはそのまま残しています」と合わせる）
- 読み取りを直す欄の書きかけは、残さない（Claude の判断）

### 区切ったとき（モック `talkend.html`）

- 「ここで区切りました」の札を出し、その下に、見えたことをトークの中のカードで出す。中身は、いまの Insights と同じ（03-validate の「話し終えたとき」）
  - 先頭に、AI の読み取りであることと、直せること
  - この話から見えた力: 力の名前と、核となる行動と本人の言葉の組
  - もう少し聞かせてほしいこと: 本人の言葉と手がかり
  - カードの中に「読み取りを直す」「この場面の続きを話す」（続きを話せるときだけ）「見えた力をまとめて見る」。読み取りを直す欄は、カードの中で開く
- カードのあとに、聞き手の側に「この場面の話は、ここで一区切りです。次は、どれにしますか？」を出し、答えの例と同じ形のボタンを並べる（言葉は Claude の判断）
  - 次にできること（`GET /api/next-step`）が、話すことと続きを話すこと以外なら、そのボタン（言葉は 00-common の表のまま）
  - 「別の日のことを話す」（新しい場面を始める）。どこまで進んでも、別の一日を話して力を足せるようにするため
  - 「今日はここまで」。押すと、聞き手の側に「おつかれさまでした。また話したくなったら、ここから続けられます。」を出し、ボタンを閉じる。何も保存しない。開き直すと、またボタンが出る（Claude の判断）
- つらい状態のサインに応えたところで終わった場面では、「次は、どれにしますか？」もボタンも出さない。相談先の案内のあとに、目立たせない「別の日のことを話す」だけを置く。いまのホームが、このとき「画面の一覧」と「話す」だけを出しているのと同じ扱い（Claude の判断）

### 入力の帯

- 入力欄（角の丸い 1 行から、書くと広がる）と、丸い「送る」ボタン。いまの文字数の上限、送っているあいだの止め方は変えない
- 話し終えた場面では、入力の帯を出さない

### メニュー板（モック `menutalk.html`）

- 6 つのタイルを 3 列 2 段に並べる。話したこと（`/episodes`）、見えた力（`/abilities`）、5 つの記録（`/profile`）、仕事の選択肢（`/options`）、まとめ（`/report`）、設定（`/settings`）
- 「選んだ案を深める」はタイルにしない。仕事の選択肢の画面と、次にできることのボタンから行く（Claude の判断）
- スマホでは、初めはたたんだ形（「▲ メニューを開く」の帯）で出す。押すと開き、「メニューをたたむ ▼」でたたむ。入力欄に文字を打っているあいだは隠す（キーボードとぶつからないように）。開いたかどうかは覚えない（Claude の判断）
- PC（幅 1024px 以上が目安）では、トークの右に縦に並べ、いつも出す

### PC

- トークの列は、読みやすい幅（640px 前後）にして中央に置き、右にメニュー板を置く

## 3. 入口の 2 画面

### 案内（モック `landing.html`）

- 上から、RE:VALUE（リバリュー）、ひとこと（「キャリアには空白があっても、人生に空白はない。」）、説明 1 文、約束 3 つ、ログインのボタン、進め方 1 行
- 約束は、題と 1 行にする。言葉はモックのとおり（Claude の判断。確かめる項目）
  - あなたの言葉が根拠です: 見えた力には、話した言葉をそのまま添えます
  - 決めるのはあなたです: 見立ては直せます。仕事も自分で選べます
  - 安心して話せます: 名前もメールアドレスも残しません
- ログインのボタンは、親指の届く画面の下に置く。ログインした人は案内を開くと先へ送られる（上の「開いたときの行き先」）ので、「続きから」のボタンは、送るまでのあいだの出口として残すだけでよい（Claude の判断）
- 「本人の言葉を根拠にする」「本人が選び、直せる」を先に伝える決まり（01-foundation の案内）は、約束の 1 つ目と 2 つ目で守る

### はじめる前に（モック `startshort.html`）

- いまの 5 項目を、短い 4 行にまとめる。言葉はモックのとおり（Claude の判断。確かめる項目）
  - 残すのは、話した内容と、そこから作るものだけです
  - 名前とメールアドレスは残しません
  - 返事や見立てを作るときだけ、AI（Anthropic の Claude）に送ります。開発者も読みません
  - 30 日使わないと自動で消えます。いつでも全部消せます
- 「くわしく読む」で、いまの 5 項目の全文を開く。全文の言葉は変えない。閉じていても、全文はページの中にある形（`<details>` など）にする。foundation-2（始める前に保存するものを示す）の確かめ方を変えずに済ませるため（Claude の判断）
- 「了解して始める」を下に大きく置く。了解しない人の出口「了解せずにやめる（ログアウト）」は、その下に目立たせずに残す
- 了解したら `/talk` へ進む（新しい場面の最初の問いが出る）。全部消したあとに来たときの「全部消しました…」も、いまのまま出す

## 4. ほかの画面

- 話したこと、見えた力、5 つの記録、仕事の選択肢、選んだ案を深める、可能性レポート、設定
- 文字、色、カード（surface の地、角の丸み、余白）、ボタンの見た目を、話す画面とそろえる。中身の並びと言葉は変えない
- 上の帯は「← トークに戻る」と画面の名前にする。左上の「RE:VALUE」の代わりになる（Claude の判断）
- 各画面の下の「ホームへ戻る」は「トークに戻る」に変え、`/talk` へ行く。各画面の下の次にできることへの道は残す
- メニュー板は、話す画面にだけ置く。LINE でメニューから開いたページと同じく、戻ってからほかへ行く（Claude の判断）
- PC では、中央に寄せた 1 列にする

  - `02-discover.md`: 話す画面の振る舞い（開いたときの行き先、選択肢の並べ方、書きかけ、区切ったとき、メニュー板）
  - `03-validate.md` 〜 `07-report.md`: ホームに触れている所
  - 画面の見た目の決まり（文字、色の役割、6 色、暗い画面、色を選ぶ）は、`00-common.md` の「画面」に 1 か所だけ書く
- ペルソナ評価: `evals/personas/how-to-judge.md` と人物ファイルで「ホームから」と書いた所を、「開くと」「トークから」に直す
- Spec とコードは同じコミットで変える

## 6. 作る順

| 順 | 中身 | main に入れる単位 |
|---|---|---|
| 1 | 見た目の土台（文字、色の役割と 6 色、暗い画面、色の値を確かめるテスト） | PR 1 |
| 2 | 話す画面（開いたときの行き先、ホームをなくす、選択肢、書きかけ、区切ったとき、メニュー板、PC） | PR 1 |
| 3 | 入口の 2 画面 | PR 2 |
| 4 | ほかの画面をそろえる、設定の「色」 | PR 2 |

- PR 1 を先に main に入れてデプロイする。PR 2 はそのあと
- 確かめ方
  - 画面のテスト（Vitest）。ホームのテストは、`/talk` の行き先と、区切ったときのボタンのテストに移す
  - 実際のブラウザ（Playwright）で、幅 320px、375px（高さ 667px と 812px）、1280px を見る。横にはみ出さないこと、入力欄が見えて押せること、明るい画面と暗い画面の両方
  - ペルソナ評価が新しい画面で最後まで通ること（PR 2 のあと。回すかは開発者が決める）

## 7. 作る人に任せること

- 部品の分け方、ファイルの置き場所、名前
- 暗い画面の色の値（コントラストの決まりの中で）
- PC に切り替える幅の細かい値、トークの列の幅
- アイコン（いまある lucide-react を使ってよい）、角の丸みや影の細かい値
- 書きかけを残す間隔（打つたびでも、少し待ってからでもよい）

## 8. 開発者に確かめてもらう言い方

- 話す画面: 「次は、どれにしますか？」「別の日のことを話す」「今日はここまで」「おつかれさまでした。また話したくなったら、ここから続けられます。」「書きかけは残っています。閉じても、続きから書けます」「それ以外（自分で書く）」「トークに戻る」
- つらい状態のサインで終わったあとに開いたときの「また話したくなったときに、いつでも始められます。」（芯 2（突き放さない）にかかるので、voice-reviewer でも点検する）
- 案内の約束 3 つの 1 行
- はじめる前にの 4 行
- メニュー板の「まとめ」（画面の名前は「可能性レポート」のまま）
- 色の名前「あおみどり」
