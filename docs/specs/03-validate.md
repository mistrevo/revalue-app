# 03 validate（確かめる）

## 目的

話した出来事の中の本人の言葉を根拠に、3 つの力を確かめる。力ごとに決めた核となる行動が 3 つとも、一つの出来事の中でそろったときだけ、「この話から見えた力」として示す。足りない行動は、会話の中で聞き返す。本人は、AI の読み取りを直し、見立てを外せる。

達成するユースケースは「力を確かめる」（[2-usecases.md](../prd/2-usecases.md)）。力を確かめる物差しは [4-rules.md](../prd/4-rules.md)、言葉と対話とデータの決まりは [00-common.md](00-common.md)、技術の決まりは [00-tech-stack.md](00-tech-stack.md) にある。[02-discover.md](02-discover.md) で作った会話の流れに、確かめの仕組みをつなぐ。

## 振る舞い

### 力と核となる行動

見る力は 3 つ。力ごとの核となる行動は [4-rules.md](../prd/4-rules.md) のとおり。コードでは次の呼び名を使う（Claude の判断）。

| 力 | 呼び名 | 核となる行動 |
|---|---|---|
| 見立てる力 | `noticing` | 1 変化に自分で気づく、2 判断の手がかりを挙げる、3 いつもの様子や前と比べる |
| 調整する力 | `coordinating` | 1 都合の違う 2 者以上が関わる、2 本人から働きかける、3 代わりの案を出すか、双方の都合を合わせる |
| 優先順位をつける力 | `prioritizing` | 1 全部はこなせないほど用事が重なる、2 何を先にし、何を後に回すかを具体的に決める、3 決めた理由や基準がある |

### 1 往復の中の確かめ

02 discover（話す）の 1 往復（読み取り → 次の一手 → 返事）のうち、読み取りに確かめを足す。AI を呼ぶのは 1 往復で 2 回のまま（Claude の判断）。

1. **読み取り**: AI は、答えの種類（[02-discover.md](02-discover.md)）に加えて、力ごとに核となる行動が見つかったかを返す。探すのは、その場面のやりとり全体。見つかった行動には、根拠になる本人の言葉を添える。あわせて、それが何番目の答えか、何番目の出来事の中か、一般論として話されたかも返す。出来事の番号は AI が読み取りのたびに振り直すので、その読み取りの中でだけ意味を持つ
2. **照らし合わせ**: コードが、AI の返した根拠を確かめる。下の「根拠として使える言葉」に当たらないものは捨てる
3. **状態を決める**: コードが、場面ごとに力の状態を決める
4. **次の一手**: 足りない行動があれば、それを一つ聞く一手をコードが選ぶ（下の「次の一手」）

確かめの結果は、返事を最後まで受け取れたときに、答えと返事と一緒に場面に保存する。読み取りに失敗したときは、02 discover（話す）と同じく何も保存しない。

会話の途中では、前の往復で確かめた根拠を残し、新しく見つかった根拠を足す。AI の読み取りが往復ごとに揺れても、話している最中に見立てが行ったり来たりしないようにするため。場面全体を読み直した結果で置き換えるのは、訂正のときだけ（Claude の判断）。

根拠には、どの読み取りで見つかったかの印を付け、別の読み取りの根拠とは同じ出来事として混ぜない。番号の振り方が変わると、別の日の行動が同じ番号にそろってしまうため。前の読み取りの出来事のうち、中身がすべて新しい読み取りのある出来事に含まれるものは、残さない（状態と見せる根拠は変わらない。Claude の判断）。

### 根拠として使える言葉

[00-common.md](00-common.md) の「対話」に従い、次のように作る。

- 本人の答えに、一字一句そのまま含まれる言葉だけを使う。コードで照らし合わせ、含まれなければ捨てる
- 空白と句読点・記号を除いて 4 文字に満たない言葉は、含まれていても捨てる。「て」のような 1 文字の助詞など、それだけでは意味の分からない言葉で根拠ありにしないため。一字一句の照らし合わせだけでは、AI がどの行動にも同じ短い言葉を返したときに防げない（Claude の判断）
- 一つの出来事の中で、同じ力の 3 つの行動の引用が、そのうち 1 つの引用の中にすべて収まるときは、ほかの 2 つを含む引用を数えない（同じ行動に別の部分の根拠があれば、そちらを数える）。一つの句を AI が切り分けて 3 つの行動に当てると、行動がそろっていないのに根拠ありになるため。次の一手も、この数え方で足りない行動を決める（validate-1（3 つともそろったときだけ根拠あり）。Claude の判断）
- 選択肢を選んだ答えは、それだけでは根拠にしない。本人が自由に書いたほかの答えから、AI が結びつく言葉も添えたときだけ使う。添えた言葉も一字一句照らし合わせ、長さも同じく見る（validate-5（選んだだけでは根拠にしない））
- 結果の良し悪しや、結果を話したかどうかは、根拠の条件にしない（validate-3（結果で見立てを変えない））
- 本人の訂正（下の「訂正」）も、本人の言葉として使える
- つらい状態のサインが出た場面（力の確かめに使わない印が付いた場面）は、確かめに使わない

### 力の状態

場面ごとに、力の状態を次のように決める（[4-rules.md](../prd/4-rules.md)）。

| 状態 | コードでの決め方 |
|---|---|
| 根拠あり | 同じ出来事の中で、一般論でない根拠が 3 つの行動すべてにそろった。同じ出来事かどうかは、一回の読み取りの中で見る |
| 要確認 | 根拠のある行動が一つ以上あるが、根拠ありには届かない。一般論として話された行動だけのときも、ここに入れる |
| 未確認 | 根拠のある行動がない |

利用者ごとの力の状態（「見えた力」）は、確かめに使える場面すべてのうち、いちばん進んだ状態にする。根拠は、その状態になった場面のうち新しいものから取る。仕事での発揮は、いつも「まだ確かめていない」とする（validate-9（生活での根拠と仕事での発揮を分ける））。

利用者ごとの力の状態が変わるたびに、履歴を 1 件残す。履歴には、いつ、どの力が、どの状態からどの状態へ変わったかと、変わった理由を持つ。理由は次の 6 つのどれか。

- 話した内容から確かめた
- 訂正を受けて確かめ直した
- やりとりを残さずに別の話にした（場面ごと残さないときと、続きで足したやりとりだけを残さないときの両方）
- 本人が外した
- 本人が戻した
- つらい状態のサインが出て、その場面を確かめに使わないことにした（Claude の判断）

場面を残さずに飛ばして消したときは、その場面の「つらい状態のサインが出て、その場面を確かめに使わないことにした」履歴を残さない。サインの出た時が、本人が残さないと選んだ場面のあとに残らないようにするため。その行のぶんの状態の移り変わりは、「場面を残さずに別の話にした」として残し、その行のあとの外す・戻すの履歴は、その行がなかったときの状態に書き直す。履歴の前と後がつながるようにするため（Claude の判断）。続きを話している場面を飛ばしたときは、場面が残るので、その履歴も残す。

### 次の一手

02 discover（話す）の次の一手に、「足りない行動を一つ聞く」を足す。優先の順は次のとおり（Claude の判断）。

つらい状態のサイン → 締め（往復の上限） → 家族の病気の話 → 続きの問いに「その日のほかのことを話したい」を選んだ（同じ日のほかのことを聞く） → **足りない行動を一つ聞く** → 具体的な出来事がある → 分からない・何もない → 一般論だけ

- 「足りない行動を一つ聞く」を選ぶのは、いまの答えが具体的な出来事のとき、または、いまの答えから一般論でない根拠が見つかったときに限る。一般論だけ・分からない・何もないの答えには、02 discover（話す）の一手を使う。一般論には具体的な出来事を聞き（validate-10（一般論には具体的な出来事を聞く））、「分からない」の人を問い詰めないため（Claude の判断）
- そのうえで、いまの答えの出来事の中に要確認の力があるときに選ぶ。いまの答えの出来事は、いまの答えから見つかった根拠の出来事で、なければいちばん新しい読み取りの、いちばん新しい出来事とする。そろっている行動がいちばん多い力（同じ数なら見立てる力、調整する力、優先順位をつける力の順）を選び、その力の足りない行動を聞く。足りない行動が複数あれば、この場面でまだどこにも根拠のない行動を先に、同じなら番号の小さいものを聞く。読み取りが前の答えの行動を落としたとき、本人がもう話したことを聞き直さないため（Claude の判断）
- 場面ですでに根拠ありの力は聞かない。いまの出来事でその力の行動が欠けていても、聞かずに次の力か、02 discover（話す）の一手へ移る。新しい読み取りが同じ出来事の行動を落としたとき、そろった力の行動を聞き直さないため（Claude の判断）
- 同じ場面で同じ行動を聞くのは 2 回までにする。続きを話すときの問い（下の「続きを話す」）も数に入れる。訂正で打ち消された行動（下の「訂正」）と、続きの問いに「とくに思い当たりません」を選んだ行動は、2 回聞いたものとして扱う。2 回聞いても見つからなければ、ほかの行動か、02 discover（話す）の一手へ移る。問い詰めないため（Claude の判断）
- 一般論だけの話には、具体的な出来事を一つ聞く（02 discover（話す）の一手のまま。validate-10（一般論には具体的な出来事を聞く））
- 力の確かめに使わない印（つらい状態のサイン）が付いた場面では、そのあと「続けて話す」を選んでも、根拠を照らし合わせず、足りない行動も聞かない。02 discover（話す）の一手だけを使う。打ち明けたあとの人に、確かめのための問いを重ねないため（Claude の判断）
- 聞き手の AI には、核となる行動の一覧を渡さない。渡すのは、聞く行動を普通の言葉にした手がかり（下の表）だけ。答えの例で、その行動を正解のように並べない

手がかりの言葉は、画面の「もう少し聞かせてほしいこと」にも使う（Claude の判断）。画面では前の文脈なしに並ぶので、「そう」のように前を指す言葉やかっこ書きを使わず、それだけで意味が通る形にする。

| 行動 | 聞き手への手がかり |
|---|---|
| 見立てる力 1（変化に自分で気づく） | いつもと違うことに、自分で気づいたこと |
| 見立てる力 2（判断の手がかりを挙げる） | 何を見たり聞いたりして、いつもと違うと思ったか |
| 見立てる力 3（いつもの様子や前と比べる） | いつもの様子や、前のときと比べたこと |
| 調整する力 1（都合の違う 2 者以上が関わる） | ほかに関わっていた人と、その人たちの都合 |
| 調整する力 2（本人から働きかける） | あなたから声をかけたり、頼んだりしたこと |
| 調整する力 3（代わりの案を出すか、双方の都合を合わせる） | みんなの都合を合わせたり、別の案を出したりしたこと |
| 優先順位をつける力 1（全部はこなせないほど用事が重なる） | その日に重なっていた用事 |
| 優先順位をつける力 2（何を先にし、何を後に回すかを具体的に決める） | 何を先にして、何を後に回したか |
| 優先順位をつける力 3（決めた理由や基準がある） | 先にすること、後に回すことを、どう考えて決めたか |

### 話し終えたとき

場面を区切ったとき（締めの返事のあと、または「ここで区切る」）、話す画面の下に、その場面から見えたことを出す（validate-7（見えた力と、もう少し聞きたいことを示す））。区切ったあとは、ホームへ戻らず、この画面に留まる（Claude の判断）。

見えたことの先頭には、話した言葉から読み取ったものであることと、違っていれば「読み取りを直す」から直せることを一文で添える。判定の結果のように見せないため（Claude の判断）。

- **この話から見えた力**: 根拠ありの力。力の名前と、根拠の本人の言葉を「」で囲んで一字一句そのまま出す。選択肢を選んだ答えは「（選んだ答え）」と添え、結びついた本人の言葉と並べる（validate-4（根拠は本人の言葉））。同じ言葉が複数の行動の根拠になっていても、一度だけ出す（Claude の判断）
- **もう少し聞かせてほしいこと**: 要確認の力。見つかった行動の根拠と、足りない行動の手がかり（上の表）を出す。手がかりの前置きは「もし覚えていることがあれば、こんなことも聞かせてください」とし、していて当然のことの一覧に見せない。根拠が一般論だけの力には、足りない行動ではなく「いつものことの中から、最近のある一日の出来事」だけを出す（validate-10（一般論には具体的な出来事を聞く））。訂正で打ち消された行動の手がかりは出さない（下の「訂正」）。添える手がかりがないときは、聞き返さずに「思い出したことがあれば、続きを話せます。」とだけ出す。「この場面の続きを話す」を添える（どれも Claude の判断）
- **まだ聞けていない力**: 未確認の力の名前だけ。「まだ聞けていない」は力がないという意味ではないと添える
- 状態の呼び名と、核となる行動のチェック表の扱いは、[00-common.md](00-common.md) の「言葉」に従う。この画面では前面に出さず、点数や順位も出さない（validate-6（否定の言葉を使わない））

### 訂正

- 話し終えた場面の「見えたこと」の下に、「読み取りを直す」を置く。押すと、どこが違うかを自由に書く欄が出る（Claude の判断）
- 書く欄の例は、自分のした行動を足す向きを先に、取り下げる向きと並べる。取り下げる向きだけだと、自分の手柄を減らすための欄に見え、自分を低く言う方へ誘いやすいため（Claude の判断）
- 送った訂正は、その場面に本人の答え（訂正）として足し、AI がその場面を読み直す。訂正は前の発言より優先する（AI への指示に書く）
- やりとりの中では、訂正を本人の答えの吹き出しと分け、「あなたが読み取りを直した言葉」という見出しを付けた枠だけの囲みで、右寄せで出す。訂正には返事を作らないので、答えに AI が返事をしなかったように見せないため（Claude の判断）
- 読み直して状態が変わった力は、履歴に「訂正を受けて確かめ直した」として残す（validate-8（訂正したら確かめ直す））
- 読み直して根拠が消えた行動（訂正で打ち消された行動）は、訂正のターンに印を残す。本人が訂正で答えたばかりのことなので、続きの問い、足りない行動を聞く一手、「もう少し聞かせてほしいこと」と見えた力の画面の手がかりで聞き直さない。読み取りが訂正と関係なく落とした行動も入るが、どれも本人がもう話した行動なので、聞き直さない側に倒す。手がかりは、後回しにしても、足りない行動がそれだけのときは同じものが出るので、出さない（Claude の判断）
- 訂正にも送信回数の上限をかける。訂正の中につらい状態のサインがあれば、02 discover（話す）と同じ言葉と相談窓口を出す。その場面には、力の確かめに使わない印を付ける
- 読み直しに失敗したときは、書いた訂正を入力欄に残し、穏やかな言葉「うまく読み直せませんでした。書いた言葉はそのまま残しています。少し待ってから送り直すことも、「やめる」でいまの読み取りのままにしておくこともできます。」を出す。不調のときも AI が断ったときも同じ言葉にする。訂正では返事を作らないので、話す画面の返事の失敗の言葉は使わない。話し終えた場面には「この話は飛ばす」がないので、飛ばす道も示さない。読み取りの失敗はつらい状態のサインを見落としているかもしれないので、02 discover（話す）と同じく、相談窓口の添え書きを小さく出す（Claude の判断）

### 続きを話す

- 要確認の力がある、話し終えた場面は、「この場面の続きを話す」で続きを話せる（validate-11（要確認の場面に戻れる））。話している途中の場面がほかにあれば、そちらを開く（1 人 1 つまで。[02-discover.md](02-discover.md)）
- 続きは、コードが決めた問いで始める。[4-rules.md](../prd/4-rules.md) の「対話の決まり」のとおり、決まった受け止めの一文「続きの話を選んでくれて、ありがとうございます。」、本人の言葉の映し返し「前に「…」と話してくれましたね。」、足りない行動ごとに決めた問い一つ、の順にする。問いは、映し返した言葉の日を「その日」で指す（Claude の判断）
- 受け止めの一文は、区切った直後に押しても、日をおいて戻っても合うよう、「また」「来てくれて」のように時間を前提にした言い方をしない。問いは後ろの一つだけにするので、受け止めの一文では何も求めない（Claude の判断）
- 映し返す言葉は、聞く力の見せる根拠（聞く行動がなければ、要確認の力すべての見せる根拠）のうち、一般論でないものを先に、いちばん短いもの。選んだ答えの根拠なら、結びついた本人の言葉。一字一句そのまま「」で囲むが、文末の句読点だけは外す（保存した根拠は変えない）。根拠がなければ、映し返しの代わりに「前に話してくれた日のことです。」と書き、問いの「その日」が指す日を示す（Claude の判断）
- 行動ごとの問いは、本人がその行動をしたことを前提にせず、「ありましたか」「いましたか」で聞き、一度に一つだけ求める。例: 調整する力 2（本人から働きかける）なら「その日、だれかに声をかけたり、頼んだりしたことはありましたか？」。「考えて決めたか」のように、考えたかどうかを疑う聞き方はしない。「なかった」と答えると、確かめている力を自分で打ち消すことになるため。優先順位をつける力 3（決めた理由や基準がある）は「その日、どれを先にするか決めるときに、気にしていたことはありましたか？」と聞く。9 つの文は `AbilityText.cs` に置く（Claude の判断）
- 選択肢は「思い当たることがあります」「とくに思い当たりません」「その日のほかのことを話したい」の 3 つ。どの問いにも自然な答えになるよう、問いの形をそろえる。していないことを、値打ちを下げずに言える答えを入れる（Claude の判断）
- 続きの問いで次の選択肢を選んだときは、次のように扱う。働くのは、選んだ答えで、直前の問いが続きの問いのときだけ。同じ言葉を書いた答えでは働かない。言葉は選択肢と一字一句同じかで見る（Claude の判断）
  - 「とくに思い当たりません」: その問いで聞いた行動を、この場面で 2 回聞いたものとして扱い、聞き直さない（上の「次の一手」と、次の続きの問いでも）
  - 「その日のほかのことを話したい」: 次の一手は、足りない行動ではなく、同じ日のほかの時間や出来事を一つ聞く一手にする。前の出来事の行動は聞き直さない。選んだ答えには映し返す行動がないので、受け止める一文と問いだけにする。つらい状態のサイン、締め、家族の病気の話は、これより先
- 聞く行動は、要確認の力のうち、そろっている行動の多い力（同じ数なら見立てる力、調整する力、優先順位をつける力の順）の足りない行動で、選び方は「次の一手」と同じ。根拠が一般論だけの力は、指せる「その日」がないので除く。この場面ですでに 2 回聞いた行動と、訂正で打ち消された行動は避けて次を選ぶ。聞ける行動が残っていなければ、受け止めの一文と映し返しのあとに「その日のことで、ほかに覚えていることはありますか？」と聞く。同じ行動を 3 回聞かないため（Claude の判断）
- 要確認の力がどれも一般論だけのときは、「その日」を前提にせず、一般論の映し返しのあとに「特別な日でなくてかまいません。いつものことの中から、いちばん最近の一日のことを、聞かせてもらえますか？」と聞く。「毎週同じで、この日というのは浮かばない」人がつまずかないよう、特別な日でなくてよいことを先に伝え、日を選ばせない。選択肢は「今週のことを話したい」「先週のことを話したい」「すぐには浮かばない」（validate-10（一般論には具体的な出来事を聞く）。Claude の判断）
- 区切る前の最後の問いに答えていないときは、同じことを聞く問いを続けて出さない。最後の問いが足りない行動を聞いていたら、続きの問いではその行動を選ばず、次の行動を選ぶ（なければ手がかりを添えない問い）。答えずに区切ったのは答えにくかったからかもしれないので、すぐには聞き直さない。その行動も、続きの中でいつもの決まり（同じ行動は 2 回まで）で聞くことがある。足りない行動を聞いていたかを見るとき、最後の問いのあとの訂正は数えない。最後のターンが続きの問い（続きを開いて、答えずにまた区切った）なら、問いを足さず、その問いから続ける。そのあとに訂正していたら、訂正を読んだうえで新しい続きの問いを足し、前の続きの問いの行動は選ばない。訂正で打ち消された行動を聞き直さないため。この場合も、続けた場面を飛ばすと、その問いを含む前に話し終えていた姿に戻る（Claude の判断）
- 続きを話すときは、往復の上限を 4 つ増やす（Claude の判断）
- 続きを話している場面で「この話は飛ばす」を選ぶと、場面ごとは消さない。続きで足したやりとりと根拠だけを残さず、続きを話す前の話し終えた姿に戻してから、別の話を始める。前に話し終えていた分は、飛ばす前の確かめ「このやりとりは残さずに、別の話にしますか？」の外にあるため。続きの中でつらい状態のサインが出て付いた、力の確かめに使わない印は残す（安全な側。Claude の判断）
- エピソードの一覧でも、続きを話せる場面に「もう少し聞かせてほしいことがあります」と添える

### 見えた力の画面

- 画面の先頭で、話した出来事の中の本人の言葉をもとにしていること、違うところはその話を開いて直せること、見立ては外したり戻したりできること、をこの順で伝える。外すか受け入れるかの二択に見せないため（Claude の判断）
- 3 つの力ごとに、「生活の中で」と「仕事で」を分けて出す（validate-9（生活での根拠と仕事での発揮を分ける））
  - 生活の中で: 「あなたの話から見えた力」「もう少し聞かせてほしいこと（確かめ中）」「まだ聞けていない」のどれかと、根拠の本人の言葉、その場面へのリンク
  - 仕事で: いつも「まだ確かめていません」
- 力ごとに「この見立てを外す」を置く。外した力は、仕事の選択肢のカードの理由と、可能性レポート（確かめた力、選んだ案、最初の一歩をまとめたもの）に使わない。外したあとも「戻す」で戻せる。どちらも履歴に残す（validate-12（本人が見立てを外せる））
- 履歴（いつ、どの力が、どう変わったか、なぜ）を、新しい順に出す。日時は日本時間。状態は画面の言葉（見えた、確かめ中、まだ聞けていない）で書く
- つらい状態のサインで場面を確かめに使わなくなった履歴は、状態の移り変わりを書かず、「話してくれた場面の一つを、力を確かめる話には使わないことにしました。話した内容は、そのまま残っています」とだけ出す。打ち明けた直後に、見立てが下がったと読める行を出さないため。外す・戻すも、理由だけを出す（Claude の判断）。この履歴は場面が残っているときだけあり、場面を残さずに飛ばすと消える（上の「力の状態」）

### API

すべてログインと了解が要る（[01-foundation.md](01-foundation.md)）。AI を呼ぶ API には、送信回数の上限（foundation-6（使いすぎを穏やかに止める））を付ける。

| メソッドとパス | AI | 返すもの |
|---|---|---|
| `GET /api/episodes/{id}` | 呼ばない | 02 discover（話す）の中身に、「見えたこと」（見えた力と根拠、もう少し聞かせてほしいこと（根拠と手がかり）、まだ聞けていない力、続きを話せるか）を足す。見えたことは、話し終えた場面で、力の確かめに使わない印がないときだけ入れる |
| `GET /api/episodes` | 呼ばない | 02 discover（話す）の中身に、場面ごとの「続きを話せるか」を足す |
| `POST /api/episodes/{id}/corrections` | 呼ぶ（上限あり） | 訂正（長さは 02 discover（話す）の答えと同じ上限）を受け取り、場面全体を読み直して、見えたことを含む場面を返す。話し終えた場面だけ。話している途中なら 409（いまの状態ではできないと知らせる応答。その場面の id 付き）、力の確かめに使わない印のある場面も 409。AI が失敗したか断ったときは 503 と、どちらだったかと、念のための相談窓口を返し、何も保存しない |
| `POST /api/episodes/{id}/resume` | 呼ばない | 場面を話している途中に戻し、続きの問いを足して返す（最後のターンが答えていない続きの問いなら、足さずにその問いから続ける）。要確認の力がない場面、力の確かめに使わない場面は 409。その場面がまだ話している途中か、ほかに途中の場面があれば 409（その場面の id 付き） |
| `GET /api/abilities` | 呼ばない | 3 つの力の、生活の中での状態と根拠、根拠の場面、確かめ中なら手がかり、仕事での状態、外したか。履歴（新しい順） |
| `POST /api/abilities/{name}/exclude` | 呼ばない | その力の見立てを外し、`GET /api/abilities` と同じものを返す。`{name}` は `noticing`、`coordinating`、`prioritizing` のどれか（ほかは 404） |
| `POST /api/abilities/{name}/restore` | 呼ばない | 外した見立てを戻し、`GET /api/abilities` と同じものを返す |

- 1 往復の保存、訂正、飛ばすのたびに、利用者ごとの力の状態を、保存してある場面から計算し直す。計算し直しに失敗しても、その操作は成功のままにする（Claude の判断）。保存は、読んだときから変わっていないときだけ書く（[02-discover.md](02-discover.md) と同じ）。つらい状態のサインで場面に印が付いた往復と訂正では、履歴の理由を「その場面を確かめに使わないことにした」にする
- `POST /api/episodes/{id}/skip`（[02-discover.md](02-discover.md)）は、続きを話している場面なら、場面を消さずに続きを話す前の姿に戻す（上の「続きを話す」）。続きを話す前の姿（ターンの数、話し終えた日時、往復の上限、根拠）と続きを始めた日時は、続きを話すときに場面に残しておく。続きを始めた日時は、レポートの版を捨てる境目に使う（[07-report.md](07-report.md) の「版を残す」）。場面を消したときは、その場面の「確かめに使わないことにした」履歴を外してから計算し直す（上の「力の状態」）
- 外す・戻すは、外したかどうかだけを変え、力の状態は変えない。続きを話すときも、根拠は変わらないので計算し直さない
- 根拠の言葉は画面にそのまま出すので、API は何番目の答えかではなく、引用の文字列と、選んだ答えかどうか、選んだ答えなら結びついた本人の言葉を返す
- 訂正と続きを話す操作も、読んだときから変わっていないときだけ書く。続きを話すのは、場面を始めるときと同じく「途中の場面の印」を書き換えられたときだけ。書き換えられなければ、場面を話し終えた状態に戻し（足した問いも外す）、先に始まった場面を知らせる（[02-discover.md](02-discover.md)。Claude の判断）
- 訂正につらい状態のサインがあれば、02 discover（話す）と同じ決まった言葉の返事を足し、相談窓口の知らせを返す

### 画面

| 画面 | パス | 中身 |
|---|---|---|
| 話す | `/talk/:id` | 話し終えた場面では、やりとり（訂正は「あなたが読み取りを直した言葉」の囲みで分けて出す）の下に「見えたこと」、「読み取りを直す」、続きを話せれば「この場面の続きを話す」 |
| 見えた力 | `/abilities` | 3 つの力の、生活の中で・仕事で、根拠、外す・戻す、履歴。下に、次にできることへの道を一つ（[00-common.md](00-common.md) の「次にできること」。外す・戻すたびに読み直す。行き先がこの画面なら出さない） |
| ホーム | `/home` | 「見えた力」へのリンクを足す |
| エピソード | `/episodes` | 続きを話せる場面に「もう少し聞かせてほしいことがあります」 |

- 力の名前と、行動の手がかりの言葉は、画面の文言の置き場所（`copy.ts`。[00-common.md](00-common.md)）ではなく、裏側の 1 か所に置き、API で渡す（Claude の判断）。この言葉も、使わない言葉の一覧とテストで照らし合わせる。力の名前「優先順位をつける力」の「優先順位」は、使わない言葉の「順位」（人や仕事に順位を付けること）に当たらないものとして扱う（Claude の判断）

### AI への指示

- 読み取りの指示 `reader.md` に、核となる行動の確かめを足す。書くことは次のとおり
  - 核となる行動の一覧
  - 根拠の取り方: 一字一句そのまま、何番目の答えか、何番目の出来事か、一般論か。選んだ答えなら、結びつく自由な答えの言葉
  - 結果で見立てを変えないこと
  - 訂正を優先すること
- 返事の指示 `listener.md` に、「足りない行動を一つ聞く」一手の書き方を足す。手がかりの言葉は、次の一手を渡す印 `<next_move>`（[02-discover.md](02-discover.md)）と一緒に、会話の最後に渡す
- 読み取りの AI に渡すやりとりは、1 つの文にまとめ、本人の答えに番号を付け、自由に書いた答え・選んだ答え・訂正が分かるようにする（Claude の判断）
- 読み取りの AI が返した根拠の候補のうち、形の合わないもの（知らない力の名前、数でない番号など）は捨てる。読み取り全体を失敗にはしない
- 開発で使う偽物の AI は、場面の答え（自由に書いた答えか訂正）に行動の目印の言葉（「重な」「先に」など）があれば、その答えの文全体を引用にした根拠の候補を返す。本物の読み取りと同じく、いまの答えだけでなく場面全体から探す。画面で「見えたこと」を確かめるため（Claude の判断）

## 受け入れ基準

1. validate-1（3 つともそろったときだけ根拠あり）: 同じ出来事の中で、一般論でない根拠が 3 つの行動すべてにそろったときだけ、根拠ありになる。2 つの出来事に分かれてそろったときは、要確認のまま。読み取りが往復ごとに出来事の番号を振り直しても、別の読み取りの根拠を同じ出来事としてそろえない。確かめ方: 状態を決めるコードの単体テスト（一つの処理だけを取り出して確かめるテスト）、番号を振り直す読み取りを流す結合テスト、評価
2. validate-2（足りない行動だけ聞き返す）: いまの答えが具体的な出来事か、いまの答えから一般論でない根拠が見つかり、いまの答えの出来事の中に要確認の力があり（場面ですでに根拠ありの力は除く）、より先の一手（つらい状態のサイン、締め、家族の病気の話、続きの問いに「その日のほかのことを話したい」を選んだ）に当たらないとき、次の一手は足りない行動を一つ聞く一手になる。聞き手への手がかりは、その行動だけになる。同じ行動は 1 場面で 2 回まで。続きの問いに「とくに思い当たりません」を選んだ行動は、聞き直さない。確かめ方: 次の一手の単体テストと、評価（評価で答えを読む AI が、足りない行動だけを聞いているかを見る）
3. validate-3（結果で見立てを変えない）: 結果がうまくいかなかった話も、結果を話していない話も、行動がそろえば根拠ありになる。確かめ方: 評価
4. validate-4（根拠は本人の言葉）: 見えた力と、もう少し聞かせてほしいことの根拠は、本人の答えに一字一句含まれる。含まれない引用と、短すぎる引用は捨てる。選んだ答えの根拠には「（選んだ答え）」と添え、結びついた言葉と並べる。確かめ方: 照らし合わせの単体テスト、画面のテスト、評価
5. validate-5（選んだだけでは根拠にしない）: 選択肢を選んだ答えは、自由に書いたほかの答えの結びつく言葉がなければ、根拠にしない。確かめ方: 照らし合わせの単体テストと、評価
6. validate-6（否定の言葉を使わない）: 見えたことと見えた力の画面に、使わない言葉（[00-common.md](00-common.md)）、状態の呼び名、点数、順位が出ない。確かめ方: 文言のテスト（`copy.ts` と、裏側の力の名前と手がかりの言葉と続きの問い）と、2 つの画面それぞれのテスト
7. validate-7（見えた力と、もう少し聞きたいことを示す）: 場面を区切ると、話す画面に、見えた力と根拠、もう少し聞かせてほしいこと、まだ聞けていない力が出る。確かめ方: 結合テスト（裏側を丸ごと立ち上げて API を呼ぶテスト）と画面のテスト
8. validate-8（訂正したら確かめ直す）: 訂正を送ると、その場面を読み直し、状態が変わった力の履歴に、いつ、何が、なぜ変わったかが残る。訂正で打ち消された行動は、続きの問いと手がかりで聞き直さない。確かめ方: 結合テストと、評価（訂正で状態が変わる例）
9. validate-9（生活での根拠と仕事での発揮を分ける）: 見えた力の画面と API で、生活の中での状態と、仕事での状態を別々に返し、仕事ではいつも「まだ確かめていない」になる。確かめ方: 結合テストと画面のテスト
10. validate-10（一般論には具体的な出来事を聞く）: 一般論として話された行動だけの力は要確認になり、根拠ありにならない。次の一手は具体的な出来事を一つ聞く一手になる。確かめ方: 状態を決めるコードと次の一手の単体テスト、評価
11. validate-11（要確認の場面に戻れる）: 要確認の力がある話し終えた場面は、続きを話せる。続きは、時間を前提にしない受け止めの一文、本人の言葉の映し返し、足りない行動を前提にせずに聞く問いの順で始まる。続きの問いに「その日のほかのことを話したい」を選ぶと、次は同じ日のほかの時間や出来事を聞く（選択肢を選んだときだけで、同じ言葉を書いたときは働かない）。区切る前の最後の問いに答えていなければ、同じことを聞く問いを続けて出さない。続きの途中で飛ばしても、前に話し終えていた分は残る。確かめ方: 結合テストと画面のテスト
12. validate-12（本人が見立てを外せる）: 外した力は、見えた力の API で外したと分かり、履歴に残る。戻すこともでき、それも履歴に残る。確かめ方: 結合テストと画面のテスト

## やらないこと

- 仕事での発揮の状態を動かすこと。何をもって動かすかは、ハッカソンのあとに決める
- 仮の場面の問い（状況判断質問）の答えの扱い。06 deepen（選んだ案を深める）で作る
- 5 つの記録の「できること」への反映。04 profile（5 つの記録）で、この API を読んで作る
- 力の確かめに使わない場面の印を、本人が外すこと

## 評価との対応

架空エピソードを、このまとまりで 11 件足す（02 discover（話す）の続きの番号で、`evals/episodes/e08-*.md` から。すべて架空で、このハッカソンの期間中に新しく書く。Claude の判断）。確かめる場面は [6-quality.md](../prd/6-quality.md) の表から選ぶ。

- 3 つの行動がそろった話（力ごとに 1 件、3 件）
- 一部だけそろった話（2 件）
- 一般論だけの話
- 結果がうまくいかなかった話
- 結果を話していない話
- 選択肢を選んだだけの答え
- 選択肢の答えが、自由に書いたほかの事実と結びついた話
- 本人が訂正した話（訂正で状態が変わる）

数え方の細部は `evals/criteria.md` に書く。

- エピソードごとに、場面を最後まで流したあとの力の状態を、期待した状態と比べる
- 合格の線は [6-quality.md](../prd/6-quality.md) の表のとおり。このまとまりで見るのは次の 4 つ
  - 褒めすぎ（根拠ありにしてはいけない例で、根拠ありにした）: 0 件
  - 根拠の引用が、本人の発言と一字一句同じ: すべて
  - そろっている例で、根拠ありにした: 9 割以上
  - 一部だけそろった例で、足りない行動だけを聞き返した: 9 割以上
- 02 discover（話す）で見た 3 項目（「毎回、受け止めてから問いを一つだけ出した」「つらい状態のサインが出た例で、相談窓口を示さなかった」「突き放し」）も、同じ回で見る
- 読み取りが返した引用のうち、短すぎて捨てたものの数も数える。合格の線は持たせず、読み取りの指示を直す手がかりにする（Claude の判断）
- 同じエピソードのやりとりを、特別な指示のない汎用の AI にも渡し、「この人の強みと、その根拠」を書いてもらう。評価で答えを読む AI が、どの力を強みとして挙げたかと、引用が本人の発言と一字一句同じかを読み取る。そのうえで、同じ物差しで褒めすぎと引用の違いを数える。合格の線は持たせず、比べる数字として結果に残す（README と動画で使う）
- AI の言い方（足りない行動を聞く問い、見えたことの文言）と、コードが決めた言葉（続きの問いと選択肢、手がかりの言葉、場面を確かめに使わなくなった履歴の言葉）は、AI 同士の判定だけで確定しない。開発者が確かめる項目として残す
