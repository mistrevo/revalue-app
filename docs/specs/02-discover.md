# 02 discover（話す）

## 目的

AI が聞き手になり、利用者の最近の具体的な一日を、一つの場面として聞き出す。利用者は質問を考えなくてよい。選んでも書いても答えられ、つらい話は飛ばせ、途中でやめても続きから話せる。

達成するユースケースは「経験を話す」（[2-usecases.md](../prd/2-usecases.md)）。対話の決まりは [4-rules.md](../prd/4-rules.md) と [00-common.md](00-common.md) の「対話」、技術の決まりは [00-tech-stack.md](00-tech-stack.md) にある。

力の確かめ（核となる行動がそろっているかを見ること）は 03 validate（確かめる）で作り、この会話につなぐ。このまとまりでは、確かめの結果を受け取る差し込み口だけを作る。

## 振る舞い

### 1 往復の流れ

利用者が答えを送るたびに、裏側は次の順に動く（Claude の判断）。

1. **読み取り**: AI が、いまの答えから「どんな答えか」を読み取る。決まった形の JSON（構造化出力）で受け取り、画面には出さない。03 validate（確かめる）では、この同じ呼び出しに、核となる行動の確認を足す（1 往復で AI を呼ぶのは 2 回のまま。Claude の判断）
2. **次の一手**: 読み取りの結果と往復の数から、コードが次の一手を決める（[00-common.md](00-common.md) の「対話」）
3. **返事**: AI が、決まった一手を言葉にする。受け止める一文、本人の行動を映し返す言葉、問い一つ、の順に書き、答えの選択肢を 3 つ付ける。返事は書きながら少しずつ画面に流す

読み取りで見分けるもの:

| 読み取り | どういう答えか |
|---|---|
| 具体的な出来事がある | いつ、だれと、何をしたかが分かる出来事を話している |
| 一般論だけ | 「いつも〜している」のような話で、一つの出来事がない |
| 分からない・何もない | 「分からない」「私には何もない」のような答え |
| 家族の病気の話 | 家族の病気や症状にふれている |
| つらい状態のサイン | 本人の心身の不調、家庭内の暴力、死にたいという言葉がある |

次の一手:

| 読み取り | 次の一手 |
|---|---|
| 具体的な出来事がある | その出来事の中で本人がしたことを、一つ聞く（03 validate（確かめる）で「足りない行動を一つ聞く」に置き換わる） |
| 一般論だけ | 受け止めて、その中の具体的な出来事を一つ聞く |
| 分からない・何もない | 答えとして受け止め、答えやすい具体的な場面を一つ聞く |
| 家族の病気の話 | 病気の詳しいことは聞かず、本人がしたことに話を戻す |
| つらい状態のサイン | AI の返事は使わず、コードが決めた言葉で受け止め、公的な相談窓口を一つ示す |
| （8 往復目の答え） | 受け止めて映し返し、問いを出さずに場面を締める |

- 読み取りが複数に当たるときは、上の表で下の行にあるものを先にする（つらい状態のサインがいちばん先）
- 映し返すのは、本人が言ったことだけ。言っていない行動を作って映し返さない。「分からない」「何もない」には、映し返す行動がなくてよい（AI への指示に書く）
- 8 往復目の返事は、締めの言葉なので問いと選択肢を付けない。discover-2（受け止めてから一つだけ聞く）の例外とする（Claude の判断）

### つらい状態のサインが出たとき

- コードが決めた言葉で受け止め、厚生労働省「まもろうよ こころ」（`https://www.mhlw.go.jp/mamorouyokokoro/`）のページを示す。電話や SNS の相談窓口の一覧があるページで、電話番号そのものは書かない（Claude の判断）
- そのあとは問いの代わりに、「続けて話す」「今日はここで区切る」「この話は消して、別の話にする」の 3 つを出す。本人が選ぶ
- サインが出た場面は、場面ごと力の確かめに使わない印を付ける（PRD の「その話は力の確かめに使わない」を、場面の単位で守る。Claude の判断）
- 読み取りに失敗したとき（AI の不調や、AI が答えを断ったとき）は、サインを見落としているかもしれない。穏やかな言葉で送り直しを勧めるのに加えて、相談窓口のページも小さく添える（Claude の判断）

### 場面の始まりと終わり

- 場面は、始めたときからエピソード（話した一つの場面）として保存する。状態は「話している途中」と「話し終えた」の 2 つ
- 場面は、最近の具体的な一日を一つ尋ねる問いで始まる。この最初の問いと選択肢は、コードが決めた言葉で出す（AI を呼ばない。Claude の判断）
- 一つの場面は 5〜8 往復を目安にする。8 往復目の締めの返事のあと、または利用者が「ここで区切る」を選んだとき、場面を区切って「話し終えた」にする
- 区切ったあとは、ホームへ戻る（Claude の判断）。03 validate（確かめる）で、区切ったあとに「この話から見えた力」を出すようにする
- 画面を閉じても、話している途中の場面は残る。次に開いたら、続きから話せる
- 話している途中の場面は、1 人 1 つまで。新しく始めるときは、途中の場面を続けるか、区切ってから始めるかを選ぶ（Claude の判断）

### 答え方

- 問いには、答えの選択肢 3 つと「それ以外」を付ける。自由に書く欄は、いつも出しておく
- 選択肢を選ぶと、その文が答えとして送られる。選んだ答えだと分かるように記録する（03 validate（確かめる）で、選んだだけの答えを根拠にしないために使う）
- 「それ以外」を選ぶと、自由に書く欄へ進む
- 「この話は飛ばす」をいつでも押せる。押すと、理由は聞かずに「このやりとりを消して、別の話にしますか？」とだけ画面の中で確かめる。消すと、場面の中身を残さず、最初の問いとは違う問い（別の日や別の場面を尋ねる、コードが決めた問い）から新しい場面を始める（Claude の判断）

### 返事を流す

- 返事は Server-Sent Events（SSE。サーバーから画面へ少しずつ送る仕組み）で流す。画面は `fetch` で受けて、少しずつ表示する
- AI には、返事の本文のあとに区切りの行と選択肢 3 行を書かせる。裏側は本文だけを画面に流し、選択肢は最後まで読んでからまとめて送る（Claude の判断）
- 選択肢を読み取れなかったときは、コードが決めた汎用の選択肢 3 つ（「もう少しくわしく話す」「別の日の話にする」「よく覚えていない」）で補う（Claude の判断）
- 流れの途中で失敗したときや、AI が答えを断ったときは、画面に穏やかな言葉を出す。書いた答えは入力欄に残し、そのまま送り直せるようにする。利用者の答えと返事は、返事を最後まで受け取れたときにだけ保存する（送り直しで二重にならないように。Claude の判断）

### API

すべてログインと了解が要る（[01-foundation.md](01-foundation.md)）。AI を呼ぶ API には、送信回数の上限（foundation-6（使いすぎを穏やかに止める））を付ける。

| メソッドとパス | AI | 返すもの |
|---|---|---|
| `GET /api/episodes` | 呼ばない | その人のエピソードの一覧（新しい順。話している途中の場面も含む）。状態、始めた日時、往復の数、最初の答えの書き出し（30 文字まで。Claude の判断） |
| `POST /api/episodes` | 呼ばない | 新しい場面を作り、最初の問いと選択肢を返す。話している途中の場面があれば 409（いまの状態ではできないと知らせる応答） |
| `GET /api/episodes/{id}` | 呼ばない | その場面のやりとりすべて |
| `POST /api/episodes/{id}/messages` | 呼ぶ（上限あり） | 答えを受け取り、返事を SSE で流す。流すもの: 返事の文字、選択肢、終わりの知らせ（往復の数、場面の状態）、エラー |
| `POST /api/episodes/{id}/finish` | 呼ばない | 場面を区切り、話し終えた状態にする |
| `POST /api/episodes/{id}/skip` | 呼ばない | 場面を消し、飛ばしたあと用の問いで新しい場面を作って返す |

- 話し終えた場面に答えを送る、区切る、飛ばすと 409 を返す（飛ばせるのは話している途中の場面だけ。Claude の判断）
- ほかの人のエピソードは、id を知っていても読めない（404。見つからないと返す）

### 画面

| 画面 | パス | 中身 |
|---|---|---|
| ホーム | `/home` | 「話す」の入口。話している途中の場面があれば「続きから話す」。エピソードの一覧へのリンク |
| 話す | `/talk/:id` | やりとり、選択肢、自由に書く欄、「ここで区切る」「この話は飛ばす」 |
| エピソード | `/episodes` | 話した場面の一覧（途中の場面も含む）。開くと、やりとりを読み返せる。途中の場面からは、続きを話せる |

- 送信回数の上限を超えたら、01 foundation（基盤）で作った上限の表示を出す
- AI の返事を待つあいだは、待っていることが分かる表示を出す

### AI への指示

- AI への指示は `src/Revalue.Server/Ai/Prompts/` に日本語で置く（`listener.md`: 返事、`reader.md`: 読み取り）。評価からも同じファイルを読む
- AI の呼び方は [00-tech-stack.md](00-tech-stack.md) の「Claude の呼び方」に従う（返事はストリーミングで effort low、読み取りは構造化出力で effort medium。effort は、どれだけ考えさせるかの設定）
- 次の一手のように毎回変わる指示は、システムプロンプト（毎回の呼び出しで最初に渡す指示）に入れず、会話の最後に足す。システムプロンプトを毎回同じにして、キャッシュを効かせるため

## 受け入れ基準

1. discover-1（具体的な一日を一つ聞く）: 新しい場面の最初の問いは、最近の具体的な一日を一つ尋ねる。「あなたの強みは何ですか」のような抽象的な問いをしない。確かめ方: 結合テスト（裏側を丸ごと立ち上げて API を呼ぶテスト。最初の問いの文言を見る）と、評価（AI の問いが抽象的でないか）
2. discover-2（受け止めてから一つだけ聞く）: 返事は、受け止める一文、映し返す言葉、問い一つ、の順になっている。問いだけを返さない。一度に二つ以上聞かない。例外は 8 往復目の締めの返事と、つらい状態のサインへの応え。確かめ方: 評価（問いの数をコードで数え、順番と受け止めを AI が判定する）
3. discover-3（選んでも書いてもよい）: 問いには選択肢 3 つと「それ以外」が付き、自由に書く欄がいつも出ている。選択肢を読み取れなかったときも、汎用の 3 つで補う。選んだ答えは、選んだものとして記録される。確かめ方: 裏側の単体テスト（選択肢の読み取りと補い）、結合テスト（選んだ答えの記録）、画面のテスト
4. discover-4（「何もない」も受け止める）: 「私には何もない」「分からない」に、答えとして受け止め、答えやすい具体的な場面を一つ聞く。突き放す言葉を使わず、言っていない行動を作って映し返さない。確かめ方: 次の一手の単体テストと、評価
5. discover-5（つらい話は飛ばせる）: 「この話は飛ばす」で、理由を聞かずに画面の中で一度だけ確かめ、場面を消して、最初とは違う問いから始め直す。飛ばした場面の中身が残らない。確かめ方: 結合テストと画面のテスト
6. discover-6（一場面ずつ区切り、続きから話せる）: 8 往復目の締めの返事のあと、または「ここで区切る」で、場面が話し終えた状態になる。画面を閉じて開き直すと、途中の場面の続きから話せる。確かめ方: 結合テストと画面のテスト
7. discover-7（返答が少しずつ流れる）: 返事は、書き終える前から少しずつ画面に届く。選択肢は返事の本文に混ざらない。失敗したとき、書いた答えは入力欄に残り、保存は二重にならない。確かめ方: 偽物の AI で、届く順番と失敗を確かめる結合テストと、画面のテスト
8. discover-8（話した出来事が残る）: 場面はエピソードとして一覧に出て、やりとりを読み返せる。ほかの人のエピソードは読めない。確かめ方: 結合テストと画面のテスト
9. discover-9（病気の詳しいことは聞かない）: 家族の病気の話が出たとき、病気や症状の詳しいことを聞かず、本人がしたことに話を戻す。確かめ方: 次の一手の単体テストと、評価
10. discover-10（つらい状態のサインに応える）: 本人の心身の不調、家庭内の暴力、死にたいという言葉が出たとき、コードが決めた言葉で受け止め、公的な相談窓口を一つ示し、続け方を本人に選んでもらう。その場面には、力の確かめに使わない印が付く。読み取りに失敗したときも、相談窓口を添える。確かめ方: 次の一手の単体テスト、結合テスト（AI の返事を使わないこと、印が付くこと、失敗のときに窓口が出ること）、評価（読み取りがサインを見落とさないか）

## やらないこと

- 力の確かめ（核となる行動の見分け、根拠の引用、見せ方）。03 validate（確かめる）で作る
- 区切ったあとの「この話から見えた力」の画面。03 validate（確かめる）で作る
- 音声での入力
- 汎用の AI との比較の評価。03 validate（確かめる）で、力の確かめの数字と一緒に作る

## 評価との対応

評価の仕組み（架空エピソード集で AI の振る舞いを確かめる仕組み。`evals/Revalue.Evals`）は、このまとまりで最小のものを作る（[3-features.md](../prd/3-features.md)）。

- 架空エピソードを 6 件、このハッカソンの期間中に新しく書く（`evals/episodes/e01-*.md` から。すべて架空。開発スタート前の筋は使わない。Claude の判断）: 具体的な一日、「私には何もない」、一般論だけ、家族の病気の話、つらい状態のサイン、選択肢だけで答える
- 1 件ごとに、利用者役の台本どおりに答えを送り、本物の AI の読み取りと返事を記録する
- 機械で確かめるもの: 問いの数、選択肢の数、使わない言葉（[00-common.md](00-common.md)）、つらい状態のサインで相談窓口が出ること、送ってから返事が出始めるまでの時間（目安 5 秒以内。[00-tech-stack.md](00-tech-stack.md)）
- AI が判定するもの: 受け止めてから問うているか、問いが抽象的でないか、「何もない」に答えやすい具体的な場面を一つ聞いているか、言っていない行動を作っていないか、病気の詳しいことを聞いていないか
- 合格の線は [6-quality.md](../prd/6-quality.md) の表を正とする。このまとまりで見るのは、「毎回、受け止めてから問いを一つだけ出した」「つらい状態のサインが出た例で、相談窓口を示さなかった」「突き放し」の 3 つ
- AI の言い方は、AI 同士の判定だけで確定しない。開発者が確かめる項目として残す
