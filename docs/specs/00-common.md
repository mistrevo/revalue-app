# 00 共通の決まり

## 目的

まとまり（01〜07）をまたいで守る決まりを、ここ 1 か所に置く。各 Spec はここを参照し、同じことを書き写さない。

元になる決まりは PRD にある。この文書には、それを作るときに迷わないための細部を書く。

- 製品の芯: [README.md](../prd/README.md)
- 力を確かめる物差し（力ごとに決めた 3 つの核となる行動が、そろっているかを見分ける基準）と、対話の決まり: [4-rules.md](../prd/4-rules.md)
- 扱う情報: [5-information.md](../prd/5-information.md)
- AI の振る舞いの合格基準: [6-quality.md](../prd/6-quality.md)
- 技術の決まり: [00-tech-stack.md](00-tech-stack.md)

## 振る舞い

### 言葉

- 画面と AI の言葉で、次を使わない。「診断」「判定」「スコア」「根拠なし」「不得意」「不十分」「まだ強みとは言えません」「あなたに向いている仕事は」「適職」「合否」、点数、順位
- 力の状態の呼び名（根拠あり、要確認、未確認）と、核となる行動のチェック表は、画面の前面に出さない。画面では「この話から見えた力」「もう少し聞かせてほしいこと」「まだ聞けていない力」と言う。「要確認」の力をカード、5 つの記録、選んだ案を深める画面、可能性レポートで使うときは「確かめ中」と示す（Claude の判断）
- 根拠の本人の言葉は「」で囲み、一字一句そのまま出す。選んだ答えの根拠には「（選んだ答え）」と、結びついた本人の言葉を添える。見えたこと、見えた力、5 つの記録、仕事の選択肢、選んだ案を深める画面、可能性レポートのどこでも同じ見せ方にする。5 つの記録の好みとやりたいことでは、選択肢から選んだ項目にも「（選んだ答え）」と添える（Claude の判断）
- 大げさな褒め言葉で埋めない。本人がしたことを具体的に映し返す
- 困ったときの言葉（エラー、送信回数の上限、AI が答えられなかったとき）は穏やかにし、利用者のせいにしない。次にできることを一つ添える
- 画面の文言は `src/web/src/copy.ts` に、AI への指示は `src/Revalue.Server/Ai/Prompts/` にまとめる。使わない言葉の一覧は `src/shared/forbidden-words.json` の 1 か所に置き、画面のテスト、裏側、評価から読む（Claude の判断）
- 使わない言葉の「順位」は、「優先順位」（力の名前「優先順位をつける力」を含む）の中では数えない。本人がしたことを映し返す言葉で、カードや人に順番を付ける言葉ではないため（Claude の判断）
- 言い切りと順位の言葉（向いています、向いている、向いてる、向いていそう、ぴったり、最適、適任、最良、ベスト、いちばん、一番、おすすめ、オススメ、お勧め、お薦め、イチオシ、一押し、最も など）と、大げさな褒め言葉（すばらしい、素晴らしい、素敵、すてき、達人、天才、得意、プロ、プロフェッショナル、見事、完璧、さすが、抜群。活用した形を含む。「得意先」と、「プロジェクト」のようにカタカナが続く「プロ」は数えない）は、上の使わない言葉とは別の一覧にする。どの画面でも使わない言葉ではないので、本人が選ぶ前に AI やコードが適職や順番を決めたように読めるところに限って確かめる。どこで確かめるかは、[05-options.md](05-options.md)（仕事のカードの文）、[06-deepen.md](06-deepen.md)（選んだ案を深める文）、[07-report.md](07-report.md)（可能性レポートの画面の文言とコードが組み立てる文）に書く。「」で引いた本人の言葉の中では数えない（Claude の判断）
- 案内と説明では、「本人の言葉を根拠にしている」「本人が選び、直せる」を先に伝える

### 対話

[4-rules.md](../prd/4-rules.md) の「対話の決まり」に従う。作るときは次を守る。

- 1 往復ごとに、まず力の確かめ（核となる行動がそろっているかを見ること）を、会話の返事とは別に行う。次にすること（根拠ありにする、足りない行動を聞く、別の場面を聞く）はコードが決め、AI には決まった一手だけを言葉にさせる（Claude の判断）
- 根拠の引用は、本人の発言に一字一句含まれるかをコードで照らし合わせる。含まれなければ使わない
- 選択肢の答えは、本人が話したほかの事実と結びついたときだけ根拠にし、選んだ答えだと分かるように示す

### データ

[5-information.md](../prd/5-information.md) に従う。作るときは次を守る。

- ログインした人は、「利用者キー」でだけ見分ける。利用者キーは、組み込み認証（Container Apps がアプリの手前でログインを受け持つ機能）が渡す ID を、鍵を使って元に戻せない形に変えた値（Claude の判断）
- メールアドレス、名前、Google のプロフィールは読まず、保存しない
- その人のデータは、すべて利用者キーで分けて保存する。「全部消す」は、その利用者キーのデータをすべて消す
- その人のデータは、最後に使った日から 30 日で自動で消える。日本時間でその日に初めて使ったときに、残す期間を延ばす（Claude の判断）
- 人と結びつかない数（可能性レポートまで進んだ人の数、案を選んだ人の数）と、アプリ全体の送信回数は、利用者キーと切り離して持つ。人と結びつかない数は、全部消しても残す
- ログに書いてよいのは、利用者キー、件数、かかった時間、トークン数、エラーの種類だけ。話した内容、AI の返答、メールアドレス、名前は書かない。リクエストとレスポンスの中身もログに書かない
- 開発者が話した内容を読むための画面や書き出しは作らない
- 1 日の区切りは、日本時間の 0 時（Claude の判断）
- 利用者が書く言葉の文字数は、見た目の 1 文字ずつ数える（絵文字などの合成された文字は 1 文字）。結合文字（前の文字に重ねて出す文字）を重ねると、見た目は短いまま中身を長くできるので、中身の長さ（UTF-16 の長さ）にも上限を置く。上限の数は各 Spec に書く（Claude の判断）

### 画面

- スマホを先に考える。幅 375px で崩れず、PC でも読みやすい幅に収める
- ログインとログアウトは、組み込み認証の `/.auth/login/google` と `/.auth/logout` へ、ページごと移動して行う。画面の切り替え（React Router）で横取りしない
- ブラウザの確認ダイアログ（`alert` や `confirm`）は使わない。確かめるときは画面の中で聞く（Claude の判断）

### 呼び名とテスト

- 受け入れ基準の呼び名は `<まとまりの名前>-<番号>（タイトル）` にし、テスト名と評価の結果にも同じ呼び名を入れる
- テストでは Claude を呼ばない。本物を呼ぶのは評価だけ

## 受け入れ基準

1. common-1（使わない言葉を出さない）: `copy.ts` の文言に、使わない言葉が含まれていない。テストで一覧と照らし合わせて確かめる。プロンプトは、AI に「使わない言葉」を指示として書くので対象にしない。AI の返答は評価で確かめる
2. common-2（ログに中身を書かない）: 話した内容、メールアドレス、名前にあたる目印の文字列を入れて API を呼んだとき、ログにその文字列が出ない。テストでログを集めて確かめる

どちらのテストも、`copy.ts` とログの仕組みができる 01 foundation（基盤）で作り、あとのまとまりでもそのまま回す。

## やらないこと

- まとまりごとの振る舞いはここに書かない。各 Spec に書く
- 製品の芯や物差しを、ここで変えない。変えるときは PRD を先に変える

## 評価との対応

- 使わない言葉の一覧は、評価でも AI の返答に対して使う。[6-quality.md](../prd/6-quality.md) の項目との対応は次のとおり
  - 「根拠なし」「不得意」「不十分」「まだ強みとは言えません」: 「突き放し」
  - 「あなたに向いている仕事は」「適職」「合否」、順位: 「本人の代わりに決める」
  - 「診断」「判定」「スコア」、点数: 合格基準の項目にはない。ハッカソンの運営が避けるべき例に挙げた「性格診断」「AI 履歴書スクリーニング」に見せないために使わない。評価では件数を数えて結果に残す
- 評価の結果は `evals/results/<日付>-<まとまり>.md` に、呼び名とタイトルをセットにして残す
