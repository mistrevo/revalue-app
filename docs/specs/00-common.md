元になる決まりは PRD にある。この文書には、それを作るときに迷わないための細部を書く。

## 振る舞い

### 言葉

- 画面と AI の言葉で、次を使わない。「診断」「判定」「スコア」「根拠なし」「不得意」「不十分」「まだ強みとは言えません」「あなたに向いている仕事は」「適職」「合否」、点数、順位
- 力の状態の呼び名（根拠あり、要確認、未確認）と、核となる行動のチェック表は、画面の前面に出さない。画面では「この話から見えた力」「もう少し聞かせてほしいこと」と言う。「要確認」の力をカード、5 つの記録、選んだ案を深める画面、可能性レポートで使うときは「確かめ中」と示す（Claude の判断）
- 「まだ聞けていない力」の名前は並べず、代わりに次の一文を添える。力が「ない」「足りない」と読める言い方、数、「あと〜」は使わない（Claude の判断）
  - 何か見せたとき: 「ほかの力も、話を重ねると見つかることがあります。」
  - 何も見せないとき: 「話を重ねると、見えてくる力があります。」
- 根拠の本人の言葉は「」で囲み、一字一句そのまま出す。選んだ答えの根拠には「（選んだ答え）」と、結びついた本人の言葉を添える。見えたこと、見えた力、5 つの記録、仕事の選択肢、選んだ案を深める画面、可能性レポートのどこでも同じ見せ方にする。5 つの記録の好みとやりたいことでは、選択肢から選んだ項目にも「（選んだ答え）」と添える（Claude の判断）
- 大げさな褒め言葉で埋めない。本人がしたことを具体的に映し返す
- 困ったときの言葉（エラー、送信回数の上限、AI が答えられなかったとき）は穏やかにし、利用者のせいにしない。次にできることを一つ添える
- 送信回数の上限の言葉には、また使える時刻と、何がまたできるかと、ここまでの記録が残っていることを添える。何がまたできるかは画面に合わせる（Claude の判断）
  - 話す画面: また続きを話せます
  - 仕事の選択肢: また仕事の選択肢を作れます
  - 選んだ案を深める: また選んだ案を深められます
- 画面の文言は `src/web/src/copy.ts` に、AI への指示は `src/Revalue.Server/Ai/Prompts/` にまとめる。使わない言葉の一覧は `src/shared/forbidden-words.json` の 1 か所に置き、画面のテスト、裏側、評価から読む（Claude の判断）
- 使わない言葉の「順位」は、「優先順位」（力の名前「優先順位設定力」を含む）の中では数えない。本人がしたことを映し返す言葉で、カードや人に順番を付ける言葉ではないため（Claude の判断）
- 言い切りと順位の言葉（向いています、向いている、向いてる、向いていそう、ぴったり、最適、適任、最良、ベスト、いちばん、一番、おすすめ、オススメ、お勧め、お薦め、イチオシ、一押し、最も など）と、大げさな褒め言葉（すばらしい、素晴らしい、素敵、すてき、達人、天才、得意、プロ、プロフェッショナル、見事、完璧、さすが、抜群。活用した形を含む。「得意先」と、「プロジェクト」のようにカタカナが続く「プロ」は数えない）は、上の使わない言葉とは別の一覧にする。どの画面でも使わない言葉ではないので、本人が選ぶ前に AI やコードが適職や順番を決めたように読めるところに限って確かめる。どこで確かめるかは、[05-options.md](05-options.md)（仕事のカードの文）、[06-deepen.md](06-deepen.md)（選んだ案を深める文）、[07-report.md](07-report.md)（可能性レポートの画面の文言とコードが組み立てる文）に書く。「」で引いた本人の言葉の中では数えない（Claude の判断）
- 案内と説明では、「本人の言葉を根拠にしている」「本人が選び、直せる」を先に伝える

### 力

- 力の正しい一覧は、能力辞書 `src/shared/abilities.json` の 1 か所に置く。辞書は、力の id、名前、分類、核となる行動の文と手がかりを持つ。使うかどうか（話から確かめる `active`、準備中の `preparing`）も持つ。話から確かめる力の行動には、続きを話すときにその行動を聞く問い（続きの問い）も持つ。本人の行動ではなく、その日の状況を表す行動（用事が重なる、予定が変わる、など）には、状況の行動の印（`situation`）を付ける。どの力にも、本人の行動が一つ以上ある（Claude の判断）
- コード、画面、評価の台本は、力の id を決め打ちせず、辞書から読む
- 辞書の形が崩れていれば、起動時に止める。たとえば、核となる行動が 2〜3 でない、id が重なる、辞書にない分類を指す、話から確かめる力が 1 つもない、話から確かめる力の行動に続きの問いがない、行動がすべて状況の行動
- 話から確かめる力の核となる行動、手がかり、続きの問いは、本人がしたことを聞く形にし、うまくいかなかったわけ（なぜ、何が原因か）を問わない。続きの問いはコードが決めた文としてそのまま出て、手がかりは画面と聞き手の指示に出るため（[02-discover.md](02-discover.md) の「場面の始まりと終わり」、validate-3（結果で見立てを変えない））。わけを考えること自体が核となる行動の力（原因分析力、仮説思考力）は、聞き方が決まるまで準備中にする（Claude の判断）
- 話から確かめる力は、いまは次の 22。並びは辞書の順で、表示もこの順にする。足りない行動を聞く力を選ぶとき、そろった行動の数が同じなら、この順で選ぶ（[03-validate.md](03-validate.md) の「次の一手」）

- 見せる力: 一つの場面から本人に見せる力を、次のように絞る（[4-rules.md](../prd/4-rules.md) の「画面での見せ方」。数と選び方は Claude の判断）。似た力が並んで褒めすぎに見えないように、また採点表に見えないようにするため。絞るのは見せ方だけで、場面の根拠と力の状態の決め方は変えない
  - この話から見えた力（根拠あり）は、分類ごとに 1 つまで、場面全体でも 3 つまで。どちらも、そろった行動の多い力、同じなら辞書の順で前の力。分類の数が多く、分類ごとの上限だけでは一つの話に力が並びすぎるため。核となる行動の文（辞書の共通の文）と本人の言葉を組にして並べる
  - もう少し聞かせてほしいこと（要確認）は、場面ごとに 2 つまで。その場面で聞き返した力を先に、残りは見つかった行動の多い順、同じなら辞書の順。続きの問いも、ここに出した力の行動だけを聞く
  - そろっても見えた力に出せない力は、もう少し聞かせてほしいことに出さず、会話の中でも足りない行動を聞かない。答えても本人には何も見えず、聞き返しの数も減るため。出せない力とは、同じ分類で、上の選び方で前に来る力がそろっている力と、場面全体の上限からこぼれる力
  - まだ聞けていない力の名前の一覧は、どの画面にも並べない
  - 本人が力を見るすべての所（話す画面の見えたこと、見えた力の画面と履歴、5 つの記録の「できること」、仕事の選択肢のカード、選んだ案を深める画面、可能性レポート）は、見せた力だけを使う。画面に出さない力は、カードとレポートの理由にも使わない。本人が見ていない力は外せないため（validate-12（本人が見立てを外せる））。見せた力の決め方は [03-validate.md](03-validate.md) の「力の状態」
- 準備中の力は、読み取りの表、次の一手、見えた力のどれにも出さない。辞書にない力の id を持つ根拠は、落とさずに無視する
- 辞書にない力の id を持つ保存データ（場面の根拠、聞いた行動の印、力の本（利用者ごとの力の状態をまとめた記録）の状態・外した力・履歴、カードと選んだ案、深めるの業務と問い、レポートの版）は、読めない力として無視する。名前を引く前に除き、例外（処理を止めるエラー）にしない。保存データは消さず、新しい id に移さない。ただし、力の本の状態と見せた力の印は、話から確かめる力で計算し直した結果なので、古い id は次の計算で落ちる（外した力と履歴は残す。Claude の判断）。話した中身はそのまま残る。名前を出す所では、その力を出さないか、名前なしにする（深めるの業務なら力の名前を添えず、使えるところとしても示さない）
- 業務マスターの業務の使う力（主な力と補助の力。[05-options.md](05-options.md) の「登録した職種と業務」）には、準備中の力が入っていてもよい。業務が力に「つながる」のは、話から確かめる力だけ。カード、深める、レポートで力として示し、理由に使うのは、見せた力だけ
- 画面は力の名前を API から受け取り、画面のコードに力の id を書かない。業務の見立てで選べる力は、`GET /api/deepen` が返す（[06-deepen.md](06-deepen.md)）

### 対話

[4-rules.md](../prd/4-rules.md) の「対話の決まり」に従う。作るときは次を守る。

- 1 往復ごとに、まず力の確かめ（核となる行動がそろっているかを見ること）を、会話の返事とは別に行う。次にすること（根拠ありにする、足りない行動を聞く、別の場面を聞く）はコードが決め、AI には決まった一手だけを言葉にさせる（Claude の判断）
- 根拠の引用は、本人の発言に一字一句含まれるかをコードで照らし合わせる。含まれなければ使わない
- 選択肢の答えは、本人が話したほかの事実と結びついたときだけ根拠にし、選んだ答えだと分かるように示す

### データ

[5-information.md](../prd/5-information.md) に従う。作るときは次を守る。

- ログインした人は、「利用者キー」でだけ見分ける。利用者キーは、組み込み認証（Container Apps がアプリの手前でログインを受け持つ機能）が渡す ID を、鍵を使って元に戻せない形に変えた値（Claude の判断）
- メールアドレス、名前、Google のプロフィールは読まず、保存しない
- その人のデータは、すべて利用者キーで分けて保存する。「全部消す」は、その利用者キーのデータをすべて消す
- その人のデータは、最後に使った日から 30 日で自動で消える。日本時間でその日に初めて使ったときに、残す期間を延ばす（Claude の判断）
- 人と結びつかない数（可能性レポートまで進んだ人の数、案を選んだ人の数）と、アプリ全体の送信回数は、利用者キーと切り離して持つ。人と結びつかない数は、全部消しても残す
- ログに書いてよいのは、利用者キー、件数、かかった時間、トークン数、エラーの種類だけ。話した内容、AI の返答、メールアドレス、名前は書かない。リクエストとレスポンスの中身もログに書かない
- 開発者が話した内容を読むための画面や書き出しは作らない
- 1 日の区切りは、日本時間の 0 時（Claude の判断）
- 利用者が書く言葉の文字数は、見た目の 1 文字ずつ数える（絵文字などの合成された文字は 1 文字）。結合文字（前の文字に重ねて出す文字）を重ねると、見た目は短いまま中身を長くできるので、中身の長さ（UTF-16 の長さ）にも上限を置く。上限の数は各 Spec に書く（Claude の判断）

### 画面

- スマホを先に考える。幅 375px で崩れず、PC でも読みやすい幅に収める。幅 320px〜1280px のどれでも、横にはみ出さない。ボタンを並べるときは、縦に並べるか、折り返す格子にする
- ログインとログアウトは、組み込み認証の `/.auth/login/google` と `/.auth/logout` へ、ページごと移動して行う。画面の切り替え（React Router）で横取りしない
- ブラウザの確認ダイアログ（`alert` や `confirm`）は使わない。確かめるときは画面の中で聞く（Claude の判断）
- どの画面も、左上に「RE:VALUE」を出す。ログインして了解した人の画面ではトーク（`/talk`。[02-discover.md](02-discover.md) の「開いたときの行き先」）へ、案内とはじめにでは案内（`/`）へ行く。話す画面では、上の帯（聞き手）がその代わりになる（Claude の判断）
- ログインして了解した人の、話す画面のほかの画面には、トークへ戻る道「トークに戻る」を置く。話す画面からほかの画面へは、メニュー板から行く（[02-discover.md](02-discover.md) の「話す画面の形」）。古いリンクの `/home` は `/talk` へ送る
- ページのタイトル（ブラウザのタブに出る名前）は、画面ごとに「話す — RE:VALUE」の形にする。画面の名前は、はじめに、話す、話したこと、見えた力、5 つの記録、仕事の選択肢、選んだ案を深める、可能性レポート、設定。案内は「RE:VALUE（リバリュー）」（Claude の判断）

#### 見た目

- 文字は太めの丸ゴシック（M PLUS Rounded 1c）。太さは本文 500、見出しとボタン 700、大見出し 800。アプリの中から配り、外のサーバーに読みに行かない（Claude の判断）。本文は 16px、行の高さ 1.7。補足の文字も 12px より小さくしない。押すものは高さ 44px 以上
- 色は、同じ名前の役割（トークン）で持つ。部品ごとに色の値を書き込まず、役割から引く

  | 役割 | 使う所 |
  |---|---|
  | ground | 画面の地 |
  | surface | 聞き手の吹き出し、カード、入力のまわり、メニュー板 |
  | text / muted | 本文 / 補足の文字 |
  | border | 区切りの線 |
  | accent / onAccent | 送るボタン、選択肢の枠と文字、アイコン / その上の文字 |
  | tint / onTint | 本人の吹き出し、アイコンの丸 / その上の文字 |
  | tile | メニュー板のタイル |
  | chip | 日付やお知らせの小さな札 |
  | field / fieldBorder | 入力欄 |

- 色は 6 色。名前は、あおみどり（いつもの色。名前は Claude の判断）、さくら、わかば、そら、みかん、ふじ。値は `src/web/src/lib/palette.ts` の 1 か所に置く
- 暗い画面は、スマホや PC の設定（`prefers-color-scheme`）に合わせて自動で切り替える。手で切り替えるスイッチは置かない。設定を読めないときは明るい画面にする
- 選んだ色と、話す画面の書きかけ（[02-discover.md](02-discover.md)）は、その端末のブラウザ（`localStorage`）にだけ残し、サーバーへ送らない。アプリが残すのは、見分ける ID と話した内容だけ、という決まりを守るため。書きかけは、最後に書いてから 30 日で捨て、ログアウトと全部消すときにも消す。読めないとき、書けないとき（ブラウザが保存を止めているときなど）は、いつもの色で出し、画面を止めない（Claude の判断）
- どの色でも、明るい画面と暗い画面の両方で、次の組がコントラスト比（WCAG の AA）を満たす（Claude の判断）
  - 4.5 以上: text と ground・surface・field・tile（メニュー板のタイル）、muted と ground・surface・field（見えた力のカードの中の行動の文）・chip（日付の札）、onTint と tint、onAccent と accent、accent と surface（選択肢の文字）
  - 3 以上: 入力欄の枠（fieldBorder と field・surface）、アイコンの accent と tint・tile
  - 対象にしない: 文字のあるボタンの枠（文字でボタンと分かるため）、区切りの線（border）、点線の「それ以外（自分で書く）」の枠
  - 文字と地の組は、上で確かめた組から選ぶ。accent と tile は、色によって 4.5 に届かないので、文字の組にしない

### 次にできること

利用者が次にすることで迷わないよう、いまの記録から「次にできること」を一つだけ示す。決めるのはコードで、AI は呼ばない。裏側の `GET /api/next-step`（[01-foundation.md](01-foundation.md) の API）が決める。区切ったあとの話す画面では、答えの例と同じ形のボタンで出し（下の「区切ったあとの話す画面」）、各画面の下には、ボタン一つで出す。

- 上から順に、最初に当たるものを示す（Claude の判断）

  | 順 | いまの記録 | 次にできること（画面の言葉） | 行き先 |
  |---|---|---|---|
  | 1 | 話している途中の場面がある | 話している途中の場面の続きを話す | その場面 |
  | 2 | 話し終えた場面がない | 最近のある一日のことを話す | 新しい場面を始める |
  | 2a | いちばん新しく話し終えた場面が、つらい状態のサインに応えたところで終わっている | （何も勧めない。欄を出さない） | なし |
  | 3 | 条件（使える時間と場所）が入っていない | 使える時間と場所を、5 つの記録に入れる | 5 つの記録（条件から聞く） |
  | 4 | 使える力がない（本人が外した力だけのときも） | 最近のある一日のことを話す | 新しい場面を始める |
  | 5 | 仕事の選択肢でまだ選んでいない | 仕事の選択肢を見て、一つ選ぶか保留する | 仕事の選択肢 |
  | 6 | 案を選んでいて、いまの案で深めた中身がない（選び直して古くなったときも） | 選んだ案を深める | 選んだ案を深める |
  | 7 | それ以外（保留している、深めた中身がある） | 可能性レポートで、ここまでのまとめを見る | 可能性レポート |

- つらい状態のサインに応えたところで終わった場面のあとは、何も勧めない。打ち明けた人に、先へ進むことを勧めないため（芯 2（突き放さない））。開いたとき（`/talk`）は、その場面の会話を出さず、聞き手の側に「話したいときに、ここから始められます。」と、目立たせない「別の日のことを話す」だけを出す。PRD の revisit-7（つらい話を持ち出さない）に合わせ、「また話せる」とは言わない（開いたときの行き先は [02-discover.md](02-discover.md)。サインのあとふつうに締めた場面でも、この形で出す）。別の一日を話し終えるか、話している途中の場面ができれば、いつもの表に戻る（Claude の判断）
- 使える力が本人の外した力だけのときも、話すことを示す。外したのは本人が決めたことなので、戻すことは勧めない（芯 5（本人が選ぶ））。戻す道は、見えた力の画面と仕事の選択肢の画面に残す（Claude の判断）
- 各画面の下では、一つだけ示し、すぐ下に「どこから進めてもかまいません。」と添える。ほかの画面への道も、同じ画面に並べたまま残す（芯 5（本人が選ぶ））
- 区切ったあとの話す画面: 見えた力のカードのあとに、聞き手の側から「この場面の話は、ここで一区切りです。次は、どれにしますか？」と聞き、次のボタンを答えの例と同じ形で並べる。どれを押してもよく、ほかの画面へはメニュー板から行ける（芯 5（本人が選ぶ）。言葉は Claude の判断）
  - 次にできること。上の表の 3、5、6、7（条件を入れる、仕事の選択肢、選んだ案を深める、可能性レポート）のときだけ出す。話すことと続きを話すことは、次の「別の日のことを話す」と重なるので出さない
  - 「別の日のことを話す」: 新しい場面を始める。どこまで進んでも、別の一日を話して力を足せるようにするため。ほかの画面で途中の場面ができていたら、その場面を開く
  - 「今日はここまで」: 押すと、ボタンを閉じ、聞き手の側から「おつかれさまでした。また話したくなったら、ここから続けられます。」と返す。何も送らず、何も保存しない。開き直すと、またボタンが出る
  - つらい状態のサインに応えたところで終わった場面と、力の確かめに使わない印が付いた場面（サインのあと「続けて話す」を選んで区切った場面）では、問いもボタンも出さない。相談先の案内があればそのあとに、目立たせない「別の日のことを話す」だけを置く。打ち明けた直後に、先へ進むことを勧めないため。開いたときの行き先（[02-discover.md](02-discover.md)）と同じ印で見る（芯 2（突き放さない）。Claude の判断）
- 各画面の下に出す次にできることへの道（各 Spec の画面の表）も、行き先は上の表と同じ。「最近のある一日のことを話す」は、その場で新しい場面を始める。いまいる画面と同じ行き先なら出さない
- 進み具合の点数や割合、済んだ数、「あと何歩」のような言い方にしない
- 次にできることを読めなかったときは、各画面の下には欄を出さない。区切ったあとの話す画面では、「別の日のことを話す」と「今日はここまで」だけを出す。開いたとき（`/talk`）に読めなかったときは、話し終えた場面があれば、つらい話を出さない側に倒して、上の「別の日のことを話す」だけの形にする（Claude の判断）
- 言葉は Claude の判断。開発者が確かめる

### 呼び名とテスト

- 受け入れ基準の呼び名は `<まとまりの名前>-<番号>（タイトル）` にし、テスト名と評価の結果にも同じ呼び名を入れる
- テストでは Claude を呼ばない。本物を呼ぶのは評価だけ

## 受け入れ基準

1. common-1（使わない言葉を出さない）: `copy.ts` の文言に、使わない言葉が含まれていない。テストで一覧と照らし合わせて確かめる。プロンプトは、AI に「使わない言葉」を指示として書くので対象にしない。AI の返答は評価で確かめる
2. common-2（ログに中身を書かない）: 話した内容、メールアドレス、名前にあたる目印の文字列を入れて API を呼んだとき、ログにその文字列が出ない。テストでログを集めて確かめる
3. common-3（次にできることを一つ示す）: 記録の組み合わせごとに、上の表の順で次にできることが一つ決まる。表には、話している途中の場面、条件がない、外した力だけ、保留、選び直して深めた中身が古いときを含む。`GET /api/next-step` は、了解していない人には使えない。1 日の送信回数を使わず、ログには時間だけを書く。区切ったあとの話す画面では、「次は、どれにしますか？」のあとに、次にできること（条件を入れる、仕事の選択肢、選んだ案を深める、可能性レポートのときだけ）、「別の日のことを話す」、「今日はここまで」をボタンで並べる。「別の日のことを話す」は新しい場面を始め、「今日はここまで」は何も送らずに一言を返す。読めなかったときは、残りの 2 つだけを出す。つらい状態のサインに応えたところで終わった場面と、力の確かめに使わない印が付いた場面（サインのあと続けて話して区切った場面）では、次にできることを読まず、「別の日のことを話す」だけを出す。各画面の下には、その一つをボタン一つで出し、「どこから進めてもかまいません。」と添える。読めなかったときは出さない。各画面の下の「最近のある一日のことを話す」は、その場で新しい場面を始める。確かめ方: 単体テスト、結合テスト、画面のテスト
4. common-4（どの画面からもトークへ戻れ、幅に収まる）: ログインして了解した人の画面では、左上の「RE:VALUE」と「トークに戻る」がトーク（`/talk`）へ行く。ページのタイトルは画面ごとに変わる。確かめ方: 画面のテストと、実際のブラウザで幅 320〜1280px を測る
5. common-5（どの色でも読める）: 6 色それぞれの明るい画面と暗い画面で、上の「見た目」の組がコントラスト比を満たす（文字は 4.5 以上、入力欄の枠とアイコンは 3 以上）。当てた色と暗さが画面の変数に出て、端末の設定が暗い画面なら暗い画面になる。保存できないブラウザや、知らない値が残っているときも、いつもの色で出る。確かめ方: 単体テスト（コントラスト比の計算と、色の読み書き）。暗い画面の見え方は実際のブラウザで確かめる

common-1（使わない言葉を出さない）と common-2（ログに中身を書かない）のテストは、`copy.ts` とログの仕組みができる 01 foundation（基盤）で作り、あとのまとまりでもそのまま回す。

## やらないこと

- まとまりごとの振る舞いはここに書かない。各 Spec に書く
- 製品の芯や物差しを、ここで変えない。変えるときは PRD を先に変える

## 評価との対応

- 使わない言葉の一覧は、評価でも AI の返答に対して使う。[6-quality.md](../prd/6-quality.md) の項目との対応は次のとおり
  - 「根拠なし」「不得意」「不十分」「まだ強みとは言えません」: 「突き放し」
  - 「あなたに向いている仕事は」「適職」「合否」、順位: 「本人の代わりに決める」
  - 「診断」「判定」「スコア」、点数: 合格基準の項目にはない。ハッカソンの運営が避けるべき例に挙げた「性格診断」「AI 履歴書スクリーニング」に見せないために使わない。評価では件数を数えて結果に残す
- 評価の結果は `evals/results/<日付>-<まとまり>.md` に、呼び名とタイトルをセットにして残す
