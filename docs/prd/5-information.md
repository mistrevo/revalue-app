# 5. 情報 — 扱う情報と状態

ここには、何を持ち、状態がどう移るかだけを書く。型や名前の細部は Spec で決める。

## 扱う情報

| 情報 | 中身 |
|---|---|
| エピソード | 話した一つの場面。会話の中身と、話している途中か話し終えたか |
| 根拠 | エピソードの中の本人の発言。答え方（自由に書いた、選択肢を選んだ、仮の場面の問いに答えた）を区別する |
| 力 | 3 つの力ごとの状態（[4-rules.md](4-rules.md)）。生活の中での状態と、仕事での発揮の状態を別々に持つ。状態が変わった履歴（いつ、前と後、理由）と、本人が外したかどうかも持つ |
| 5 つの記録 | 下の表。項目ごとに、本人が書いたか、AI が推し量ったかを持つ |
| 仕事の選択肢 | カードの種類と中身。本人の扱い（選んだ、保留した、自分で書いた）。「創る」には、需要を確かめたかを持つ |
| 職種と業務 | アプリに登録する参照のデータ。下の「職種と業務のデータ」に書いた項目と、出典を持つ |
| まだ確かめていないこと | 選んだ案に照らして、まだ確かめていない力や業務 |
| 可能性レポート | 版ごとに残す |
| 了解の記録 | いつ、何に了解したか |
| 使った記録 | その日の送信回数と、最後に使った日 |
| 数 | 可能性レポートまで進んだ人の数と、案を選んだ人の数。人と結びつかない形で持ち、本人が全部消しても残る |

## 5 つの記録

| 記録 | 意味 | 入り方 |
|---|---|---|
| できること | 「根拠あり」の力と、その根拠。「要確認」の力は「確かめ中」として分けて示す | 確かめる（03 validate）から入る。根拠のないものは入れない |
| 好み | 合うやり方や環境 | 選択肢つきの問いで一つ聞く。会話から推し量ったものも足せる |
| やりたいこと | やってみたいこと、これから目指したいこと | 選択肢つきの問いで一つ聞く。会話から推し量ったものも足せる |
| 条件 | 使える時間帯、週あたりの時間、在宅か外出できるか、収入の目安 | 本人が入れる |
| 主体性 | 自分で選び、動き出すときに大事にしたいこと（意味の書き方と欄の文言は Claude の推測。開発者が確かめる） | 本人が書く。AI は推し量らない |

## 力の状態の移り方

- 未確認から要確認へ: 核となる行動の一部が確かめられた。または、一般論だけを話した
- 要確認から根拠ありへ: 3 つとも、一つの出来事の中で確かめられた
- 未確認から根拠ありへ一度に上がることもある: 一つの出来事の中で、3 つとも一度に確かめられた
- 下がることもある: 本人の訂正や AI の読み違いで、根拠が外れた
- 本人が見立てを外した力は、状態を残したまま、カードの理由と可能性レポートに使わない
- どの移り方も、履歴に残す
- 仕事での発揮の状態は、P0 では動かさず、いつも「まだ確かめていない」と示す。P1 以降に何をもって動かすかは、開発者が決める。仮の場面の問いの答えだけでは上げない

## 職種と業務のデータ

- 「選ぶ」と「組み合わせる」は、アプリに登録した職種と業務だけを使う
- データは開発者が手で書く。下書きは Claude が作る。公的な職業情報を参考にし、出典と、使ってよい条件を、データと一緒に書く
- P0 では 3〜5 職種で始める（例: オンライン秘書、経理事務、採用事務）。P1 で、オンライン秘書の業務 5〜10 件と、経理と採用支援の業務を少し足す
- 業務ごとに、次の項目を人が書く。AI はこれらを推し量らない（Claude の判断）

| 項目 | 使い道 |
|---|---|
| 週あたりの時間、時間帯、在宅か外出か | 本人の条件の範囲で絞り込む |
| 収入の幅 | 本人の目安と比べて示す。絞り込みには使わない |
| 使う力（3 つの力のどれか） | 選んだ案を深めるとき、確かめた力と照らす |
| 要る知識や道具（簿記、表計算など） | 3 つの力の外で、まだ確かめていないこととして示す |

## 保存と削除

- 保存するのは、ログインした人を見分ける ID と、上の表の情報だけ。メールアドレスや名前は保存しない
- ログインした人を見分ける ID は、そのまま保存せず、元に戻せない形に変えて保存する（Claude の判断）
- 保存期間は、最後に使った日から 30 日（Claude の判断）。本人はいつでも全部消せる
- 話した内容と AI の返答はログに書かない。開発者も、試用を含めて、話した内容と AI の返答を読まない
- ほかの人に見せる共有の機能は、作るとしても初めは切っておく
- 試用の感想を使うときは、A さん・B さんのように記号にし、個人が分かる部分を除く

## 公開の範囲

- Google アカウントがあれば、だれでも入れる。審査員が入れるよう、Google 側のログイン設定（OAuth の同意画面）は「本番」として公開する
- 1 人あたりとアプリ全体で、1 日の利用回数に上限を付ける（Claude の判断）。Claude API のクレジット（配布された利用枠）を使い切られないため
- 合言葉や許可リストを付けるかは、開発者があとで決める
