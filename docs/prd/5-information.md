# 5. 情報 — 扱う情報と状態

ここには、何を持ち、状態がどう移るかだけを書く。型や名前の細部は Spec で決める。

## 扱う情報

| 情報 | 中身 |
|---|---|
| エピソード | 話した一つの場面。会話の中身と、話している途中か話し終えたか |
| 根拠 | エピソードの中の本人の発言。答え方（自由に書いた、選択肢を選んだ）を区別する |
| 考え方の傾向 | deepen-6（仮の場面での考え方を聞く）の問いと答え。根拠にはせず、力の状態も上げない |
| 力 | 能力辞書（`src/shared/abilities.json`）の、話から確かめる力ごとの状態（[4-rules.md](4-rules.md)）。生活の中での状態と、仕事での発揮の状態を別々に持つ。状態が変わった履歴（いつ、前と後、理由）と、本人が外したかどうかも持つ。根拠ありになった話ごとに根拠を残し、話の数はそこから数える（Claude の判断） |
| 5 つの記録 | 下の表。好みとやりたいことは、項目ごとに、本人が選んだか書いたかを持つ。AI が推し量った項目は P1 で足す（Claude の判断） |
| 仕事の選択肢 | カードの種類と中身。本人の扱い（選んだ、保留した、自分で書いた）。「創る」には、需要を確かめたかを持つ |
| 最初の一歩 | 選んだ案の一歩の候補と、本人が選んだか書いた一歩（1 つ以上）。その後を聞いたかどうかも持つ。やったかどうかは持たない（Claude の判断） |
| 職種と業務 | アプリに登録する参照のデータ。下の「職種と業務のデータ」に書いた項目と、出典を持つ |
| まだ確かめていないこと | 選んだ案に照らして、まだ確かめていない力や業務 |
| 可能性レポート | 版ごとに残す |
| 了解の記録 | いつ、何に了解したか |
| 使った記録 | その日の送信回数と、最後に使った日 |
| 数 | 可能性レポートまで進んだ人の数と、案を選んだ人の数。人と結びつかない形で持ち、本人が全部消しても残る |

## 5 つの記録

| 記録 | 意味 | 入り方 |
|---|---|---|
| できること | 「根拠あり」の力と、その根拠、話の数。「要確認」の力は「確かめ中」として分けて示す | 確かめる（03 validate）から入る。根拠のないものは入れない |
| 好み | 合うやり方や環境 | 選択肢つきの問いで一つ聞く。会話から推し量ったものを足すのは P1 |
| やりたいこと | やってみたいこと、これから目指したいこと | 選択肢つきの問いで一つ聞く。会話から推し量ったものを足すのは P1 |
| 条件 | 使える時間帯、週あたりの時間、在宅か外出できるか、収入の目安 | 本人が入れる |
| 主体性 | 自分で選び、動き出すときに大事にしたいこと。欄の文言もこれにする | 本人が書く。AI は推し量らない |

## 力の状態の移り方

- 未確認から要確認へ: 核となる行動の一部が確かめられた。または、一般論だけを話した
- 要確認から根拠ありへ: 核となる行動がすべて、一つの出来事の中で確かめられた
- 未確認から根拠ありへ一度に上がることもある: 一つの出来事の中で、すべて一度に確かめられた
- 下がることもある: 本人の訂正や AI の読み違いで、根拠が外れた
- 根拠ありのまま別の話でもすべてそろったときは、状態は変わらず、話の数が増える。本人の訂正や話を飛ばしたことで根拠が外れると、話の数も減る
- 本人が見立てを外した力は、状態を残したまま、カードの理由と可能性レポートに使わない
- どの移り方も、履歴に残す
- 仕事での発揮の状態は、ハッカソンの期間中は動かさず、いつも「まだ確かめていない」と示す。何をもって動かすかは、ハッカソンのあとに決める。仮の場面の問いの答えだけでは上げない

## 職種と業務のデータ

- 「選ぶ」と「組み合わせる」は、アプリに登録した職種と業務だけを使う
- データは業務マスター（領域、職種、業務）として持つ。当事者の協力者のインタビューをもとに Claude が書き起こし、開発者が確かめる
- 参考にするのは、厚生労働省の職業情報提供サイト（job tag）のダウンロードデータ。中身は、労働政策研究・研修機構が作った「職業情報データベース」
  - 利用規約の第 9 条で、編集・加工して使うことが認められている
  - 規約の記載例どおりに、出典と、加工して作ったことを、データと一緒に書く
  - サイト上の文章はそのまま写さない
- 業務ごとに、カードに使う（`active`）か準備中（`preparing`）かを持つ。カードに使うのは、下の項目と job tag の職業とタスクの番号がそろった業務だけ
- 業務ごとに、次の項目を持つ。Claude が下書きし、開発者が確かめて直す。アプリの AI はこれらを推し量らない（Claude の判断）

| 項目 | 使い道 |
|---|---|
| 週あたりの時間、時間帯、在宅か外出か | 本人の条件の範囲で絞り込む |
| 収入の幅 | 本人の目安と比べて示す。絞り込みには使わない |
| 使う力（能力辞書の力。主な力と補助の力） | 選んだ案を深めるとき、確かめた力と照らす |
| 要る知識や道具（簿記、表計算など） | 能力辞書の力とは別に、まだ確かめていないこととして示す |
| 力が生きる場面 | カード、深める、レポートで、力が業務のどこで生きるかを添える |
| 小さな試し方 | 深めるの最初の一歩の候補の手がかり |
| 本人に確かめる条件 | 深めるとレポートで、まだ確かめていないこととして示す。力の確かめにもカードの絞り込みにも使わない |

## 保存と削除

- 保存するのは、ログインした人を見分ける ID と、上の表の情報だけ。メールアドレスや名前は保存しない
- ログインした人を見分ける ID は、そのまま保存せず、元に戻せない形に変えて保存する（Claude の判断）
- 保存期間は、最後に使った日から 30 日。本人はいつでも全部消せる
- 書きかけの答えと選んだ色は、その端末のブラウザにだけ残し、サーバーへは送らない。書きかけは、送る、区切る、飛ばす、全部消す、ログアウトのときと、最後に書いてから 30 日で消える。家族と共用する端末ではほかの人の目に入りうるので、「はじめに」で先に伝える（Claude の判断）
- 別の日に話す仕組みのために、メールアドレスや通知の宛先は保存しない。話の数と、別の日の入口（[4-rules.md](4-rules.md)）は、いま持っている情報から決める（Claude の判断）
- カレンダーに入れる操作では、選んだ日も、入れたかどうかも保存しない。予定に渡すのは決まった言葉とアプリの URL だけで、話した内容は渡さない。保存するものが増えないので、了解の中身は変えない（Claude の判断）
- 話した内容と AI の返答はログに書かない。開発者も、試用を含めて、話した内容と AI の返答を読まない
- ほかの人に見せる共有の機能は、作るとしても初めは切っておく
- 試用の感想を使うときは、A さん・B さんのように記号にし、個人が分かる部分を除く

## 公開の範囲

- Google アカウントがあれば、だれでも入れる。審査員が入れるよう、Google 側のログイン設定（OAuth の同意画面）は「本番」として公開する
- 1 日の送信回数に上限を付ける。1 人 1 日 100 回、アプリ全体で 1 日 1,000 回。Claude API のクレジット（配布された利用枠）を使い切られないため
- 合言葉や許可リストは付けない。審査員がそのまま入れるようにし、送信回数の上限で守る
