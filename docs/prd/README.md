# PRD — RE:VALUE（リバリュー）

> **確定（2026-11-02）、改訂（2026-11-05）**。改訂の理由は [docs/decisions/](../decisions/) に残した。Claude が仮に決めたところには「（Claude の判断）」と書いた。まだ決めていないことは、最後の「決めていないこと」にまとめた。

## 何を作るか

育児などでキャリアを中断した人のための Web アプリ。AI が聞き手になり、人生の経験を具体的な出来事として引き出す。本人の言葉を根拠に、3 つの力（見立てる力、調整する力、優先順位をつける力）を確かめ、仕事の選択肢を広げる。どの仕事に進むかは本人が選び、最初の一歩を決める。AI は仕事を決めない。

> キャリアには空白があっても、人生に空白はない。

ハッカソンのテーマ 2「本来、誰にでも届くべきものを。」に応える。

## 製品の芯（ぶらさない）

1. **根拠のない力は出さない**: 力ごとに、核となる行動を 3 つ決めている（[4-rules.md](4-rules.md)）。その 3 つが一つの具体的な出来事の中ですべて確かめられたときだけ「根拠あり」とし、本人の言葉を添える
2. **突き放さない**: 「根拠なし」「不得意」とは言わない。足りないときは、足りない行動だけを聞き返す
3. **AI が聞き手になる**: 利用者は質問を考えなくてよい。最近の具体的な一日を尋ね、毎回受け止めてから一つだけ聞く
4. **条件の中で選択肢を広げる**: 使える時間と場所の範囲で、収入の目安と比べながら、3 つの道を示す。「選ぶ」は登録した実在の職種、「組み合わせる」は登録した業務の組み合わせ、「創る」は事業のアイデア
5. **本人が選ぶ**: AI の見立てを、採用の判断や適職の断定の代わりにしない。本人が直す、保留する、却下する、自分の案を書く

## 作るときの判断

- 機能の数より、一人の体験を最後まで通すことを優先する。最後とは、確かめた力、選んだ案、最初の一歩をまとめた可能性レポート
- 削るときは、職種の数や見た目の飾りから削る。受け止める言葉、本人が決めること、根拠を示すことは削らない
- 力を確かめることは目的ではない。本人が信じられる発見のための手段
- 一つの話で言えるのは「その日そう動いた」まで。力があると言い切らず、話を重ねて確かめていく。初回の基準は上げず、1 回で可能性レポートまで着ける流れは崩さない

## 決めていないこと

開発者が決める。決まったら該当のファイルに書き、ここから消す。

1. 遅れたときに、どのまとまりを削るか（[3-features.md](3-features.md)）
2. [1-value.md](1-value.md) の調査の数字を、原典の表で確かめる。報道では確かめたが、原典のサイトが自動の取得を断るため、開発者がブラウザで見る
3. 当事者の協力者（開発に続けて協力してくれる当事者。[6-quality.md](6-quality.md)）に見てもらうこと（[3-features.md](3-features.md)）
   - deepen-6（仮の場面での考え方を聞く）の問いの中身と、考え方の傾向の残し方。決まるまでは Claude が Spec で仮に決める
   - P1 の「本人の職種入力」を、「本人がこれまでの職種を入れて、話を聞く手がかりにする」と読んでよいか
   - 08 revisit（別の日に話す）の次の 3 つ。返事を待たずに仮の形で作り、返事を見て直す
     - 「1 つの話から見えた」という言い方に、がっかりするか、かえって信じやすいか。レポートの見出し「できること」をこのままにするか
     - 選んだ一歩のその後を聞かれるのは、楽しみか、宿題のように重いか
     - 「また話しませんか」と知らせることは、ありがたいか、負担か。カレンダーに「RE:VALUE」と出ることを、家族に見られても気にならないか
   - 最初の問い（気持ちが動いた日を聞く）の言葉と選択肢。重く感じないか。返事を待たずに仮の形で作り、協力者からのレポートを見て直す
4. 保存期間を 30 日のままにするか。また話すまでの間が 30 日を超えると、記録が消える。カレンダーの候補の日は 30 日より手前にするが、本人がカレンダーの画面で先の日に変えることはできる（[5-information.md](5-information.md)）
